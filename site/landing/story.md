**定位。** fold.vibecoding.icu 的入口（第三轮先发到 fold-v2.vibecoding.icu）：第一次来的人，在手机上两三分钟、电脑前五分钟，先认出**问题是什么**，再看到 Fold 的切入点，然后进原型。画面上的每个点、每块面积、每个数，都是演示回放里真实的一条输入、一件事：composite 数据集（Jonas 的两周，化名改写的真实公开数据），停在第 26 轮（f26，8/16 周日 00:00，“车道下的铜管裂了”）。

## 论点

Agent 能看到的没有上限；人每一刻能处理的有限，而且这个上限随处境变化。Fold 要做的，是在每个处境的带宽里，把**同一刻**的信息重新编码，只给出你能处理、也最值得处理的那部分。

用户的核心句是“人在不同场景下接收的带宽或者处理的窗口是不同的。而 Agent 需要在不同的场景下，足够高效、准确地，在你的处理带宽内，给你提供最有价值的信息。”每个词在页面上的着落：

| 词 | 落在哪里 |
| --- | --- |
| 不同场景 | 首屏的三个处境：骑车、桌前、复盘；第 3 节的六个原型按处境排 |
| 带宽或窗口不同 | 首屏那扇窗本身：表盘大的圆 → 1.7 : 1 的桌面 → 整宽的复盘；第 3 节每个小图的大小随带宽变宽 |
| 足够高效 | 每个处境标着能看多久：抬腕两秒、坐下几分钟、停下来半小时；窗里给出的内容要在这个时间里读完 |
| 准确 | 窗里的每一样都追得回原话：场里亮着的点就是这扇窗用到的那些输入（骑车 28 条，桌前 428 条，复盘 1156 条；页面上不写这几个数，亮着的点自己说明） |
| 在你的处理带宽内 | 窗有多大，给出多少：1 件、14 件、两周的走向；窗外的不挤进来 |
| 最有价值 | 骑车时只剩的那一件是明天上午前要定、档位关键的那根裂了的水管；没用到的不删掉，只是变暗 |

**为什么不用 64 当英雄。** 用户的批评：“涌进来的再多，你也只有 64 份”是无力的叙述，而且把细节暴露在标题上。64 是可以配置的值，把注意力切成固定份数只是一种编码战术，和顶层设计关系不大。所以首屏不出现 64，也不用任何一个巨大的数字当英雄；64 只在第 4 节作为“一种编码的例子”出现。

**是编码，不是裁剪。** 同一刻的信息放到表盘上、桌前、复盘时，不是同一张图放大缩小：筛选不同（亮的点不同、而且散在两周各处，不是窗框住的一块），顺序不同（表盘只排最急的一件，桌面按面积排，复盘按时间排），形式不同（一个数和一行字 → 一张面积图 → 26 根按轮排的柱）。

## 首屏：一扇窗（已实现）

### 画面与文案

手机上自上而下：一行小字、标题、一句话，然后是“场”与“窗”。桌面上标题与说明在左三列，场与窗在右五列。

- 小字：`Fold · 按处境给 Agent 的汇报编码`
- 标题（两行，Fold Serif SC）：**同一刻的信息，按你此刻的带宽编码。**
- 手机一句话：Agent 看到的没有上限；你能处理的有限，而且随处境变化。
- iPad 与桌面的说明段：Agent 能替你看着所有的软件、消息和家里的琐事，它看到的没有上限；你每一刻能处理的却有限，而且随处境变化：骑车时只能看一眼手表，坐到桌前能多看一些，停下来复盘时才能看全部。Fold 让 Agent 按你在每种处境下能处理的量，又快又准地挑出最值得你看的那部分。
- **场**（这一刻客观的全部）：上方一行“Agent 这两周读过 3051 条”与“一个点是一条”；f01 到 f26 每轮一列、每条输入一个点，按到达先后从下往上排，一列 12 小时；轴上“两周前”到“此刻”（桌面中间加“一列是半天”）。3051 是首屏唯一留下的大数：它是“看见的没有上限”的证据。
- **窗**（随处境变形）：下面一块固定高的区域，窗在正中，三种形状：
  1. **骑车 · 抬腕两秒**：表盘大的圆。窗里“1 件要紧 · 水管裂了 / 挖开换还是不挖？ · 明天上午前要定”（腕上一瞥与智能眼镜在 f26 显示的就是这一件，原文“主水管：挖开换还是免挖？”，白话见下文「白话对照」）。场里只有用到这一件的 28 个点亮着（朱红），其余 3023 个变暗。
  2. **桌前 · 坐下几分钟**：1.7 : 1 的长方形。窗里是 f26 根层的 14 件按份额排的面积图（原版树图在这一刻的读法），等你的 5 件朱红（要紧那件实朱红），留白 1 份是虚线框。场里亮回 428 个点：归到这 14 件的输入，等你的那 124 个是朱红。
  3. **复盘 · 停下来半小时**：整宽。窗里是 26 轮各自的份额，按轮排成柱，**每一根正好站在场里它那一轮的那一列下面**；最后一根（此刻）里等你的几件是朱红。场里亮着 1156 个点：两周里归到过任何一件的输入；没归到任何一件的 1895 个（噪音、重复、暂缓）暗着。
- 三个处境按钮（骑车 / 桌前 / 复盘，下面写能看多久：抬腕两秒 / 坐下几分钟 / 停下来半小时）和一行账，每种处境最多一个数：“手表上只显示最要紧的一件事。亮着的点是它用到的几条消息，其余的变暗。”“眼下的事按轻重排开，其中 5 件等你回复；没用到的点变暗。”“复盘时看这两周的变化，一根柱子是一次整理；没用到的点变暗。”
- 桌面上两颗按钮：“为什么是新问题 ↓”“直接看原型”；手机底部一行“为什么是新问题 ↓”。

### 怎样避免“土”

- 没有英雄数字：最大的字是标题；“1”只在表盘那扇窗里，按手表的比例。
- 不写口号：标题是切入点本身（编码、带宽、同一刻），问题由画面给出：场是 3051 个真实的点，窗很小。
- 动作只做信息上的事：铺进来（这两周确实有这么多）、原地变暗（不用的不是删掉）、窗改形（带宽变了）、内容换形（是编码不是缩放）。没有飞点、拖尾、粒子，也没有循环。
- 平面：窗是一道 1.5px 墨线加纸面，没有阴影、高光和仿真机身。

## 方向取舍

第三轮先做了三个方向的静帧与分镜（会话 scratchpad 的 `landing/hero-v2/`，不入库），选了 A：

- **A 一扇窗（抽象地讲解法）**：上面所写，已实现。选它是因为它一张图里同时有“客观固定的这一刻”“随处境改形的带宽”“窗里重新编码、窗外原地变暗”，而且三者都是真数据；手机上竖排自然成立。
- **B 信道（精炼地讲切入点）**：信源 → 编码 → 信道 → 你，信道的宽度就是带宽。最贴近用户“为带宽做编码”的说法，但更像示意图，手机上信道一段是空白，第一眼的信息量不如 A。它的说法“给你看什么、按什么顺序、用什么形式”借进了第 3 节的导语。
- **C 问题先行（一个软件 vs 所有软件）**：先让人认出问题，再收进一块表盘大的窗。作为首屏偏重问题、切入点要等第二拍；整体借进第 2 节。

## 整页结构

三端同一个顺序：首屏 → 为什么是新问题 → 带宽随处境变 → 一种编码的例子（三拍与回流）→ 六种处境 → 其余 N 种（画廊）→ 文档 → 页脚。入口页固定纸白浅色、藏外观开关，与第二版相同。导航：处境（#bandwidth）· 全部原型 ▾ · 从头读起（/docs/why）· 文档 ▾。2026-11-03 去掉了“为什么（#why）”：小册子改写成“为什么要做 Fold”（/docs/why）后导航里有了“从头读起”，两项会重复；首屏的“为什么是新问题 ↓”按钮与 #why 锚点仍在。

### 第 2 节 · 为什么是新问题（#why）

这一节要让人认出问题：单个软件的通知是局部的、有上限的，平铺开人也看得完；Agent 替你管所有的软件、所有的股票、家里所有的琐事，看见的一定超出人能处理的。第三轮的版本用演示数据（23 个来源，GitHub 1019 条最多），动画只是各行长出、总和那行长出去。用户的反馈（2026-11-03）：“右边那个图你想表达的是对的，但是你的动画做的不到位，应该是从左往右播放，然后把这些全加在一起，表达 Agent 如果帮你管全部，就会是爆炸式的，agent 顶到底的时候，其他的都往前缩到一点点……然后 message 的数量明显是要更多的呀。。因为 message 有那种大群。。比如你加了 discord，github 不一定是最多的。”所以数据换成一般人的一天，动画换成三幕。

第一版三幕（19 行，总和 1850，最大一项 500）看过逐帧条后，同日又改了两处（协调方拍板）：一是第 3 幕没有“缩成一点点”，总和只有最大一项的 3.7 倍，Discord 那行还剩整宽的 27%。问题不在量级，在口径：人加的群不是三个，是几十个，每个群都是单独的来源，Agent 每个都要读，所以一个群一行。二是第 2 幕乱：几十段同时从各行斜着飞向总和那一行，路线交叉；改成先竖直落、再水平滑，按批落，任何时刻在路上的不超过两批。

- 标题：**一个软件的通知有尽头，Agent 看见的没有。**（不变）
- 导语：一个软件只管自己的通知：幼儿园 App 一天发几条，翻一翻就看完了。可要是让 Agent 替你看着所有的群、邮件、工作、股票和家里的琐事，它要读的是这些加在一起。一个人往往加了几十个群，每个群一天几十到上百条，光是群消息一天就上千条。首屏那片点是演示里的两周，平均一天两百来条，只是一个很小的样本。Agent 看到的一定比你能处理的多，所以它得替你取舍：留下的，应该是你此刻能处理、也最值得处理的那部分。（“两百来条”是 `why.demoPerDay` 235；“上千条”是 32 个群加起来 1965。导语不写阿拉伯数字。）
- 图：一个人一天的量级（示意，不是演示数据），46 个来源各一行（`why.day`）：先是 32 个群，再是 14 个其他来源，各自从多到少。只给 5 行写名字：最大的三个群（Discord 社区、业主群、小区团购群）、其他来源里最多的工作邮件、最后一行的幼儿园 App（加粗，标“← 一个软件”）。其余的行是细行，每一段连续的细行共用一个括号标注：“还有 29 个群 / 公司、家长 / 同学、家族……”“还有 12 个来源 / 新闻、股票 / 私聊、快递……”（`landing.mjs` 的 `WHY_BLOCKS`）。不写每行的条数，长短自己说话。右上一行比例：“满格：一天 150 条”，第 3 幕换成“满格：一天 2565 条”。最后一行“全部加起来”。图下一行“一个软件一天几条；替你看着全部的 Agent，一天要读的是它的几百倍。”（2565 ÷ 5 = 513，写成“几百倍”，不写一个看起来像实测的倍数），再下一行小字“示意：一个人一天大致的条数，不是演示数据。工作邮件按微软的统计取整，四个工作群加起来与同一份统计里的工作消息相当，其余是保守的估计。”，链到本节的出处表。
- 尺寸：写名字的行 13px（iPad 起 16px），细行 5px（6px）；条高 5px / 3px（6px / 4px）；群与其他来源之间空 8px（10px）。手机上整张图约 290px 高，和第一版 19 行时差不多，不是一面墙。

#### 三幕（只演一次，进视口触发，约 5.3 秒）

时刻的唯一出处是 `landing.mjs` 的 `WHY`，`whyModel()` 把它写成图上的 CSS 变量，并核对第 1 幕长完才开始第 2 幕、第 2 幕落完才开始第 3 幕；只动 transform 与 opacity，没有逐元素的脚本帧循环。

| 时刻（从进视口算） | 幕 | 动什么 | 读出来的 |
| --- | --- | --- | --- |
| 0–1.17 秒 | 1 各自 | 比例按最大的单个来源定（最大的三个群各 150 条，占满一行）。46 行从上到下依次从左往右长出（每行错开 18ms，各 360ms） | 每个单独看都“还行”；群一行接一行，多得数不过来 |
| 1.4–3.36 秒 | 2 加在一起 | 每一行复制一段，按批从下往上落进最后一行：写名字的一行单独一批，一个括号下的细行一起一批，共 7 批，每批错开 240ms，各 520ms。每段先竖直落到总和那一行的高度（前 40%，加速），再水平滑进自己的位置（后 60%，减速），首尾相接，深浅两种墨交替，段间 1px 纸色缝；同一批一起落，像一摞纸压下来、再向右铺开。任何时刻在路上的不超过两批；落走的那一行原地淡到三成 | 幼儿园 App 和 12 个小来源先在左边拼满一行；后面工作邮件、29 个群、三个大群一批批落下来，滑出屏幕右边：全加起来是 17 个满格 |

### 第 3 节 · 带宽随处境变（#bandwidth）

- 标题：**处境定了带宽，带宽定了编码。**
- 小字：带宽随处境变化 · 同一时刻
- 导语：能看多久、屏幕多大、能不能当场回复，决定了 Agent 给你看什么、按什么顺序、用什么形式。下面六个原型用的是同一时刻的数据，按带宽从窄到宽排列；它们都是呈现方式上的尝试，点开一个可以看它的演示。
- 六行（手机）/ 六列（桌面），从窄到宽，每个小图的宽度随带宽变大（`landing.mjs` 的 `LADDER`）。2026-11-03 用户说 Top 6 里“手机首页”和“回应托盘”太像，手机首页换成 A 空间排布（电脑上的注意力方块），它的处境是“坐在电脑前”，排在折叠屏之后、两周小倍数之前。六个 id 与名字在 `LADDER` 里自己列，不读第 5 节六张卡的组成与顺序；一行有对应的卡就滚到那张卡，没有（现在的 A）就直接打开原型（桌面在弹框里，手机上是原型本身）。每行最多一个数：

| 原型 | 处境 | 带宽 | 给出的（f26 的真实值，最多一个数） | data.json |
| --- | --- | --- | --- | --- |
| 腕上一瞥 | 抬腕两秒 | 只看得清一个数字 | 1 件要紧 | `beat3.urgent.length` |
| 回应托盘 | 通勤几分钟 | 只能单手操作 | 6 次点按，答完所有问题 | `beat3.taps` |

| 两周小倍数 | 周末复盘 | 不回复，只看变化趋势 | 每轮整理一张小图，看两周的变化（不写数） | — |

A 的小图：一块电脑屏幕，左边一列两张待答的卡（要紧那张朱红、带两个按钮），右边是这一轮 14 件按份额铺成的纸片（`squarify`），等你的朱红。

- 动：进视口时一行一行出现（错开 150ms），每个小图就地画出来一次（刻度顺时针亮起、托盘升起、带子从此刻线拉出、纸片依次铺上），约 1.2 秒画完。小图沿用第二版桥上的画法（`glyphs()`），顺序改成按带宽。

### 第 4 节 · 一种编码的例子：把注意力切成固定的份数（#example）

- 标题：**把注意力切成固定的份数**
- 导语：原型里试的一种编码：把每一层的注意力切成固定的份数，演示里是 64 份（份数可以配置）。Agent 每一轮把这些份数分给各件事，份数就是面积。有了面积，同样的轻重就能在手表、手机和桌面上分别画出来。下面是演示里的一轮：你离开的 12 小时。
- 其下是第二版的“一轮整理”：钉住的舞台加四段文字，拍 1 收到（158 条，一条消息一道竖线，按到达时间排在五个渠道上）、拍 2 折叠（118 条折叠，40 颗点归到各自那件事，尺上的份数随之重分，水管那件翻了一倍）、拍 3 提问（1 件要紧，卡从水管那一段下面展开，能点）、你回复之后（演示卡收成回执，接真实的那一通电话）。2026-11-03 起拍名用平常话：涌入 → 收到、折 → 折叠、开口 → 提问、回流 → 你回复之后。几何、时刻与约束不变，见 [spec.md](spec.md)「F」与 [style.md](style.md)「动效语言」。64 在全页只在这一节出现。
- 2026-11-03 起这一节只留讲清每一拍必需的数：158 条进来、118 条折叠、1 件要紧（“0 件要紧”是“你回复之后”那一拍）、64 份。车道名后的条数、尺下“涨 / 让”的份数（原来一格一格数到新值）、两周与每轮的条数、折掉的三种去向的条数、“5 件等你 · 38 份”“新问题 2 个”“本轮 16 条输入落进这一件”“两周回应 N 次”这些都不再写；尺下只写份数增加与减少的几件的白话名字（标签“增 / 减”，原来是“涨 / 让”）。卡上的标签写“要紧 · 明天上午前要定”，不写“周一 10:00 前 · 还有 34 小时 · 24 份”。
- 例子都是白话（下文「白话对照」）：拍 2 写“水管裂了这件事占的份数翻了一倍，份数变少的是猫看病、儿子病假和空余部分”；演示卡问“车道下的水管裂了：挖开整根换（约 6.8 万），还是不挖开、从旧管里穿一根新管（约 4.1 万）？”，两个按钮“挖开换 · 6.8 万”“不挖开 · 4.1 万”，回执“演示替你选了「不挖开 · 4.1 万」”；真实的一次写“Agent 问：「猫多吃了药，要打给兽医吗？」主人没有点按钮，而是直接打了电话。下一轮 Agent 读到通话记录「打给宠物诊所，6 分钟」，猫这件事占的份数就减少了一半。”标题“8/14 早上 08:02，一通电话。”改成“一通电话，下一轮就读到了。”（改标题后重跑 `landing-fonts.mjs` 更新字体子集）。
