**定位。** fold.vibecoding.icu 的入口（第三轮先发到 fold-v2.vibecoding.icu）：第一次来的人，在手机上两三分钟、电脑前五分钟，先认出**问题是什么**，再看到 Fold 的切入点，然后进原型。画面上的每个点、每块面积、每个数，都是演示回放里真实的一条输入、一件事：composite 数据集（Jonas 的两周，化名改写的真实公开数据），停在第 26 轮（f26，8/16 周日 00:00，“车道下的铜管裂了”）。

## 论点

Agent 能看见的没有上限；人每一刻能接住的有上限，而且这个上限随处境变。Fold 要做的，是在每个处境的带宽里，把**同一刻**的信息重新编码，只交出你接得住、也最值得接的那部分。

用户的核心句是“人在不同场景下接收的带宽或者处理的窗口是不同的。而 Agent 需要在不同的场景下，足够高效、准确地，在你的处理带宽内，给你提供最有价值的信息。”每个词在页面上的着落：

| 词 | 落在哪里 |
| --- | --- |
| 不同场景 | 首屏的三个处境：骑车、桌前、复盘；第 3 节的六个原型按处境排 |
| 带宽或窗口不同 | 首屏那扇窗本身：表盘大的圆 → 1.7 : 1 的桌面 → 整宽的复盘；第 3 节每个小图的大小随带宽变宽 |
| 足够高效 | 每个处境标着能看多久：抬腕两秒、坐下几分钟、停下来半小时；窗里交出的东西要在这个时间里读完 |
| 准确 | 窗里的每一样都追得回原话：场里亮着的点就是这扇窗用到的那些输入（骑车 28 条，桌前 428 条，复盘 1156 条；页面上不写这几个数，亮着的点自己说明） |
| 在你的处理带宽内 | 窗有多大，交出多少：1 件、14 件、两周的走向；窗外的不挤进来 |
| 最有价值 | 骑车时只剩的那一件是明天上午前要定、档位关键的那根裂了的水管；没用到的不是删掉，是原地暗下 |

**为什么不用 64 当英雄。** 用户的批评：“涌进来的再多，你也只有 64 份”是无力的叙述，而且把细节暴露在标题上。64 是可以配置的值，把注意力切成固定份数只是一种编码战术，和顶层设计关系不大。所以首屏不出现 64，也不用任何一个巨大的数字当英雄；64 只在第 4 节作为“一种编码的例子”出现。

**是编码，不是裁剪。** 同一刻的信息放到表盘上、桌前、复盘时，不是同一张图放大缩小：筛选不同（亮的点不同、而且散在两周各处，不是窗框住的一块），顺序不同（表盘只排最急的一件，桌面按面积排，复盘按时间排），形式不同（一个数和一行字 → 一张面积图 → 26 根按轮排的柱）。

## 首屏：一扇窗（已实现）

### 画面与文案

手机上自上而下：一行小字、标题、一句话，然后是“场”与“窗”。桌面上标题与说明在左三列，场与窗在右五列。

- 小字：`Fold · 按处境给 Agent 的汇报编码`
- 标题（两行，Fold Serif SC）：**同一刻的信息，按你此刻的带宽编码。**
- 手机一句话：Agent 看见的没有上限；你接得住的有，而且随处境在变。
- iPad 与桌面的说明段：Agent 能替你看着所有的软件、消息和家里的琐事，看见的没有上限；你每一刻接得住的有上限，而且随处境在变：骑车时只剩一块表盘，坐到桌前多一些，停下来复盘才全部展开。Fold 让 Agent 在每一种处境的带宽里，又快又准地，只交出你接得住、也最值得接的那部分。
- **场**（这一刻客观的全部）：上方一行“Agent 这两周读过 3051 条”与“一个点是一条”；f01 到 f26 每轮一列、每条输入一个点，按到达先后从下往上排，一列 12 小时；轴上“两周前”到“此刻”（桌面中间加“一列是半天”）。3051 是首屏唯一留下的大数：它是“看见的没有上限”的证据。
- **窗**（随处境变形）：下面一块固定高的区域，窗在正中，三种形状：
  1. **骑车 · 抬腕两秒**：表盘大的圆。窗里“1 件要紧 · 水管裂了 / 挖开换还是不挖？ · 明天上午前要定”（腕上一瞥与智能眼镜在 f26 显示的就是这一件，原文“主水管：挖开换还是免挖？”，白话见下文「白话对照」）。场里只有落进这一件的 28 个点亮着（朱红），其余 3023 个原地暗下。
  2. **桌前 · 坐下几分钟**：1.7 : 1 的长方形。窗里是 f26 根层的 14 件按份额排的面积图（原版树图在这一刻的读法），等你的 5 件朱红（要紧那件实朱红），留白 1 份是虚线框。场里亮回 428 个点：落进这 14 件的输入，等你的那 124 个是朱红。
  3. **复盘 · 停下来半小时**：整宽。窗里是 26 轮各自的份额，按轮排成柱，**每一根正好站在场里它那一轮的那一列下面**；最后一根（此刻）里等你的几件是朱红。场里亮着 1156 个点：两周落进过任何一件的输入；没落进任何一件的 1895 个（噪音、重复、暂缓）暗着。
- 三个处境按钮（骑车 / 桌前 / 复盘，下面写能看多久：抬腕两秒 / 坐下几分钟 / 停下来半小时）和一行账，每种处境最多一个数：“只交出最要紧的一件。亮着的是它用到的那几条，其余的原地暗下。”“眼下的事按分量摊开，5 件等你回话；没用上的原地暗下。”“交出这两周的走向，一根柱是一次整理；没用上的原地暗下。”
- 桌面上两颗按钮：“为什么是新问题 ↓”“直接看原型”；手机底部一行“为什么是新问题 ↓”。

### 动画分镜（只演一次，约 8 秒，停在“复盘”）

纯 CSS，首绘即开始，不等脚本；时刻的唯一出处是 `landing.mjs` 的 `MOMENT`，`momentCSS()` 由它生成关键帧。点处境按钮时摘掉这段动画（`.manual`），改用过渡在三种状态间切换。`prefers-reduced-motion` 直接给“复盘”的终态。

| 时刻 | 动什么 | 落定 |
| --- | --- | --- |
| 0 | 标题、说明、空的场（只有轴）、三颗灰着的处境按钮 | — |
| 0.1–1.0 秒 | 一根播放线从左往右扫过，两周一列列铺进来，每个点都是墨色 | 3051 条 |
| 1.2–1.65 秒 | 骑车：窗从中心张开成表盘大的圆；场里所有点同时原地暗到 14%，落进主水管的 28 个点留成朱红 | 1 件 |
| 1.44–1.72 秒 | 窗里“1 件要紧 · 水管裂了…… · 明天上午前要定”淡入，账换成第一行 | 28 条 |

| 4.49–4.77 秒 | 窗有了形状之后，14 块面积淡入，账换成第二行 | 14 件、5 件等你 |

演完之后场上没有残留的盖板、前两扇窗的内容与账都收起，只亮“复盘”一颗按钮（`check-landing` 逐项核对）。逐帧条与分镜是真实录屏取帧，见 spec.md「验收」。

### 怎样避免“土”

- 没有英雄数字：最大的字是标题；“1”只在表盘那扇窗里，按手表的比例。
- 不写口号：标题是切入点本身（编码、带宽、同一刻），问题由画面给出：场是 3051 个真实的点，窗很小。
- 动作只做信息上的事：铺进来（这两周确实有这么多）、原地暗下（舍弃不是删除）、窗改形（带宽变了）、内容换形（是编码不是缩放）。没有飞点、拖尾、粒子，也没有循环。
- 平面：窗是一道 1.5px 墨线加纸面，没有阴影、高光和仿真机身。

## 方向取舍

第三轮先做了三个方向的静帧与分镜（会话 scratchpad 的 `landing/hero-v2/`，不入库），选了 A：

- **A 一扇窗（抽象地讲解法）**：上面所写，已实现。选它是因为它一张图里同时有“客观固定的这一刻”“随处境改形的带宽”“窗里重新编码、窗外原地暗下”，而且三者都是真数据；手机上竖排自然成立。
- **B 信道（精炼地讲切入点）**：信源 → 编码 → 信道 → 你，信道的宽度就是带宽。最贴近用户“为带宽做编码”的说法，但更像示意图，手机上信道一段是空白，第一眼的信息量不如 A。它的说法“交出哪些、按什么顺序、用什么形式”借进了第 3 节的导语。
- **C 问题先行（一个软件 vs 所有软件）**：先让人认出问题，再收进一块表盘大的窗。作为首屏偏重问题、切入点要等第二拍；整体借进第 2 节。

## 整页结构

三端同一个顺序：首屏 → 为什么是新问题 → 带宽随处境变 → 一种编码的例子（三拍与回流）→ 六种处境 → 其余 N 种（画廊）→ 文档 → 页脚。入口页固定纸白浅色、藏外观开关，与第二版相同。导航：为什么（#why）· 处境（#bandwidth）· 全部原型 ▾ · 小册子 · 文档 ▾。

### 第 2 节 · 为什么是新问题（#why）

这一节要让人认出问题：单个软件的通知是局部的、有上限的，平铺开人也看得完；Agent 替你管所有的软件、所有的股票、家里所有的琐事，看见的一定超出人能处理的。第三轮的版本用演示数据（23 个来源，GitHub 1019 条最多），动画只是各行长出、总和那行长出去。用户的反馈（2026-11-03）：“右边那个图你想表达的是对的，但是你的动画做的不到位，应该是从左往右播放，然后把这些全加在一起，表达 Agent 如果帮你管全部，就会是爆炸式的，agent 顶到底的时候，其他的都往前缩到一点点……然后 message 的数量明显是要更多的呀。。因为 message 有那种大群。。比如你加了 discord，github 不一定是最多的。”所以数据换成一般人的一天，动画换成三幕。

- 标题：**一个软件的通知有尽头，Agent 看见的没有。**（不变）
- 导语：一个软件只管自己那一摊：幼儿园 App 一天发几条，翻一翻就看完了。可要是让 Agent 替你看着所有的群、邮件、工作、股票和家里的琐事，它要读的是这些加在一起，光是几个几百人的大群，一天就上千条。首屏那片点是演示里的两周，平均一天两百来条，只是一个轻的样本。看见的必然超出你接得住的；总有一刻它得替你舍掉一些，而留下的，得是你此刻接得住、也最值得接的。（“两百来条”是 `why.demoPerDay` 235；“上千条”是四个群加起来 1100。导语不写阿拉伯数字。）
- 图：一个人一天的量级（示意，不是演示数据），19 个来源各一行（`why.day`），按条数从多到少；只写名字，不写每行的条数，长短自己说话。幼儿园 App 那一行加粗并标“← 一个软件”。右上一行比例：“满格：一天 500 条”，第 3 幕换成“满格：一天 1850 条”。最后一行“全部加起来”。图下一行“一个软件一天几条；替你看着全部的 Agent，一天要读的是它的几百倍。”（1850 ÷ 5 = 370，写成“几百倍”，不写一个看起来像实测的倍数），再下一行小字说明“一个人一天的量级，示意，不是演示数据”，链到本节的出处表。

#### 三幕（只演一次，进视口触发，约 5.4 秒）

时刻的唯一出处是 `landing.mjs` 的 `WHY`，`whyModel()` 把它写成图上的 CSS 变量；只动 transform 与 opacity，没有逐元素的脚本帧循环。

| 时刻（从进视口算） | 幕 | 动什么 | 读出来的 |
| --- | --- | --- | --- |
| 0–1.23 秒 | 1 各自 | 比例按最大的单个来源定（Discord 社区 500 条占满一行）。各行从上到下依次从左往右长出（每行错开 45ms，各 420ms） | 每个单独看都“还行”，最长的是消息类的大群 |
| 1.55–3.1 秒 | 2 加在一起 | 每一行的条复制一段，从下往上依次落进最后一行，首尾相接拼成一根（每段错开 55ms，各 560ms，深浅两种墨交替，段间 1px 纸色缝）；落走的那一行原地淡到三成 | 小的几段先在左边拼起来，后面几个大群的段越过屏幕右边：全加起来是 3.7 个满格，跑出屏幕 |
| 3.5–4.9 秒 | 3 换比例 | 比例尺缩小（`--k` = 500 ÷ 1850），“全部加起来”那根正好缩到顶满整宽；上面每一行同时往左缩，同一条缓动，回到全墨色；比例那行字先出后进换成 1850 | 单个软件在 Agent 面前只是一点点：最大的大群只剩约 27%，幼儿园 App 只剩 1.5px 的一道 |
| 5.05–5.37 秒 | 收尾 | 图下那一行字淡入 | 几百倍 |

最小的几行缩下来不到 1px，所以每一行左端有一道不随比例缩的 1.5px（桌面 2px）短痕，终态里每个来源都看得见。越过右边的部分裁在图里：图向右伸到屏幕边（桌面算上居中留白），在那里裁掉，页面不横向滚动。`prefers-reduced-motion` 直接给第 3 幕终态。

### 第 3 节 · 带宽随处境变（#bandwidth）

- 标题：**处境定了带宽，带宽定了编码。**
- 导语：能看多久、屏幕多大、能不能当场作答，决定了交出什么、按什么顺序、用什么形式。下面六个原型读的是同一刻，按带宽从窄到宽排；它们都是表现层上的尝试，点一个看它自己讲一遍。
- 六行（手机）/ 六列（桌面），从窄到宽，每个小图的宽度随带宽变大（`landing.mjs` 的 `LADDER`）。2026-11-03 用户说 Top 6 里“手机首页”和“回应托盘”太像，手机首页换成 A 空间排布（电脑上的注意力方块），它的处境是“坐在电脑前”，排在折叠屏之后、两周小倍数之前。六个 id 与名字在 `LADDER` 里自己列，不读第 5 节六张卡的组成与顺序；一行有对应的卡就滚到那张卡，没有（现在的 A）就直接打开原型（桌面在弹框里，手机上是原型本身）。每行最多一个数：

| 原型 | 处境 | 带宽 | 交出（f26 的真实值，最多一个数） | data.json |
| --- | --- | --- | --- | --- |
| 腕上一瞥 | 抬腕两秒 | 只读得了一个数 | 1 件要紧 | `beat3.urgent.length` |
| 回应托盘 | 通勤几分钟 | 只有一只拇指 | 6 下答完全部问题 | `beat3.taps` |

A 的小图：一块电脑屏幕，左边一列两张待答的卡（要紧那张朱红、带两个按钮），右边是这一轮 14 件按份额铺成的纸片（`squarify`），等你的朱红。

### 第 4 节 · 一种编码的例子：把注意力切成固定的份数（#example）

## 约束

- **同源：** 首屏的场、三扇窗与它们的账，第 2 节的每一行，第 3 节的每个数，以及页面上的每一处白话，都读 data.json，`check-landing` 逐个核对（页面上 68 处、47 个出处）。第 2 节的数是“一个人一天”的示意量级，不是演示回放，出处见上文那一节的表。
- **少写数字：** 一个数如果读者要停下来想才懂、或者不影响论点，就不写（用户：“你不要到处写满数字。。这个 26 重要吗”）。首屏每种处境最多一个数，3051 留一个；第 3 节每行最多一个；第 4 节只留讲清这一拍必需的；第 2 节只写比例那一行的 500 与 1850。能用一句白话说的，不写一串数。删掉的数仍在 data.json。
- **白话：** 入口页正文（第 5 节六张原型卡、画廊、弹框里是原型自己的样子，不算）不出现 #编号、PR、CI、master、演示里的人名与瑞典语，也不直接搬演示原文的标题、问题与选项；`check-landing` 核对。
- **只演一次：** 首屏一遍、停在复盘；第 2、3 节进视口各画一次。唯一一直在动的是画廊和录像。
- **原地：** 被舍弃的点原地暗下，不飞、不删；窗从中心改形；柱在自己那一列下面升起。
- **朱红只给等你回应：** 场里落进等你那几件的点、要紧那件与等你那几件的面积、复盘柱里此刻等你的几段、账里“5 件等你”、第 3 节里“1 件要紧”、A 小图里待答的卡。
- **64 只在第 4 节：** 首屏、第 2 节、第 3 节的文字里都不写 64（腕上一瞥与两周小倍数的小图本来就画着它们的刻度与方阵，那是原型的样子）。
- **不劫持滚动；不拟物。**
