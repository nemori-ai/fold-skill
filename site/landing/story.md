**定位。** fold.vibecoding.icu 的入口（第三轮先发到 fold-v2.vibecoding.icu）：第一次来的人，在手机上两三分钟、电脑前五分钟，先认出**问题是什么**，再看到 Fold 的切入点，然后进原型。页面上的数据分两种，各管各的：

- **示意的一天**：首屏与第 2 节是同一天，一个加了几十个群的程序员，一天进来 2565 条（第 2 节的出处表）。首屏把这一天的每一条铺成一个点，三扇窗里的事（线上告警、发版审批、代码评审，混着猫的药、孩子请假、房租、快递）是为这一天写的示意，不是演示回放。数据由 `landing-data.mjs` 用固定的种子生成，每次一样，data.json 里每项带 `basis: "示意"`。
- **演示回放（真实数据）**：第 3 节每行的数与第 4 节“一种编码的例子”读的是 composite 数据集（Jonas 的两周，化名改写的真实公开数据），停在第 22 轮（f22，8/14 周五 00:00，“热浪第一天：药量超过失明线”）。这一刻开着的问题都是家常事：猫多吃了药要不要打给兽医、母亲九月住哪、儿子的病假报了没有、女儿的同意书签了没有，还有一份同事的修复等批准。从 f26 换来，是因为 f26 的要紧一问是“车道下的主水管挖开换还是免挖”，用户说太抽象；/docs/why 用的也是 f22。第 5 节六张卡与画廊是原型本身，讲它们自己的演示（卡上的录像与数由另一条线维护）。

## 论点

Agent 能看到的没有上限；人每一刻能处理的有限，而且这个上限随处境变化。Fold 要做的，是在每个处境的带宽里，把**同一刻**的信息重新编码，只给出你能处理、也最值得处理的那部分。

用户的核心句是“人在不同场景下接收的带宽或者处理的窗口是不同的。而 Agent 需要在不同的场景下，足够高效、准确地，在你的处理带宽内，给你提供最有价值的信息。”每个词在页面上的着落：

| 词 | 落在哪里 |
| --- | --- |
| 不同场景 | 首屏的三个处境：骑车、桌前、复盘；第 3 节的六个原型按处境排 |
| 带宽或窗口不同 | 首屏那扇窗本身：表盘大的圆 → 1.7 : 1 的桌面 → 整宽的复盘；第 3 节每个小图的大小随带宽变宽 |
| 足够高效 | 每个处境标着能看多久：抬腕两秒、坐下几分钟、停下来半小时；窗里给出的内容要在这个时间里读完 |
| 准确 | 窗里的每一件都追得到输入：场里亮着的点就是归到这扇窗里那几件的输入（骑车 34 条，桌前 143 条，复盘 175 条；页面上不写这几个数，亮着的点自己说明） |
| 在你的处理带宽内 | 窗有多大，给出多少：1 件、10 件、两周的走向；窗外的不挤进来 |
| 最有价值 | 骑车时只剩的那一件是线上报错突增、要不要回滚，半小时内要定；没用到的不删掉，只是变暗 |

**为什么不用 64 当英雄。** 用户的批评：“涌进来的再多，你也只有 64 份”是无力的叙述，而且把细节暴露在标题上。64 是可以配置的值，把注意力切成固定份数只是一种编码战术，和顶层设计关系不大。所以首屏不出现 64，也不用任何一个巨大的数字当英雄；64 只在第 4 节作为“一种编码的例子”出现。

**是编码，不是裁剪。** 同一刻的信息放到表盘上、桌前、复盘时，不是同一张图放大缩小：筛选不同（亮的点不同、而且散在两周各处，不是窗框住的一块），顺序不同（表盘只排最急的一件，桌面按面积排，复盘按时间排），形式不同（一个数和一行字 → 一张面积图 → 两周一天一根的柱）。

## 首屏：一扇窗（已实现）

### 画面与文案

手机上自上而下：一行小字、标题、一句话，然后是“场”与“窗”。桌面上标题与说明在左三列，场与窗在右五列。

- 小字：`Fold · 按处境给 Agent 的汇报编码`
- 标题（两行，Fold Serif SC）：**同一刻的信息，按你此刻的带宽编码。**
- 手机一句话：Agent 看到的没有上限；你能处理的有限，而且随处境变化。
- iPad 与桌面的说明段：Agent 能替你看着所有的软件、消息和家里的琐事，它看到的没有上限；你每一刻能处理的却有限，而且随处境变化：骑车时只能看一眼手表，坐到桌前能多看一些，停下来复盘时才能看全部。Fold 让 Agent 按你在每种处境下能处理的量，又快又准地挑出最值得你看的那部分。
- **场**（这一天客观的全部，示意）：上方一行“Agent 这一天读过 2565 条”与“示意 · 一个点是一条”；此刻是傍晚 6 点，场是此前 24 小时，一小时一列、每条输入一个点，按到达先后从下往上排；轴上“24 小时前”“一列是一小时”“此刻”。2565 就是第 2 节那一天的总和，第 2 节正好解释这片点从哪来：几十个群、邮件、GitHub、股票、家里的各种通知，半夜少、午饭和晚上多。
- **窗**（随处境变形）：下面一块固定高的区域，窗在正中，三种形状：
  1. **骑车 · 抬腕两秒**：表盘大的圆。窗里只有 1 件：“1 件要紧 · 线上报错突增 / 要不要回滚？ · 半小时内要定”。场里只有归到这一件的 34 个点亮着（朱红），挤在最后三列（下午 3 点以后：告警邮件、项目群与部门群、告警短信），其余变暗。
  2. **桌前 · 坐下几分钟**：1.7 : 1 的长方形。窗里是这一天的 10 件按份额排的面积图（原版树图的读法），工作与家常混着；等你的 5 件朱红，线上告警是最大的一块、实朱红；留白 4 份是虚线框。场里亮着 143 个点：归到这 10 件的输入，等你的那 94 个是朱红。
  3. **复盘 · 停下来半小时**：整宽。窗里是这两周每天一根柱，当天收尾时注意力怎么分：深色是工作，浅色是家里的事；周末浅色多，发版前两天深色占大头，最后一根是今天（就是桌前那 10 件，等你的几件朱红，告警那一大块在最下面）。轴是“两周前”到“今天”。场里亮着 175 个点：今天归到过任何一件的输入（包括早些时候办完的站会改期（10 条）、小区停水（15 条）、午饭拼单（7 条））。
- 三个处境按钮（骑车 / 桌前 / 复盘，下面写能看多久：抬腕两秒 / 坐下几分钟 / 停下来半小时）和一行账，每种处境最多一个数：“手表上只显示最要紧的一件事。亮着的点是它用到的几条消息，其余的变暗。”“眼下的事按轻重排开，其中 5 件等你回复；没用到的点变暗。”“复盘时看两周的变化：一根柱子是一天，深色是工作，浅色是家里的事。”
- 桌面上两颗按钮：“为什么是新问题 ↓”“直接看原型”；手机底部一行“为什么是新问题 ↓”。

这一天的故事是连贯的：下午上线的新版本让接口报错突增，要不要回滚得你来定，这是表盘上唯一的一件；今晚的发版等你批准，但要等告警处理完；两份代码评审等你看；测试没过、猫的药、周末聚餐、房租、快递由 Agent 跟着。

### 怎样避免“土”

- 没有英雄数字：最大的字是标题；“1”只在表盘那扇窗里，按手表的比例。
- 不写口号：标题是切入点本身（编码、带宽、同一刻），问题由画面给出：场是一天的 2565 个点，窗很小。
- 动作只做信息上的事：铺进来（这一天确实有这么多）、原地变暗（不用的不是删掉）、窗改形（带宽变了）、内容换形（是编码不是缩放）。没有飞点、拖尾、粒子，也没有循环。
- 平面：窗是一道 1.5px 墨线加纸面，没有阴影、高光和仿真机身。

## 方向取舍

第三轮先做了三个方向的静帧与分镜（会话 scratchpad 的 `landing/hero-v2/`，不入库），选了 A：

- **A 一扇窗（抽象地讲解法）**：上面所写，已实现。选它是因为它一张图里同时有“客观固定的这一刻”“随处境改形的带宽”“窗里重新编码、窗外原地变暗”；手机上竖排自然成立。第三轮时三者都读演示回放（f26），2026-11-03 起换成示意的一天（见「定位」）。
- **B 信道（精炼地讲切入点）**：信源 → 编码 → 信道 → 你，信道的宽度就是带宽。最贴近用户“为带宽做编码”的说法，但更像示意图，手机上信道一段是空白，第一眼的信息量不如 A。它的说法“给你看什么、按什么顺序、用什么形式”借进了第 3 节的导语。
- **C 问题先行（一个软件 vs 所有软件）**：先让人认出问题，再收进一块表盘大的窗。作为首屏偏重问题、切入点要等第二拍；整体借进第 2 节。

## 整页结构

三端同一个顺序：首屏 → 为什么是新问题 → 带宽随处境变 → 一种编码的例子（三拍与回流）→ 六种处境 → 其余 N 种（画廊）→ 文档 → 页脚。入口页固定纸白浅色、藏外观开关，与第二版相同。导航：处境（#bandwidth）· 全部原型 ▾ · 从头读起（/docs/why）· 文档 ▾。2026-11-03 去掉了“为什么（#why）”：小册子改写成“为什么要做 Fold”（/docs/why）后导航里有了“从头读起”，两项会重复；首屏的“为什么是新问题 ↓”按钮与 #why 锚点仍在。

### 第 2 节 · 为什么是新问题（#why）

这一节要让人认出问题：单个软件的通知是局部的、有上限的，平铺开人也看得完；Agent 替你管所有的软件、所有的股票、家里所有的琐事，看见的一定超出人能处理的。第三轮的版本用演示数据（23 个来源，GitHub 1019 条最多），动画只是各行长出、总和那行长出去。用户的反馈（2026-11-03）：“右边那个图你想表达的是对的，但是你的动画做的不到位，应该是从左往右播放，然后把这些全加在一起，表达 Agent 如果帮你管全部，就会是爆炸式的，agent 顶到底的时候，其他的都往前缩到一点点……然后 message 的数量明显是要更多的呀。。因为 message 有那种大群。。比如你加了 discord，github 不一定是最多的。”所以数据换成一般人的一天，动画换成三幕。

第一版三幕（19 行，总和 1850，最大一项 500）看过逐帧条后，同日又改了两处（协调方拍板）：一是第 3 幕没有“缩成一点点”，总和只有最大一项的 3.7 倍，Discord 那行还剩整宽的 27%。问题不在量级，在口径：人加的群不是三个，是几十个，每个群都是单独的来源，Agent 每个都要读，所以一个群一行。二是第 2 幕乱：几十段同时从各行斜着飞向总和那一行，路线交叉；改成先竖直落、再水平滑，按批落，任何时刻在路上的不超过两批。

- 标题：**一个软件的通知有尽头，Agent 看见的没有。**（不变）
- 导语：一个软件只管自己的通知：幼儿园 App 一天发几条，翻一翻就看完了。可要是让 Agent 替你看着所有的群、邮件、工作、股票和家里的琐事，它要读的是这些加在一起。一个人往往加了几十个群，每个群一天几十到上百条，光是群消息一天就上千条。首屏那片点就是这样的一天，一个点是一条。Agent 看到的一定比你能处理的多，所以它得替你取舍：留下的，应该是你此刻能处理、也最值得处理的那部分。（“上千条”是 32 个群加起来 1965。导语不写阿拉伯数字。）

#### 三幕（只演一次，进视口触发，约 5.3 秒）

时刻的唯一出处是 `landing.mjs` 的 `WHY`，`whyModel()` 把它写成图上的 CSS 变量，并核对第 1 幕长完才开始第 2 幕、第 2 幕落完才开始第 3 幕；只动 transform 与 opacity，没有逐元素的脚本帧循环。

#### 数据与出处（`why.day`，由 `landing-data.mjs` 的 `DAY_SOURCES` 写入）

### 第 3 节 · 带宽随处境变（#bandwidth）

- 标题：**处境定了带宽，带宽定了编码。**
- 小字：带宽随处境变化 · 同一时刻

- 六行（手机）/ 六列（桌面），从窄到宽，每个小图的宽度随带宽变大（`landing.mjs` 的 `LADDER`）。2026-11-03 用户说 Top 6 里“手机首页”和“回应托盘”太像，手机首页换成 A 空间排布（电脑上的注意力方块），它的处境是“坐在电脑前”，排在折叠屏之后、两周小倍数之前。六个 id 与名字在 `LADDER` 里自己列，不读第 5 节六张卡的组成与顺序；一行有对应的卡就滚到那张卡，没有（现在的 A）就直接打开原型（桌面在弹框里，手机上是原型本身）。每行最多一个数：

### 第 4 节 · 一种编码的例子：把注意力切成固定的份数（#example）

- 标题：**把注意力切成固定的份数**
- 导语：原型里试的一种编码：把每一层的注意力切成固定的份数，演示里是 64 份（份数可以配置）。Agent 每一轮把这些份数分给各件事，份数就是面积。有了面积，同样的轻重就能在手表、手机和桌面上分别画出来。下面是演示回放里真实的一轮：8 月 13 日中午到半夜，你离开的 12 小时。

## 约束

- **同源：** 首屏的场、三扇窗与它们的账，第 2 节的每一行，第 3 节的每个数，以及页面上的每一处白话，都读 data.json，`check-landing` 逐个核对（页面上 59 处、44 个出处）。首屏与第 2 节是同一天的示意（`hero`、`why`），不是演示回放：第 2 节的数有出处表，首屏的件是为这一天写的、由固定种子生成；`check-landing` 还逐层数点，核对场里亮着的点正好是窗里那几件的输入。第 3、4 节读演示回放（f22）。
- **少写数字：** 一个数如果读者要停下来想才懂、或者不影响论点，就不写（用户：“你不要到处写满数字。。这个 26 重要吗”）。首屏每种处境最多一个数，一天的总条数（2565）留一个；第 3 节每行最多一个；第 4 节只留讲清这一拍必需的；第 2 节只写比例那一行的 150 与 2565，括号里写还有几个群、几个来源。能用一句白话说的，不写一串数。删掉的数仍在 data.json。
- **白话：** 入口页正文（第 5 节六张原型卡、画廊、弹框里是原型自己的样子，不算）不出现 #编号、PR、CI、master、演示里的人名与瑞典语，也不直接搬演示原文的标题、问题与选项；`check-landing` 核对。
- **平常的书面语：** 像一篇清楚的说明文，精准、简洁，不为了俏皮造词（用户：“中文真的不说『接得住』这种拗口的、文不文俗不俗的表达”）。改掉的说法见上文「用词」，`check-landing` 核对正文与页面描述里不再出现。
- **只演一次：** 首屏一遍、停在复盘；第 2、3 节进视口各画一次。唯一一直在动的是画廊和录像。
- **原地：** 没用到的点原地变暗，不飞、不删；窗从中心改形；柱在自己那一列下面升起。
- **朱红只给等你回应：** 场里归到等你那几件的点、要紧那件与等你那几件的面积、复盘柱里此刻等你的几段、账里“5 件等你”、第 3 节里“1 件要紧”、A 小图里待答的卡。
- **64 只在第 4 节：** 首屏、第 2 节、第 3 节的文字里都不写 64（腕上一瞥与两周小倍数的小图本来就画着它们的刻度与方阵，那是原型的样子）。
- **不劫持滚动；不拟物。**
