## A. 适配审计与选型

### 怎么量的

- 31 个原型逐个**直接打开 `href`**（整页，不是画册里的嵌入），在 390 × 844（手机，DPR 2，移动模拟 + 触屏 + iPhone UA）、820 × 1180 与 1180 × 820（iPad，移动模拟 + 触屏 + iPad UA）、1440 × 900（桌面）下截图。载入后 5 秒截一张，再按一下 Shift（“讲一遍”被任意键跳过）2.2 秒后截第二张，并在页面里量：实际排版宽度、视口内最小字号、小于 10px 的文字数、短边小于 24px 的点按目标数、纵向几屏、报错。四个尺寸 124 次打开，**没有一次报错**。
- 关键量是**排版宽度**：页面要的宽度比设备宽时，手机浏览器整页缩小。例如来源矩阵在手机上排成 1440px 宽，缩到 27%，最小字实际只有 2.5px。
- 概念卡：形式页直接打开时概念卡展开，在手机与 iPad 竖屏上盖住主图。原型本来就接受 `?card=0`（画册嵌入用的就是它），所以另拍了带 `card=0` 的一组；入口页在手机上打开形式页时带上它，不改原型。
- 联系表：`landing/contact/sheet-01…08.png`（每行一个原型 × 四个尺寸，图下写量到的事实），`grid-phone.png` 与 `grid-padP.png`（31 个原型的手机 / iPad 竖总览），`landing/audit/extra/`（`card=0` 与手机横屏补拍）。

### Top 6 及顺序（2026-11-02 拍板）

> 2026-11-03 第四轮改为 **A 空间排布 → 回应托盘 → 腕上一瞥 → E 折叠屏 → B 时间展开 → 两周小倍数**，D 手机首页移进画廊，见文末“第四轮”。下面是 11-02 的原始拍板。

用户审过第一段后定下的顺序：**D 手机首页 → 回应托盘 → 腕上一瞥 → E 折叠屏 → 两周小倍数 → B 时间展开**；画廊第一是后来加的智能眼镜，原版树图第二。相邻两个仍在**带宽、注意力时长、交互能力**上拉开：一按就答的一分钟 → 一只拇指几分钟答完 → 只读一个数的两秒 → 翻开读来龙去脉 → 不作答的复盘 → 看期限谁先到。实现里这张表是 `site/.vitepress/theme/landing.mjs` 的 `TOP`，桥的六个小图、六张卡与录像脚本都读它。

1. **D 手机首页**（5 / 4 / 5 / 5）。处境：离开半天回来，掏出手机看一分钟。限制 → 顺应：一屏只放得下三张卡、拇指只够一排按钮，所以首页只排等你回应的事，最急的最大，一按就答、原地收成回执。三端适配最好，也是拍 3 那张卡的原型。
2. **回应托盘**（5 / 3 / 5 / 4）。处境：排队、通勤的几分钟，一口气答完。限制 → 顺应：一只拇指、几分钟，所以按“要点几下”排，托盘几排就是几下。手机最贴合的两个之一，接在 D 后面：同为作答，回答的是“要花多少力气”。
3. **腕上一瞥**（3 / 4 / 5 / 5）。处境：抬腕两秒。限制 → 顺应：两秒读不了一句话，只读得了一个数和一圈刻度；64 份卷成 64 格表圈，中间只数要紧的。它的表圈就是入口页那把尺卷成的圆。手机上需要 `card=0`、页面缩到 75%，表盘本身清楚。
4. **E 折叠屏**（2 / 4 / 5 / 5）。处境：翻开折叠屏或横放 iPad，想知道这几张卡从哪来。限制 → 顺应：屏幕大了一倍，就把这一轮的原料摊在左页，一条线穿过折痕连到右页那张卡。入口页拍 2 的 158 / 34 / 6 / 118 就是它左页的账。iPad 横是它的姿态。
5. **两周小倍数**（3 / 4 / 4 / 4）。处境：周末复盘，十分钟，不作答。限制 → 顺应：要看的是走向，所以每轮一张 8×8 的小方阵同尺度并排。六个里唯一回答“两周”的。
6. **B 时间展开**（3 / 4 / 4 / 4）。处境：想知道哪件事的期限先到。限制 → 顺应：时间往右展开，此刻是一条竖线，每件事一条带，期限落在此刻线之后的哪里就标在哪里。适配比原版树图好；桥上它的小图画的就是“期限落在此刻线之后的那几条带”。

### 其余的在画廊里的顺序（不写死数量）

画廊 = `prototypes.mjs` 的全部原型减去 Top 6，按 `landing.mjs` 的 `GALLERY_ORDER` 排；表里没有的新原型自动排在末尾，标题“还有 N 种呈现方式”（第四轮前是“还有 N 种读法”）的 N 与导航面板的卡数同样由清单现算。现在 32 − 6 = 26 个（第四轮起）：

智能眼镜 → D 手机首页 → 原版树图 → 整理脉冲 → 等待链 → C 流动形态 → 变形 → 份额拨盘 → 回应时序 → 峰值保持 → 让位图 → 驻龄 → 批次记谱 → 拔河 → 身份线 → 来源矩阵 → 结绳 → 回应组件 → 对话线程 → 晨间朗读 → 到期时刻表 → 出处栏 → 头版 → 小票 → 进程条架 → 环境球。

- 规则：智能眼镜（2026-11-03 合入，手机与 iPad 上都能直接点滑）放第一；D 手机首页（第四轮从六块移下来，手机上最好用）第二；原版树图是“桌面树图”本身、其余形式的出发点，放第三；接着是画面最强的与手机或 iPad 能用的（脉冲、等待链、C、变形、拨盘），再按“完成度 × 代表性”排桌面类关系图，然后是组件演示，最后是第一轮撤下的八个（环境球最后）。
- 轮播分三行，按位置轮流发牌（第 1、4、7… 个进第一行），每一行都混着能在手机上打开的与带“桌面”标的。

### 手机上基本不可用的（不改原型）

- **读不了（手机 1 分）**：身份线、回应时序、来源矩阵、让位图、批次记谱、变形、峰值保持、驻龄、等待链、拔河、结绳，共 11 个（`landing.mjs` 的 `DESK_ONLY`）。画廊块右上标“桌面”；手机上点开先出一张底部说明卡：“这个形式按电脑宽度排版，在手机上会缩到三成左右”，按钮“分享 / 复制链接”“仍然打开”“关闭”。
- **能看但体验差**：第五节 A、E 折叠屏、B 时间展开、两周小倍数的块上（只在手机上），按钮旁写“在电脑上查看效果更好”（E 是“在横屏平板或电脑上查看效果更好”）。第五轮起不再写死这四个：按块实际的缩放判断，低于 0.5 的才在块下写“在电脑上看更清楚”，见“第五轮”。
- **手机上打开**：同一个标签页打开原型本身，不带帧号（好让它讲一遍），形式页带 `card=0`（主图不被概念卡盖住），链接带 `rel="noreferrer"`。iPad 与桌面在本页的查看弹框（PrototypeLayer）里打开。

横向看：

- **节奏。** 好的首屏要么是入场型（三拍两三秒讲完然后安静：Linear、Raycast），要么是一个窗口里的一圈演示（Granola 10 秒、Apple 6.8 秒）；概念段是步骤型（MLU：每段一个变化，补间 0.4–0.6 秒）。入口页据此定为：首屏 3.4 秒搭一次、停在终态；三拍是步骤型，每拍 1.8–2.4 秒、单个动作 0.24–0.7 秒。
- **第一个动作。** 1 秒内可读的（Stripe、Dia、Apple 0.25 秒，Granola、Raycast 0.5 秒）比黑屏等片头的（Rive、Linear 1.75 秒）好得多；信息性的动作（Stripe 跳动的真实数字、Granola 的笔记被整理）比装饰性的（Raycast 的斜条、Rive 的字母）有力。入口页的首帧本身就是一张完整的图（64、标题、空尺），0.4 秒开始动，动的是真实刻度与真实条数。
- **不劫持滚动。** 12 个站在手机上**都没有**劫持滚动（每次滚 506px，实际也走 506px），也没有一个在手机上用 scroll-timeline、视频随滚动拖动或 canvas 序列帧。主流是 sticky 图层 + IntersectionObserver 触发补间、媒体只在视口内播放。入口页照此做（见 F）。
- **体积。** 手机首 5 秒中位 2.81 MB（0.63–14.7 MB）；轻档（< 1.2 MB）全是 DOM、SVG 或静图（Granola、MLU、Pudding）。入口页定在轻档之下：首屏 ≤ 220 KB、零视频；全页滚到底、六段 showcase 录像与轮播里出现过的块都播过一遍时 ≤ 3.5 MB。
- **减弱动态。** 做得好的（Rive、Apple、Linear）是“直接给终态或静图”；一半站点不处理。入口页所有拍直接给终态。

## F. 技术方案（按实现）

### 动画用什么画

- **首屏（第三轮）是一片 SVG 点阵加一扇会改形的窗。** `fieldSVG` 从 `hero.field` 生成五层 SVG（全部 3051 个点一层，用 `stroke-dasharray` 把每列每行画成一笔；亮着的四档各一层，用相对坐标的短笔画），每层是一个独立的 `<svg>`，所以“原地暗下”“亮回来”都是整层的 opacity，合成线程就能做，不重绘点阵。窗是一个绝对定位的 `<i>`，三种形状由 `--w1…--r3` 定义，改形动的是 width / height / border-radius（只有这一个元素在主线程上动）。三扇窗的内容（表盘的字、`deskHTML` 的面积图、`reviewSVG` 的 26 根柱）预先都在页面里，按处境淡入淡出。关键帧与时刻由 `momentCSS()` 从 `MOMENT` 生成，放进场那一块的 `<style>`。
- **第 4 节的舞台是一段生成的 HTML，不是 SVG path。** `landing.mjs` 的 `stageHTML(data, 'beats')` 从 data.json 生成（第二轮时首屏也用它，第三轮首屏换掉后只剩这一处）：158 道刻痕放在每条车道按去向（你、Agent、折掉）分的三个组里，一共 15 组，外面套一个随播放线滑开的窗口（`.fl-sweep` 与 `.fl-sweep-in` 两层反向位移，刻痕本身不动）；尺上每件事一个 `<div class="sg">`（`--x/--w` 这一轮、`--bx/--bw` 上一轮）；40 颗点各是一个 `<i class="dt">`。x 是绘图区宽度的百分比（位移用 `cqw`，绘图区 `container-type: inline-size`），y 全由 CSS 变量算，所以 SSR 不需要视口，构建出的 HTML 首绘就是完整的图。
- **点落在它到达那一刻那一段所在的位置。** 让位与落点同时进行，所以 `stageHTML` 按 `TIMING`（各时刻的唯一出处）与让位的缓动曲线算出每颗点到达时它那一段的左边与宽度，把落点（`--xl`）写进 HTML；点的弧线是 `@keyframes fl-drop` 里 11 个样点（横向与纵向两条缓动叠成），之后压扁、缩没。每段接收期间的加深（`.h`）与尺下数字的计数（`fl-roll-<格数>`，每一格在段宽越过那一份时换）也由同一张表与同一条曲线算出。
- 生成的标记用 `createStaticVNode` 放进模板，不用 `v-html`：Vue 3.5 水合时会重设动态的 innerHTML，把首屏的元素整个重建一遍，动画在首绘后约 0.5 秒（4 倍节流下约 1 秒）从头再来。静态 vnode 直接认领服务端渲染的节点；一个组件按一个节点水合，所以每段舞台拆成刻度栏与绘图区两块。
- **首屏是纯 CSS 关键帧**，首绘即开始，不等脚本：两周一列列铺进来 → 骑车（窗张成圆，其余点原地暗下，28 个朱红留着）→ 桌前（窗改形，面积图）→ 复盘（窗全开，26 根柱在各自那一列下面升起）→ 停住。第一个动作在首绘后 100ms，全程约 8.3 秒，45 个 CSS 动画（其中 26 个是柱的升起）。减弱动态时不挂动画，服务端渲染的 HTML（`data-s="3"`）本身就是终态。点处境按钮时脚本给舞台加 `.manual` 并改 `data-s`：动画摘掉，三种状态之间改用过渡（窗 650ms 改形，旧内容 140ms 先收，新内容在窗有了形状后 380ms 淡入）。
- **三拍是静态状态加只在 `.tx` 下挂上的动画与过渡**：`.fl-round` 上的状态类 `s1 s2 s3 ans` 描述终态，`.tx` 下才挂动画（与首屏同一组 `@keyframes`）和过渡。脚本只负责按阅读线换类；跳拍（一下滚过两拍）先摘掉 `tx`，直接到终态，不排队。舞台高度不变：前两拍车道占满（`--HL` 由卡高与第 3 拍的压缩比 `--s3` 算出，正好让尺落在底边），第 3 拍车道压到两成、整块上移，让出的高度给卡。
- **同一处换字先出后进**：拍号、大数、右侧小字的隐藏态带 140ms 的淡出，显示态带 140ms 延迟的淡入，所以任何一帧都只有一段字。
- 除首屏那扇窗的改形外，只动 transform 与 opacity；数字是 DOM 文字，只在节拍上换一次（拍 1 的计数除外）。不用 canvas、WebGL、Lottie、GSAP。

### 滚动联动但不劫持滚动

- 页面原生滚动；叙述区的舞台 `position: sticky`，四段文字（三拍与回流）在正常文档流里。
- 阅读线：桌面在视口 55% 处；手机在舞台下沿之下、剩余高度的 35% 处。`scroll` 监听只在 IntersectionObserver 说叙述区在视口附近时挂上（`rootMargin: 50%`），每帧最多算一次。
- 往回滚直接给上一拍的终态，不倒放；不监听 wheel / touchmove、不 `preventDefault`、不用 scroll-snap 与平滑滚动库。

### 录像与静帧怎么预制（`scripts/record-landing.mjs`）

- 画廊的录像：用本机 Chrome 的 `Page.startScreencast` 录（要在导航之前开始、带 GPU 参数），重采样到 15 fps，最后一帧一直停到片尾；ffmpeg `libx264 -tune animation`、`+faststart`。默认自己起一个本地静态服务读仓库根目录（VitePress 开发服务器不解析 `/prototype/` 的目录页）。桌面 1440 × 900 录、编码 480 × 300。
- 有剧本的几段：D 从 f21 走到 f22（全站的“此刻”；原来是 f25 → f26）再按下第一张卡的推荐按钮。其余不带帧号打开，让它自己讲一遍；第一轮撤下的八个与身份线、来源矩阵、批次记谱按 → 走 20 步。份额拨盘、驻龄画面变化多，`crf 35`。
- 第五节六块的静帧（第四轮起，六段录像与封面删掉了）：每个原型按块的尺寸（`TOP.view`）以 `?embed=show` 打开，播放的七帧（`LIVE.frames`）各截一张，宽 820px（托盘与腕上一瞥 600px），cwebp q64，超过 40 KB 的先降质量再缩小，存成 `site/media/live/<id>-<帧>.webp`。
- `--only <id>` 只录这几个（六块之一就重截它的静帧）；清单之外的新原型（例如智能眼镜）不用改脚本，按桌面 1440 × 900 录 12 秒。没有录像的原型在画廊里显示它的预览图，`prepare-site.mjs` 写出 `landing-media.json` 告诉入口页哪些录像在。
- 实际体积（第四轮）：画廊 26 段 19–118 KB（D 手机首页 35 KB，第四轮补录；A 的录像删掉）；静帧 42 张 16–35 KB，合计约 1.1 MB。

### 手机上点开

- 手机（宽 ≤ 1180 的触屏视为移动端）上“打开原型”与画廊块都是同一个标签页打开原型本身：不带帧号（让它讲一遍），形式页带 `card=0`，链接带 `rel="noreferrer"` 与 `target="_self"`（让 VitePress 的路由不拦截这些静态页）。返回键回到入口页原位。

### 怎样接进 VitePress

- `site/index.md` 的 frontmatter 是 `layout: FoldLanding`（全局注册的组件，拿到全宽画布），其余文档页仍是 `doc` 布局。
- `config.mts` 的 `transformHtml` 只对首页：去掉 VitePress 的 `check-dark-mode` 内联脚本、给 `<html>` 加 `fold-landing-page`、预载中文子集；主题里一个 MutationObserver 在入口页上把 `dark` 摘掉，离开时还原用户原来的外观。入口页藏起外观开关，文档页照旧可切换。
- 主题改从 `vitepress/theme-without-fonts` 继承，去掉 Inter；`theme/style.css` 把 VitePress 的颜色变量映射到纸与墨，标题用 Fold Serif SC，文档的“文档”下拉菜单在桌面上排成两列（六组读者，不再比屏幕高）。

## 第四轮（2026-11-03，第五节换成实时原型）

用户看过第三轮后的意见：标题“同一份状态，六种读法”改成“同一份状态，不同的交互呈现”；手机首页和回应托盘太像，第一个换成电脑上的 A 空间排布，最后两个互换；这六个最好是真的原型，分块嵌进来、跟着同一份数据同步播放、不让用户操作，而且不能卡，性能要优化，不能把六个原型整个搬进来；下面的画廊用录像；不要到处写数字。

### 改了什么

- **组成与顺序**：A 空间排布 → 回应托盘 → 腕上一瞥 → E 折叠屏 → B 时间展开 → 两周小倍数（`landing.mjs` 的 `TOP`）。D 手机首页移进画廊，排第二；A 从画廊移出。画廊仍是全部原型减去这六个。
- **文字**：小字“六个原型 · 同步播放”，标题“同一份状态，不同的交互呈现”，导语说明这是实时运行的原型、读同一份回放、由同一个时钟驱动。每块的说明一句话，不写数字，不写演示数据里的人名；画廊标题改成“还有 N 种呈现方式”。
- **每块是原型本身**，以 `?embed=show` 打开（只在原型自己的页面与模块里加，不动 `scenario.mjs`、`shared.mjs`、`engine.mjs`、`respond.mjs`、演示数据与契约）：
  - `prototype/embed.mjs` 新增 `showing`（只看参数，所以静帧也能直接打开截图）与 `shown()`：嵌入的页面第一次画好后多发一条 `{fold: 'shown'}`；
  - `prototype/index.html` 给 `<html>` 加 `is-embedded is-show`，`explore.mjs` 挂好变体后调 `shown()`；`forms/shell.mjs` 给 `<body>` 加 `fs-show`、不出概念卡、挂好后调 `shown()`；
  - 各原型自己的样式表藏掉控件：A 与 B 的工具条、时间控件与说明，E 的侧栏与把手，托盘下面的规则与按钮，腕上一瞥只留问题与表盘，小倍数的工具条；`forms.css` 去掉形式页的顶栏；
  - 这样嵌入时，页面的动画循环在没有变化时休眠（`embed.mjs` 的 `sleepLoops`）：A、腕上一瞥与小倍数的循环即使画面不动也每帧运行（共用交互模块每帧重画指针线），单独量（4 倍节流）每秒分别占主线程 91、29、94ms。现在一帧回调里再请求的下一帧，若页面 2 秒内没被唤醒、0.5 秒内 DOM 没有真正的变化（同一个值重设不算），就先压住；下一条消息（换帧）、窗口尺寸变化或 DOM 真正变化时放行。只在嵌入且带 `embed=show` 时生效，单独打开、画册与检查脚本都不受影响。
- **不能操作**：iframe 是 `inert`、`tabindex="-1"`、`aria-hidden`、`pointer-events: none`、`scrolling="no"`；块本身是一个链接（不进 Tab 顺序），点它与点“打开原型 ↗”一样，在查看弹框里打开可以操作的完整原型（手机上同一个标签页打开）。手指在块上滑动，滚的是页面。
- **按原型自己的尺寸排版再缩放**：A 1180 × 580、托盘 390 × 800、腕上一瞥 390 × 520、E 1180 × 760、B 1180 × 660、小倍数 1180 × 800（`TOP.view`），块的宽高比就是这个，iframe 按这个尺寸排版，用 `transform: scale(块宽 / 设计宽)` 缩进去。宽桌面两行各三块，一行的块同高；平板两列；手机一列。

### 同步：一个时钟

播放器是 `site/.vitepress/theme/live.mjs`，参数在 `landing.mjs` 的 `LIVE`：

- 时钟从 f16（8/11 零点）一轮一轮走到 f22（全站的“此刻”，8/14 周五零点），每轮 3.4 秒，在 f22 停 7 秒，再从头来。（起初是 f20 → f26；全站的“此刻”改成 f22 后跟着改。）
- 用画册（all.html）的 followFrames 协议：时钟给每个在播的页面发 `{fold: 'go', frame}`，页面回 `{fold: 'at', frame}`。时钟往下走之前要等三件事：在播的页面都已报到当前这一帧（最多 4 秒），正在载入的页面画好（最多 3 秒），屏幕上显示静帧的块下一帧的静帧已解码（提前 1.6 秒取，最多 3 秒）。所以任何时刻六块都是同一轮。
- 每块底下先放当前帧的静帧，页面只在它的帧等于时钟的帧时才显示在上面（260ms 淡入）。直接载入在当前帧的页面画好就显示；落后的页面（离开屏幕后停下、或载入期间时钟走了）先被静帧盖住，收到当前帧、播完它自己的过渡（1.1 秒）再显示。
- 进度提示是六块共用的：七格短线加一行“8/13 中午 → 此刻”，由 `liveLabel` 以 data.json 里那一帧的时刻为准、按 12 小时一轮推出（与回放里 f16–f22 的时刻一致），最后一轮只写“此刻”。

### 性能怎么省

- 第五节靠近视口之前不建 iframe、不请求任何原型文件或静帧（IntersectionObserver，上下各留 40% 屏）。
- 只给在屏幕上或离屏幕不到 0.35 屏的块载入页面，同时最多：手机（< 700px）2 个、平板（< 1200px）4 个、桌面 6 个；一次只载入一个，块要被需要 220ms 以上才载入（一滑而过的不载）。
- 离开屏幕的页面停止跟随（暂停）；离开超过一屏、或屏幕上的块需要它的名额时卸载，换成当前帧的静帧；整节离开 1.4 屏以外时全部卸载。回来的块直接载入在当前帧，不会和别的块错开。
- 标签页隐藏或查看弹框打开时时钟停下。
- 嵌入的页面没有变化时不跑动画循环（见上，`sleepLoops`）。1440 × 900、4 倍节流、六个都在播时量 8 秒（含两次换帧）：掉帧从 55.8% 降到 42.5%；把六个页面的循环全部停掉是 27.3%，把 iframe 藏起来是 5.4%，剩下的主要是六个原型同时换帧的那一下。
- 手机上的降级：`LIVE.phoneStill` 里的原型在手机上只播跟着时钟的静帧、不载入页面，标准是单独打开（4 倍节流）时换帧的长任务超过 250ms。现在是空的：f16 → f22 各原型换帧的长任务最长是腕上一瞥 219ms（到 f22 那一步）、E 折叠屏 107ms、B 103ms、A 68ms，托盘与小倍数没有。播 f20 → f26 时 E 折叠屏在 f23 那一步是 259ms，那时它在手机上只播静帧。
- 静帧：六个原型 × 七帧 = 42 张 WebP，16–35 KB，合计约 1.1 MB；只有在屏幕上或快到屏幕上的块每轮换静帧。
- 减弱动态：不建 iframe、不走时钟，`<picture>` 的 `<source media="(prefers-reduced-motion: reduce)">` 在脚本运行之前就显示 f22 的静帧，进度写“此刻”。

1. **慢电脑上六个同时换帧会顿一下。** 桌面 4 倍节流时，六个原型在同一刻换帧，长任务最长 424ms。可以把桌面的上限从 6 降到 4（第二行先放静帧），或者让六块的换帧错开几十毫秒（同一轮内，看起来仍是同步）。现在按不节流的实测保留 6。
2. **回放 648 KB 是第一个页面必须下载的**（原型的演示数据），之后的页面都是 304。若要更省，得让原型改读一份只含播放那几帧的数据，这超出了“不改演示数据”的范围。

### 1. 块刚滚进视口时的白块

**原因（先录屏，再改）。** 第五节每块里只有一张 `<img loading="lazy">`（第一帧 f16 的静帧），块本身是 `--paper-2` 底，没有别的东西。浏览器的懒加载要等块接近视口才开始取图；时钟走过几轮后，块一接近，`live.mjs` 又把 `src` 换成当前帧，还没载完的那次请求被换掉、从头再取。静帧每张 16–35 KB，网慢或延迟大时，块已经在屏幕上了图还没到，看到的就是纸色的空框（改前录屏：块的边框画着、里面全是纸色，页面里记的状态是“静帧未载入、没有占位”）。画廊同理：预览图也是懒加载，录像在第一帧播出之前是透明的，底下空着；轮播把块从屏幕外横着带进来，懒加载要等它进了这一行的可见范围才取。iframe 不是原因：它在发来 `{fold: 'shown'}`、并且到了时钟那一帧之前一直是透明的（`check-landing` 现在逐帧核对这一点）。

**修法。**

1. **内联占位缩略图。** 第五节每块第一帧的静帧缩到 32 像素宽、每个原型的预览图缩到 24 像素宽（WebP，q40，每张 80–290 字节），以 data URI 写进 `site/landing/placeholders.json`，入口页把它作为块与画廊块的背景（CSS 变量 `--ph`，`cover`），放大后是一张模糊的缩略图，颜色与布局接近那个原型的首帧。38 张共 6.5 KB；首页 HTML gzip 后 25.4 → 28.9 KB。生成：`node scripts/record-landing.mjs --placeholders`（只要 cwebp）；录过六块的静帧后自动重写；`placeholders.json` 记着每张取自哪个文件和它的哈希，静帧或预览图换了而缩略图没重写时 `check-landing` 不过。
2. **提前取静帧。** 第五节进入 1.4 屏以内（原来用来卸载的 `far` 观察器）时，六块都换成时钟当前帧的静帧并改成 `eager`，不等懒加载。一张静帧载入后会一直留在屏幕上，直到下一张载完，所以之后换帧不会空。每次接近只取这六张；时钟之后每轮仍只给近处的块换静帧。
3. **滚动停下才载入原型页面。** 录屏时同时记了 iframe 的增删：快速滑过第五节时，块高、`wanted` 一下就超过 220ms 的门槛，页面每 200ms 建一个、又拆一个，每个在 4 倍节流下占主线程约一秒，合成线程那时赶不上光栅化，偶尔有一两帧整块没画出来（连边框都没有）。现在 `pump()` 还要等滚动停了 180ms 才载入。
4. **画廊录像的 poster。** 原来没有 `poster`，封面是叠在录像下面的预览图。现在给 `src` 的同时把 `poster` 设成同一张预览图（不写在标记里，免得首屏就去取 26 张预览图）；录像仍在第一帧播出后才盖上去，底下依次是预览图和内联占位。

**验收：逐帧录屏。** 本机无头 Chrome（开 GPU），CPU 4 倍节流，网络限速 1.6 Mbps、150ms 延迟，另给每个静帧、预览图、录像请求加 800ms；页面载入后跳到第五节上方一屏，用 `Input.synthesizeScrollGesture` 以 3200 px/s（手机，触屏）/ 4000 px/s（桌面，滚轮）一路往下滑过第五节与画廊，停 1.2 秒，往上滑回第五节，停 1.2 秒，再往下滑一遍；全程 `Page.startScreencast` 逐帧录。页面里每一帧同时记下每块的位置，按录屏帧自己的滚动位置校正后，在每一帧里找出屏幕上的每一块（第五节的块与画廊块，桌面去掉固定导航盖住的部分），块内（去掉 4px 边）与 `--paper-2` 相差超过 10 的像素少于 0.4% 记为空白；块里那一片在静帧原图里本来就是白的不算。工具是会话 scratchpad 里的一次性脚本（`blank/blank-run.mjs`），录屏帧、逐帧条与每次的明细也在那里。
