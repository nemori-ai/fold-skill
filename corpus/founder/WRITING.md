# founder 语料的写作指引

状态：2026-11-03 起用，给并行写节拍表的四位写作者。剧情与目标以[大纲](OUTLINE.md)为准；人物、渠道、事项、问题、预算与归属以 [beats/_cast.json](beats/_cast.json) 为准。本文的表由 `_cast.json` 整理而来，两处对不上时以 `_cast.json` 为准，并告诉架构。流水线与命令见 [README](README.md)。

四个人分头写同一个人的两周。合起来要像一个人真实收到的消息：钟点对得上，他本人不会同时在两处说话，数字前后一致，群里的人说话像群里的人。

**剧情归线，噪音归渠道。** 剧情消息由它所属的线的那一份写，哪怕落在别人的渠道里：B 在 9/16 19:44 “大模型应用开发”群里的那句问话由 main-ops 写，C 的估时出现在“飞书 · 白鹭上线”由 main-customer 写。噪音由负责那个渠道噪音的一份写；“飞书 · 白鹭上线”由 A 和 B 共用，噪音只归 main-customer。落在别人渠道里的剧情已经算进你那一份的预算（第 1 节）。

### 文件

```
corpus/founder/beats/
  _cast.json          共用设定，只读：people、pools、channels、items、asks、templates、ignore_reasons、parts、budget
  main-customer.json  {"beats": [...], "noise": [...]}
  main-ops.json
  side.json
  home.json
```

- 份文件只有 `beats` 与 `noise` 两个键。缺人、缺渠道、缺模板，或者要改问题、档位与预算，先告诉架构，由架构改 `_cast.json`；不要在自己的文件里绕过去。
- 拍号以事项的线字母开头（`A01`、`C14`、`F07`）；同一条线只在一份里，拍号不会撞。噪音组号以本份的前缀开头（`Nh-class-0910`、`Ns-dc-03`）。
- 人只用 `_cast.json` 的 `people`。群里的路人从 `pools` 的成员里挑（`class-07`、`discord-12`），同一个成员在同一个群里口气前后一致；不要另造人。
- `from` 一般不写：合并时按人在这个渠道或应用里的别名补上（陆晨在 GitHub 上是 `luchen-hz`，在三(2)班家长群里是“可可爸爸”，韩敏在那里是“可可妈妈”）。
- `dup_of` 只能指向本份里的消息。
- 通知类优先用 `_cast.json` 的 `templates`（`template` 加 `params`）；没有合适的模板就直接写 `text`。

### 一拍与一组噪音

字段沿用大纲[第 7 节](OUTLINE.md#7-数据形态)与[小样例](../../scripts/fixtures/founder-mini/beats.json)，只有 `ask` 不同：拆开的写法里 `ask` 只写问题编号，问法、短问法、选项与期限由 `_cast.json` 的 `asks` 展开。

```json
{"id": "I07", "item": "fd:I-dog", "level": "high", "ask": "i2",
 "gist": "韩敏在上海，问明早谁带土豆打针；他没回，22:50 她发“??”。",
 "misfit": "“??”是对同一问题的再发",
 "messages": [
  {"at": "2026-09-17T21:30:12+08:00", "ch": "wx-hanmin", "who": "hanmin", "text": "明天狗打针你带去吗"},
  {"at": "2026-09-17T21:30:40+08:00", "ch": "wx-hanmin", "who": "hanmin", "text": "我回不来 寄养那边要看疫苗本"},
  {"at": "2026-09-17T22:50:03+08:00", "ch": "wx-hanmin", "who": "hanmin", "text": "??", "ignore": "resend", "dup_of": "I07.1"}]}
```

| 拍的字段 | 写法 |
| --- | --- |
| `id`、`item` | 拍号与事项键；事项只能是本份的（`_cast.json` 里事项的 `part`） |
| `level` | 这一拍之后 Fold 应给的关注档：critical / high / normal / low / trace / none。大纲说“撤下”写 none；“丢弃”的消息放进噪音组或标 `ignore`，不另改档。一拍算在它第一条消息所在的帧；`_cast.json` 给事项写了档的帧，都要有这个事项的一拍从那一帧开始，那一帧最后一拍的档就是帧末的档 |
| `ask`、`answers`、`voids` | 登记、回答、失效的问题编号。登记帧按这一拍里第一条**别人**发来的消息算；回答帧按这一拍里**他本人**的第一条算；失效帧按这一拍的第一条算 |
| `gist`、`misfit`、`note` | 旁白：这一拍发生了什么、有意放的错位、备注。check 按大纲第 6 节扫禁用词 |

| 消息的字段 | 写法 |
| --- | --- |
| `at` | `2026-09-16T19:41:07+08:00`；秒要写，不要都是 `:00` |
| `ch`、`who` | 渠道编号、人的编号 |
| `text`，或 `template` 加 `params` | 正文 |
| `kind` | 省略即 message；其余见第 3 节 |
| `subject`、`url` | 邮件主题、GitHub 的标题与链接、飞书卡片的标题 |
| `ignore`、`dup_of` | 别人发来的、应被忽略的消息写理由（`_cast.json` 的 `ignore_reasons`）；重复的写它重复的那一条（`拍号.序`，序从 1 起） |
| `edited` | 发出后编辑过；只在飞书、GitHub、Discord（微信不能编辑，只能撤回） |
| `fragment` | 半截话（“在吗”“陆总”），同时写 `ignore: "fragment"` |
| `call`、`transfer` | 通话与转账的结构化字段，见 [3.11](#311-通话与转账) |
| `item`、`thread` | 一般不写。剧情消息的 thread 就是事项；噪音组在组上写 `thread`（`fd:n-<渠道>-<话题>`） |

一组噪音是一个地方的一个话题，通常 1–6 条：

```json
{"id": "Nh-owners-0912", "thread": "fd:n-owners-parking", "topic": "业主群里有人的车被堵在车位里",
 "messages": [{"at": "2026-09-12T08:14:33+08:00", "ch": "wx-owners", "who": "owners-03", "text": "B2-117 的白色车谁的 堵我车位半小时了", "ignore": "chatter"}]}
```

同一条通知发到两个群时写在同一组、同一个 thread，第二条写 `ignore: "dup"` 与 `dup_of`。

## 1 预算

数的是输入条数，含他本人。格子里 `12/3` 是 12 条、其中他本人 3 条；`·` 是 0。容差：每一行（第 5 节的渠道行）±10%，至少差 1 条才算超出；每一帧 ±15%，至少差 2 条才算超出；本人条数按行看，容差同上。`founder_corpus.py check --part <份>` 会把你写的条数和这些表并排打出来。

预算已经把忙的钟点放在剧情发生的地方：f17 切换、f20 故障夜、f07 教师节、f22 几件事都要第二天上午定；周末四天工作只剩告警、机器人和开源。格子是目标不是配额，剧情需要时可以在相邻帧之间挪一两条，只要每行、每帧还在容差里。

## 3 各渠道的文本形态

形状照应用里复制出来的样子写，文字一律原创，不抄任何真实通知的原文。例子里“｜”前是 `from`（合并时自动补），后是正文；只列与形态有关的字段。

### 3.1 飞书的文字

群聊与单聊。一句话常拆两三条，同一分钟；郑婉多用语音（`kind: voice`，正文是转出来的字，口头禅和同音错字照留）；截图写成 `kind: image`，正文一句说明；文件 `kind: file`，正文是文件名；发错或改数字时写 `edited: true`，或者紧跟一条“更正：”。

```
高翔｜我看下
高翔｜[图片] 识别超时率曲线，19:41 起从 0.3% 跳到 18%
高翔｜听澜那边超时 不是我们的
```

```
郑婉（voice）｜那个陆晨 你今晚把转接的方案发我 就写清楚几天能上 要几个人 我看完明早九点咱们对一下
```

```
何嘉｜周三晚受影响的来电：
1. 19:41–20:31 走了识别的 46 通（刚才写 64 是把重试算进去了）
2. 其中挂断 11 通，小罗今天上午回拨
3. 其余 35 通 AI 接了，多问了一轮
```

### 3.2 飞书的机器人

一张卡片一条消息，`kind: notification`，`subject` 写卡片标题。告警用模板 `alert`、`alert_recover`；部署 `deploy_ok`、`deploy_fail`；日程 `cal_invite`、`cal_remind`；审批 `approval`；文档 `doc_comment`、`doc_mention`。告警成串时每张卡的数值与持续时间要变，秒数错开（19:41:07、19:42:01、19:42:58），重复的写 `ignore: "alert_repeat"` 与 `dup_of` 指向第一张。

```

阈值：> 5%
持续：3 分钟
范围：白鹭口腔 · 全部门店
```

```
“滨江店：呼叫转移已设置（店长回复）”
```

### 3.3 GitHub 通知

照通知邮件的样子：`subject` 是“[saydone/saydone] 标题 (Issue #63)”或“(PR #64)”，评论前加“Re: ”；`url` 指向 issue 或改动；`kind` 用 curl 的名字：`issue_opened`、`pr_opened`、`comment`、`review`、`review_comment`、`state_closed`、`state_merged`、`state_reopened`、`state_review_requested`、`state_assigned`、`ci_failure`、`release`、`discussion_opened`、`discussion_comment`。状态变化用模板（`gh_closed`、`gh_merged`、`gh_reopened`），构建失败 `gh_ci_failure`，依赖升级 `gh_dependabot`，stale `gh_stale`，覆盖率 `gh_codecov`，PyPI 发布 `pypi_release`。frontdesk 是公司的私有仓库，标题与评论中英混写，提交信息用英文。

### 3.11 通话与转账

通话与转账带结构化字段（不给模型看），正文可以不写，渲染时按默认模板生成；要写成应用里的样子也可以写 `text`。`peer` 写对方在他手机里的名字。

```json
{"at": "2026-09-16T19:58:12+08:00", "ch": "wx-dad", "who": "luchen", "kind": "call_log", "call": {"direction": "out", "peer": "爸", "seconds": 74}}
{"at": "2026-09-17T09:25:40+08:00", "ch": "phone", "who": "mengjie", "kind": "missed_call", "call": {"direction": "in", "peer": "孟洁"}}
{"at": "2026-09-11T09:12:05+08:00", "ch": "wx-venue", "who": "luchen", "kind": "transfer", "transfer": {"direction": "out", "peer": "杜经理（弦外空间）", "amount": 2000}, "text": "转账 ¥2000.00 场地定金"}
```

他打出去的电话 `who` 是他本人；别人打来的（接了或没接）`who` 是对方。

## 4 用语

大纲[第 6 节](OUTLINE.md#6-用语规范)是规范出处，这里只取写消息时最常用到的：

- **中文按说话人的身份写。** 同事之间口语、短句、少标点，一句话常拆两三条；老师和机构用规范的书面语，不加套话。工程师真会说的英文词照用（PR、bug、上线、回滚、prompt、token），每条一两个。表情写成复制出来的样子，emoji 少用。错别字与半截话每百条人发的消息两三处。数字和时间照口语写：“明早九点”“三千左右”。
- **英文要像人写的。** 水平不一，可以有短句、拼写错误、缺主语，但不能像机器翻译或模型写的；不写 “I hope this message finds you well”“kindly”“delve”“Great question!”。issue 先说现象，再贴复现和日志；通知邮件先说日期和变化，再说要不要做什么。
- **旁白、标签与短名**（`gist`、`misfit`、`note`、噪音组的 `topic`）用白话中文；标签说一件事和它现在卡在哪，不写编号与 PR、CI 这类缩写。大纲列的禁用词（接住、闭环、抓手、拉齐、定夺、届时、cutover、follow-up、confirm……）在旁白里一律不用，check 会扫；人物台词里只许本人真会说的一两处（郑婉的“对齐一下”）。

**`ignore` 怎么标。** 只标别人发来的；他本人的消息不标。理由从 `ignore_reasons` 里选。剧情拍里也会有应忽略的（拍里的“收到”、重复的告警），照样标；噪音组里绝大多数都要标，只有偶尔一条真和他有关的（陌生人群里有人提到 saydone）不标。

**`dup_of` 怎么写。** “??”再发、同一告警的后续卡片、重复开的 issue、同一通知的第二个群、被更正的数字（64 通）写 `dup_of`，指向最早那一条；接龙里的“收到”、节日问候不写 `dup_of`（它们是附和，不是重复某一条）。

**一分钟里的成串。** 写聊天时先想“这人会不会一口气发三条”：韩敏、郑婉、老范、店长们会；高翔、杨帆、孟洁不会。机器人成串时秒数错开，间隔 40–70 秒。

**各份的噪音写什么。**

- main-customer：对接群里店长问操作、前台截图问“这样对吗”、转述客人的抱怨、节日的“辛苦了”、一波波“收到”；白鹭上线群里小罗转来的零碎问题与表情；三通推销电话。

- side：Discord 的配置问答与闲聊、X 的提及；saydone 上与发版无关的 issue、讨论与机器人；筹备群的分工、物料、签到表；参会者大群问地址、问回放、广告与表情接力；两个陌生人的群里转发、招人、问题没人答、吵模型哪家强；newsletter 与订阅号；报名通知；冷邮件、猎头、招聘平台与推销。
