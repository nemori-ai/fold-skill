# 决策记录

状态：首切片要求。本文是全仓库唯一记录未决问题的地方；其他文档正文陈述设计本身，不再逐句说明效力。

背景见[原始设计 v0.3](reference/design-v0.3.md)。产品意图见 [product.md](product.md)，职责边界见 [architecture.md](architecture.md)，工作方式见 [development.md](development.md)。

## 已对齐的方向

![已对齐方向、待定提案和历史参考是不同效力的材料，彼此没有自动批准或实现关系](assets/illustrations/14-design-status.png)

*方向指导设计，切片决定可写成用例；原始草案保留背景。*

- **泛化输入与结构化输出构成产品边界。** 输入可以来自 Agent 自身工作、外部观测或用户告知；输出是预定义结构，供 UI、推送与日志消费。Pinboard 和推送发送都是下游应用。
- **LLM 让语境估计成为可调用的环节。** Agent 结合当前状态和用户背景估计关注价值；Skill 通过表述转换与上下文供给帮助估计。估计质量需要用场景验证。
- **Agent 做判断，脚本守边界。** 重要性、让位和合并由 Agent 决定；脚本执行明确操作、检查约束、保留记录，不自行降档或驱逐。
- **信息失效与行动截止是不同概念。** 账单逾期后仍然重要；到期不推出撤下。
- **Skill 同时交付判断指引与操作工具。** Agent 通过固定语义的命令读取、提交、批注和查询，不临时实现存储与预算逻辑。

## 首个切片：US-01 单 Agent 本地闭环

冻结的标准是“能写成一致性用例”。下面每条都对应 [conformance/cases](../conformance/cases) 中的断言或 [skill 设计](skill-design.md)中的调用约定。

| 决定 | 内容 | 理由 |
| --- | --- | --- |
| 范围 | 单用户、单 Agent、本地目录存储、Agent 自己的进度声明、文字简报输出、批注往返。 | 这是 US-01 的完整闭环，也是最小可观察的产品。 |
| 份额协议 | Agent 提交五档 `weight`，脚本按固定比例派生 `share`：critical 3B/8、high 3B/16、normal 3B/32、low 3B/64、trace 1，向下取整，最小 1。B = 64 时为 24 / 12 / 6 / 3 / 1。 | LLM 擅长比较不擅长给数字；固定映射让同样的判断得到同样的份额，下游才能稳定布局。 |
| 超额处理 | 总和超过预算时整批拒绝，错误返回预算、声明总量、超出量和每项份额。不做同档平分、拥挤下调、自动降档或驱逐。 | 谁让位由 Agent 决定，脚本只说明超在哪里。 |
| 份额覆盖 | 可选字段 `share` 覆盖映射值，必须同时给 `reason`。 | 例外路径，保留 Agent 对尺度的最终控制。 |
| 输出字段 | 程序依赖的字段只有 `weight`、`share`、`rank`、`kind`、`status`。`rank` 由脚本派生：share 降序，同 share 时 needs-you 优先，再按 updated_at 新者优先，最后按 id 字典序。 | 消费者需要少量稳定字段；判断依据放进 `reason` 文本。 |
| 时间 | 存储用时刻：`created_at`、`updated_at`、`last_seen_at`、`due_at`、`stale_after`。读取视图按调用方传入的 `now` 投影为时长：`age`、`since_update`、`since_seen`、`until_due`、`until_stale`。到期只改投影，不改状态。 | 语言模型不擅长在时刻之间做算术；撤下必须是明确声明。 |
| 输入范围 | 首切片只接受 Agent 声明。声明可带可选 `sources` 附件记录来源，只存储展示，不参与校验。 | Observation 接入是一条管道，不是归约内核。 |
| 反馈状态 | 批注事件只记录“已保存”。Agent 在 commit 中带 `acknowledges` 才记为“已读”，且必须绑定一次实际提交。外部行动结果用 `kind` 和 `summary` 表达。 | 读取不等于处理；已读必须和一次整理绑定才可核对。 |
| 提交单位 | 一次整理是一个批次，整批校验、整批原子写入。 | US-03 的取舍相互依赖，不能分步保存。 |
| 调用时机 | 运行开始先读反馈和状态；只在产生用户可见变化的里程碑提交；运行结束前必须提交一次。 | 对非常驻宿主，闭环取决于这条约定。 |
| 首个渲染器 | 文字简报。按 rank 排序，critical 和 high 成段加粗，normal 单行，low 和 trace 折成尾注，时间用时长。 | 最便宜、跨渠道，并逼迫摘要本身可读。 |
| 实现栈 | Python 标准库，一个 CLI，`.fold/events.jsonl` 加 `.fold/snapshot.json`。 | 仓库工具已用 Python；首切片不需要依赖。 |

## 原稿中不再作为默认实现要求的内容

以下设计保留在原稿中供理解演进过程，未经重新讨论不按它们实现：

- 同档条目平分某个固定份额池，以及拥挤时整体下调。
- 编译器按固定顺序自动降档、嵌套、挤出条目，以替 Agent 完成溢出取舍。
- 溢出时优先撤下临近失效的条目，或把临近行动截止等同于信息价值降低。
- 把坐标与矩形排版放进通用内核。
- 起步时就交付双语言内核、全部框架适配器和远程 MCP 形态。
- 仅把 Agent 自己的工作进展视为输入；当前边界已扩展为泛化输入和多应用消费，首切片只是从 Agent 声明开始。
