## 原则

- **Agent 的批次是底稿。** 只在三种情况下改：判断会误导读者（该等你的被记成知会、不相关的事并成一件、随口的事占着最大份额）；语料的接缝或版本差异让 Agent 写错了事实；份额腾挪是上面两类修正的连带结果。措辞偏好、差一档的分歧都不改。
- **只改批次，再重放。** 修正写成对批次的 `patch`、`replace`、`add`、`drop`，重放被内核拒绝就停下；腾份额时优先提前撤下 Agent 自己后来也撤下的痕迹，并沿用它的理由。
- **不改原文。** MIX.md“接缝”一节列的不一致（公寓与房子、住在法国、问的是狗而人物养猫）与家庭流和其他流之间的接缝都不改输入，影响理解时在旁白里带一句。
- **回应路径与反馈是演示数据先行定下的形态**（见[原型说明](../../README.md#演示数据)），不是 Agent 的输出：ask 由打磨时登记，反馈从本人的后续动作推出；家庭流的后续动作是作者编写的。

## 最常见的几类错误

按自由运行的全部 28 帧，不只是被修正的那些：

1. **家里的事普遍高一档。** 家庭流平均占根层 37.7 份，工作降到 20.3。母亲九月住哪有 12 帧占 24 份（作者标 high，即 12 份），猫的药量 f22、车道下的水管 f26–f28 也到 24 份；几次升到 24 份都有截止或家人催促，算差一档的分歧，不改。反过来，作者写定为“当帧最高”的 Ture 发烧（f20）只给了 1 份知会，手机首页会把它折进“其余”，打磨时升到 3 份。
2. **随口的约定被时间信号抬高。** Joakim 把“明早 9 点骑不骑”发错到派对群，Agent 因为“今早 9 点就要出发”给了 12 份、排在根层第一，高过同帧邻居说车道湿了一整周（作者：骑车最多一条痕迹）。打磨时降为 3 份。
3. **把接缝当成事实。** 家庭流里他 8/9 早上对 Joakim 说“晚上发 rc1”，工作流里 rc1 在 8/8 23:10 已经发出。Agent 以家里那句为准，把“已发”改回“今晚发”，此后 15 帧挂着“rc1 发布待确认”。同类的小错还有：把“下周六”写成 16 日（应为 15 日），把“诊所回过电话、他没回拨”写成“诊所还没回电”。这几处都改了。
4. **了结之后降得慢，零碎的事并进别的事。** 猫的药量 8/14 答上后又占 12 份三帧；母亲 f28 约下周日吃饭、Ulrika 提的 9 月 30 日生日，都并进已经了结的“住哪”那件；f01 的浇番茄并进了猫；开学同意书在 f22 并进了作者判为噪音的头虱提醒；两条钓鱼短信都单列了提醒（BankID 那条挂了六帧，假关税那条一帧），没有丢弃。这些是措辞与粒度上的分歧，不改；对回应路径的影响见下文（一件事此刻只能登记一个问题，母亲的生日就没有登记）。
5. **生活问答收成一条知会，f21 之后整体暂缓。** 与家里有关的五个提问（猫的药量、航班、漫画、后刹、铜水管）都并进了家里的事；其余问答回复只进那条知会，f21 撤下之后，新提问的回复全部暂缓（空调、地暖找平、斜切锯、修车价、预算表、天花板凸线、车道厚度）。有人在问答站等他澄清的两处（Tilda 问是否只要美国的方案、汤底是甲壳还是贝类）都没有单独成件。不改。
6. **工作里暂缓翻倍，评审请求并成一行。** 工作流他人输入的暂缓从 388 升到 671，多是 Mastodon 回复、评论与评审：它们关联到他的事（所以不是噪音），但不改变他的理解，这正是 SKILL.md 里 `deferred` 的定义，不算漏判。评审请求 f18 起被并成一行（#13530、#12088、#13295、#13350），f22 又把 #13567 和它的修复 #13572 并进来，#13572 批准之后，三个旧 PR 在 f23–f27 一起占 6 份。不改，回应路径登记在这一行上。

此外，提交被退回的 3 次都是字段长度（标题超过 24 字、摘要超过 60 字），回执说明后一次改对，不影响演示数据。

## 回应路径与反馈

- **登记。** edits.json 的 `asks` 按事项与帧登记，按钮从模板来（review → approve，issue → choose，answer → reply，confirm、schedule、defer），也可以直接写；`short` 是 16 字以内的短问法，供腕上一瞥，这次每条都写了。ask 属于登记时的条目版本：条目此后每被改写一次就以同一 id 重登记，直到 `until` 或条目不再 active；改写后没有重登记的，视为问题失效。一件事同一时刻只登记一个问题。
- **反馈从动作推出。** 本人在 GitHub 上的评审、合并（含“closed this in 提交”）、关闭，在论坛、问答站、邮件列表、Mastodon 上的回复，以及家庭流里的消息、通话、表情、Swish 转账，按线程挂到当时已经展示过、引用了同一线程的 active 事项上，`via` 记为 `source`。同一线程被几件事引用时，挂到 Agent 在处置里把这条输入关联到的那件；没有关联的，挂到以这个线程为主的那件。家庭流的杂事线程（浇番茄、收快递、照片）不推导。
- **映射到按钮。** 那件事登记着 ask 时，动作映射到 ask 的按钮（合并算批准，通话对应“打给诊所”）；没有对应按钮或没有 ask 时只指向事项，动作取自 `feedback.sourceActions`。批准某个 PR 的 ask 只认那个 PR 上的动作，也可以用 `answer_threads` 指定哪几个线程能回答它：条目顺带引用了别的线程时，他在那边的回复只记在事项上。家里的多数问题只给选项、不给“回一句”，所以他和 Kajsa 的来回消息只记在事项上，不算回答了问题。
- **11 条被回答的 ask**：水碗尺寸、约兽医、#13473、NDEBUG（他开 #13484）、vdns、航班信息、改签还是照旧、#13528、猫的药量（8/14 打给诊所）、机票退款、#13572。
- **7 条到最后仍开着**：主水管挖开换还是免挖（截止 8/17 10:00）、开学同意书、VAB、三个旧 PR 推到哪天、#13596、派对的 Swish、母亲 23 日来吃饭。

## 旁白、章节与信号

- 每帧的 `title` 与 `narrative` 由打磨时按输入、[家庭流节拍表](../../../corpus/composite/family/BEATS.md)与 Agent 的批次手写，提到 Agent 原判断与打磨改动的地方都直接说明。帧是“此前 12 小时”的窗口：f15 是 8/10 周一上午，f16 是周一下午到夜里。

- 第二轮草图的选用帧写在 `sketchFrames`，说明写在 `sketchNotes`。
- 根层事项的短名写在 `categories.<id>.short`（60 件，手写）：取标题里的事（“猫看病”“主水管”“NTLM 复用”），不用 PR 编号；让位图与批次记谱在色块和记号旁用它。
