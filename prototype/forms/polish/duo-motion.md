# Duo 折叠屏 · 拆开的卡：参考、数据、故事

状态：2026-10-28，第三轮六步流程（reference → data → story → motion → direct → ship）走完，分支 `codex/motion-duo`。前三步加交互表与静态草图先成文（第 1–4 节、第 7 节），四个待定点由用户定下（4.4）后实现。原型探索，不是规范。起点是 [D 手机首页](home-motion.md)（下称 D，现状与交互清单见 [home.md](home.md)）；两层法则与交互标准见 [CONCEPTS.md](../CONCEPTS.md#第三轮概念动画)，交互共用 `motion/ix.mjs`。数字都由 `scenario.mjs` 回放现算，口径与 `variants/d.mjs` 相同（2.1）；推算脚本只留在本机，不入库。

一句话：**铰链是 Agent 与你的分界。** 合上是 D；展开时，每件等你的事沿折痕拆成左右两半：左半写 Agent 为它做了什么，右半写要你答什么。右页就是外屏，合上时留在手里的正是右半。英雄数字从“5 件”翻成“38 份等你回应”。它不是放大的 D：页面的主结构是一条条横跨折痕的条，64 格份额带的分界线就压在折痕上。

### 1.2 系统怎么展开

- **发布会主屏演示**（keynote 57:48–57:51，`duo-anim-apple-keynote-t3468.0…3470.6`，约 2.2 秒，跟手）。外屏内容先轻微发糊（t3468.0–3468.4）。前板绕左侧书脊向左翻开，翻开的那片像一扇半透明的毛玻璃窗（t3468.8–3469.6）。内屏右页是同一个主屏、同样大小、贴着右缘，Dock 竖排在右缘不动，状态栏也不动。左边新出现的区域（“On This Day”小组件）先暗、先糊，到 t3470.6 才清楚。Federighi 的原话是“the screen has become transparent… a window to what is underneath it”。
- **Tech Talk 111464 锁屏**（《Leverage multiple displays and scenes on iPhone Duo》，49.5–51.5 秒展开、53.5–54.5 秒合上，2026-10-29 按 30 fps 逐帧看过；早先截的 `t50.7…54.4` 是其中一段）。镜头从铰链一侧看，两块板对称张开。右半一开始就是清的；左半先黑，壁纸从折痕往外“渗”出来，由糊变清；转到一半时板的自由边迎着镜头、显得更高；跨折痕的时钟最后从右页中心滑到整个跨页的中心（讲者的说法是“wallpaper reacts to the angle of the hinge and applies a zoom effect”）。合上是倒放：暗与糊从外缘扫向折痕。
- **[empirical.health 的逆向](https://www.empirical.health/blog/why-iphone-duo-fold-animation-works/)**。靠铰链处清楚，越往活动边越糊，模糊随离铰链的距离按三次方增长：30° 时自由边约 48 px，到铰链一半处只有 6 px；内屏起初更暗、随开合变亮，活动板靠自由边更暗；两块屏采样同一张虚拟画面平面，所以画面不跳。它把这概括为“content pinned in space”：内容钉在空间里不动，展开只是露出更多；它自己的原型也是细节页留在右边，列表从左边长出来。
- **Apple 没有做“从中线往两边推开”。** 那是 AOSP 的 `UnfoldMoveFromCenterAnimator`：左右两半各从中线外移 8%（`TRANSLATION_PERCENTAGE 0.08`），进度 = 角度 / 165°，弹簧刚度 600，固定时长后备 400 ms，有一层亮光揭开，进度到 0.8 之前屏蔽触摸。

**四条精髓**（2026-10-29 对照上面三处定下，按重要性）：

1. **物理翻页。** 右页（外屏那一页）一像素不动、始终清楚；活动的那一页绕铰链轴真的转，带透视：转到一半时自由边迎面、显得更高更大，然后落平。合上是倒放。全程由铰链角度驱动，手停在半路，画面就停在那一帧。出处：Tech Talk 49.5–51.5 秒；keynote t3468.8–3469.6。
2. **磨砂玻璃。** 活动页上的内容像隔着一块绕一边铰接的毛玻璃看：靠折痕清楚，越往自由边越糊、越暗；角度越开越清、越亮，全开时全清。合上时暗与糊从自由边扫向折痕。模糊是空间渐变（离折痕的距离）× 角度，不是整页一个值。出处：Tech Talk 49.5–51.5 秒与 53.5–54.5 秒；keynote t3468.0–3470.6；empirical.health 的三次方与暗度。
3. **内容钉在空间里。** 展开只是露出更多：内屏右页与外屏同内容、同位置；左页是最终跨页的左页，钉在终点，被活动页逐渐“揭”出来。出处：keynote（“a window to what is underneath it”）；empirical.health。
4. **画面重新取景。** 跨折痕的东西随铰链重新取景：锁屏的时钟从右页中心滑到跨页中心。出处：Tech Talk 49.5–51.5 秒的后段。

**从中读出的节奏。** 一，手里那一半先稳住：原尺寸、原位置，一像素都不动。二，新的一半从折痕往外露出，先暗、先糊，后清；它不是平着擦出来的，是一块板翻过来。三，跨过折痕的东西最后才重排。四，合上是倒放。时长两档：跟手的部分随手走（演示里约 2.2 秒，Tech Talk 约 2 秒）；系统自己补完的部分不超过 0.7 秒。

## 2 数据（data）

### 2.1 规则

| 量 | 怎么算 |
| --- | --- |
| 条的集合与顺序 | 与 D 的 `compose()` 相同：开着的问题按 `urgencyKey` 排序（档位 → 24 小时内到期 → 到期 → 份额倒序 → 名次）；前 3 件是大条，其余在合上时折成“还有 N 件”，展开后成单行条 |
| 左半（Agent 那边） | `item.title`、档位、本轮变化（`itemFacts().change`）、份额、`item.summary`；首条另加 `item.reason`。下面一行事实：本轮进了几条、来自哪条流（`itemFacts().inputs` / `stream`）、两周份额走势（`trend`）；首条再加一条输入样例 |
| 右半（你这边） | 到期（`ask.due_at`，没有就取 `item.due_at`）、“新问题 / 问题已更新”、`ask.prompt`、你在原处做过什么（`feedbackTrail`）、作答控件（`respond.mjs` 的 `responseHTML`），“稍后 / 评论”放在第一行末尾 |
| 英雄数字（份） | `you` = 开着且你还没答的问题的份额之和 |
| 你答过、Agent 还没读到 | `pending` = 这一页已答的问题的份额之和（只在本页模拟，不写回回放） |
| Agent 那边 | `agent = root.used − you − pending`，也就是 D 的“进行中与结果”加次要事项 |
| 空余 | `blank = 64 − root.used` |

## 3 故事（story）

**论点。** 铰链把“轮到谁”画出来。展开时，每件等你的事沿折痕拆成两半：左半是 Agent 为它做了什么（来源、份额走势、为什么升档），右半是要你答什么。两半始终同一行、同一高度。合上时两半合回一张卡，右半就是外屏，留在你手里。答一件，右半原地收成回执；下一轮整理落地，回执过折痕，这件事就到了 Agent 那边。

**英雄数字：“N 份等你回应”。** 与 D 的“N 件等你回应”是同一组问题，换成份额来量。外屏上仍是“5 件”：外屏小，一瞥只需要“几件”。展开以后，左页摆出了 Agent 那边（25 份），64 格份额带的分界线压在折痕上，这时该回答的是“64 份里有多少压在我这边”。于是数字在整理段 0.22 秒那一帧，在同一位置从“5 件”翻成“38 份”；合上时翻回去。两页上的两个数加上空余正好是 64（f26：38 + 25 + 1）。为什么不重复 D 的“件”：件数会骗人。f26 的 5 件里主水管一件就占 24 份；story 的 f05 少了一件，份额却多了 6。

**样张。** 第 1 拍用 composite f26，最满的一页：5 件、三种作答形式。第 2、3 拍用 f22 → 打给诊所 → f23，两周里最大的一次让位（2.3）。story 数据集对应 f04 → f05（2.4）。

### 3.3 第 1 拍：展开（合 → 开）

**连续性。** 右页 = 外屏，一一对应：合上时最后一帧的每张卡，在内屏右页上 x 距右缘不变、y 不变、滚动位置不变，系统条（时间、记录）在右缘不动，只是灵动岛换成了屏下摄像头。所以翻页阶段，你手里的那一半没有任何东西移动。左半是新出来的：它画在翻开的那块板的背面，就在终点，和右半同一行、同一高度，板翻开时被“揭”出来；身份靠位置，而不是靠飞行动画。

**留下的，重排的。**

| 留在原处 | 重排 |
| --- | --- |
| 日期、标题位置（右页上沿）、卡的顺序、滚动位置、作答按钮的竖直位置、回执、系统条 | 卡上 Agent 的几行（标题行、档位、份额、摘要、说明行的前半）搬去左半；右半压紧；“还有 N 件”展开成单行条；“进行中与结果”和次要事项搬到左页；累计栏的话搬到左页页头（它的细纹一起过去） |

**两段。** Apple 的 API 说铰链角度用来驱动效果，布局交给排布变化。这里照做：翻页跟着铰链走，右页的布局在排布变成跨页时一次做完，板接着翻完。

**翻页（跟手，θ = 铰链角度 0 → 180°）。** 视角取发布会那种：你看着外屏，承载外屏的那块板（下称前板）绕它的左缘、也就是折痕，向左、朝你翻开。90° 时板侧立朝你；继续翻到 180° 落平，成为左页。前板的正面是外屏，背面是内屏左页，各自转开时就看不见（`backface-visibility: hidden`）。板下的右页始终是外屏那一页。函数都在 `duo-motion.mjs` 的 `FOLD` 与 `foldAt(θ)`，下表的数由它现算；p、s、v 都截到 0–1，smooth 是 smoothstep。

每个元素只走一段：回执是斜线一段，左半是竖直一段，两者同时到。**问题被改写重登记**（f26 答主水管 → f27）：回执填实后，右半原地展开回问题，标签换成“问题已更新”，回执变成右半里的一行“你 00:00 答过上一版”；不过折痕，因为还轮到你。

### 3.6 两层与约束

- **信息层（约 99%）。** 两页页头、条的两半、单行条、Agent 在办、次要事项、回执。墨黑加朱红；朱红只给能作答的东西（按钮、“新问题”、24 小时内的期限），而它们都在右半。左半没有朱红，因为左半没有要你做的事。
- **概念层（约 1%）。** 64 格份额带（2 px 一格，一页宽）和左页页头那块累计细纹（D 累计栏的细纹搬过来）。份额带的分界线压在折痕上，答一件就有格子变空心，落地时空心格过线：这就是“轮到谁”的全部几何。只用墨和灰，不出数字。
- **克制。** 翻页只换表现、不动信息层：板上画的就是两块屏本来的样子，糊与暗是隔着毛玻璃看它，不另加装饰。屏外是 iPhone Duo 的机身（3.7）：它只是装两块屏的容器，三种姿态与翻页途中都在，但不进信息层，屏里的内容、位置、时间与没有机身时相同，只有屏的圆角换成了机身的。机身的光只随铰链角度变（自由边的亮面与暗面、扫过两面的一道高光），不另加戏剧化的阴影与反光。平放时折痕处只有纸色留白，两半之间 24 pt，落在 HIG 的折叠区里，那里不放可点的东西。画面由数据构成：机身是装它的壳，屏里的东西不靠拟物。
- **为什么装上机身。** 上一版这里写“板只有一圈发丝边……不画金属机身、铰链高光与戏剧化的阴影”。2026-10-29 晚，用户看过翻页后说“折叠屏需要 iPhone Duo 的那个手机壳呀”，接着又说“还原度高一点哈。或者网上有素材的话直接抄一抄。”翻开的那块板没有厚度、没有金属边，就读不出是一台手机在开合。于是这一句改掉：素材的许可不允许拿进仓库（1.2），就照 Apple 的渲染图量出机身自己画（3.7）。“画面由数据构成”留着：机身只装屏，不进信息层。
- **为什么改成 3D 翻页与模糊。** 记录阶段这里写的是“不做 3D 翻页，左半不倾斜不旋转；不模糊；不画机身”，开合做成了平面擦除：左半当一扇窗，左缘从折痕往页边推，只变透明度。2026-10-29 用户看过后说“完全没抓到精髓，核心是那个动画”：iPhone Duo 开合的辨识度就在板真的绕铰链转、内容隔着毛玻璃由糊变清（1.2 的四条精髓），去掉这两样，剩下的只是一次换页。于是这一条改掉，只保留“不拟物”的那一半。
- **绝不动。** 右页在翻页阶段的一切；英雄数字的位置；条的顺序（只表现 `urgencyKey` 的结果）；系统条。
- **一个元素一次一段**，不折返；放大、缩小都并在同一次移动里。
- **不提前。** 下一轮整理之前，左半不变、份额不动、回执不变实、空心格不过线。
- **预算。** 翻页阶段逐帧变化的只有前板的转角（连同它的厚度，`translateZ`）、相机位置、正面一层模糊的遮罩位置与纸雾、背面三层模糊的遮罩位置与暗幕、份额带的缩放，加上机身自由边的亮面与暗面、两面各一道高光，共二十来个 `transform` 与 `opacity`，不重排、不加模糊；机身其余部分是不动的一层，只在姿态或阶段换的时候换一副壳。整理段同时动的元素不超过 12 个。

细则：

- **详情开在左页，不开成全屏。** 这是书本相对 D 的主要收获：读证据和按按钮在同一眼里完成。详情打开时右半仍是这件事的问题。在详情里作答，回执落在右半，详情不关。

- **切换打断。** 换轮、开合、转屏时，详情与概要先立即收起，再照常执行（与 ix 的打断规则相同）。

### 4.4 定下的四点

记录阶段留下四个待定点，2026-10-28 由用户定下（经协调者转达），实现照此：

3. **帐篷姿态这一版不做**，留在记录里（4.1 表），等真机确认帐篷时外屏能不能作答。
4. **角度阈值做常量**：接管 20°、报告跨页 120°（往回折过 110° 退出，留 10° 回差），都待真机量（见 1.1“未证实”）。

## 5 实现与出入

**文件。** [variants/duo.mjs](../../variants/duo.mjs) 编排：三种姿态、铰链、各拍、手势、讲一遍与 `window.foldDuo`；[variants/duo-motion.mjs](../../variants/duo-motion.mjs) 只放几何、阈值与各拍的时间表（第 3 节的数在这里一一对应）；[variants/duo.css](../../variants/duo.css) 是版式；D 的 `d.css` 与 `ix.css` 由 `duo.mjs` 在挂载时以样式链接插入，两张样式表都到了才显示第一帧（不用 `@import`：合页导出把样式链接内联成 data URL，样式表里不许有 `url()`），卡、标签、按钮、回执、行、详情与操作单都是 D 的。D 的视图逻辑（作答记录怎么读、`compose()` 与 `urgencyKey`、卡与行的标记、页头与说明行、详情内容）抽成 [variants/d-view.mjs](../../variants/d-view.mjs)，D 与 E 共用，D 的画面逐像素不变；“一组怎么动”的部件直接用 `d-motion.mjs` 的 `morph / reveal / band / ghostOf / stepAt`。`shared.mjs`、`scenario.mjs`、`engine.mjs`、`respond.mjs` 都没改。壳层 `explore.mjs` 与 `index.html` 只多一项 `duo`（切换栏写 E）。

**浏览器里的铰链。** 按 pt 画整台（外屏 466 × 678、内屏 951 × 669），等比缩进视口。把手在折痕上，拖一页宽是 180°，跟手；松手时不到 90° 落回合上，过 90° 落到书本（半圈 0.36 秒，缓出）。[ ] 每次 15°，F 一键折 / 展，侧栏三个按钮切合上、书本、桌面；`?hinge=h` 定格在 θ = 180° × h（0 合上、0.5 前板侧立、1 全平；2026-10-29 之前它是揭开进度，0 → 1 对应 20° → 120°），`?posture=closed|half|table` 直接进那个姿态。170° 以下算半折：两半之间的留白从 24 pt 加宽到 48 pt（0.2 秒），不重排；拖动或连播中途经过 170° 不改留白，停下来才改。

**开合怎么画**（3.3 的表）。设备容器里一层 `perspective: 2000pt` 的 3D 舞台，前板 `rotateY(−θ)`、轴在折痕。前板上是一张“画”：外屏与内屏左页的副本（去掉键、ID、焦点与一次性标记），在前板升起时拍下；最近一次重画 0.7 秒以后、没有节拍、拖动或铰链在动时，用空闲回调提前拍好，所以翻页的第一帧不用建 DOM。两块屏的内容签名变了（换轮、作答、换姿态）才作废重拍；还没拍好就开始翻时在第一帧现拍，4 倍降速下这一帧约 67–83 毫秒。正面 = 外屏副本 + 一层 10 pt 模糊副本 + 纸雾；背面 = 左页的清楚副本 + 三层模糊副本（2.5 / 7 / 14 pt）+ 暗幕。每层模糊各有一张固定的渐变遮罩，宽两页，靠一对相反的平移挪边的位置，所以逐帧只改 transform 与 opacity。左页副本的右栏换成同高的空盒，每一行的高度与书本一致。前板升起时内屏书本只画右页（`clip-path`），左页就是前板的背面，内屏的左栏点不到；落平（180°）时前板收起，书本照常整页画，与改之前逐像素相同（第 6 节）。半折静止时前板停在那个角度，左页是斜着的那张画：它的清楚那层保留条目的 `data-id`，接收轻点与长按，走同一套委托；左页详情平铺在它上面。两页一起滚时副本跟着平移。从合上翻开时左页从顶上读起（整理段把滚动放在那里）；从书本往回折时，画的是你当时滚到的位置。脚本接口：`foldDuo.state()` 原来的 `windows` 换成 `panel`（前板的转角，收起时为 0）与 `fold`（这一帧正面的不透明度、背面自由边的模糊 pt、显示的模糊副本数、暗幕的不透明度与边的位置、份额带的缩放，与 `foldAt()` 同一组数）；`unfold()` / `fold()` 用手的缓动。

**机身怎么画**（3.7）。`duo-motion.mjs` 的 `bodyHTML()`、`panelBodyHTML()` 与 `pageCutHTML()` 是纯函数，出四副不动的壳、键、前板两面的边框、自由边和右页的下缘；`duo.mjs` 挂载时插入一次。不动的那层 `.u-body` 垫在屏下面，四副壳各是一个合成层、只画一次，显示哪一副由 `data-body` 定、靠 opacity 换，前板升起或落下时换壳不重画；哪一副壳用 `data-shell` 标，不用类名，因为页面会把整个宿主里的 `is-open` 一并清掉（打开详情时）。转屏时只把离开的那副壳复制出来，随旧排布一起淡出。前板两面各是“边框 + 屏的副本”（副本的容器从 `.u-face` 挪进 `.u-glass`，圆角跟机身的屏），自由边是带与小平面，两面的高光只是一条 226 pt 宽、斜 14° 的带，平移着扫过去。逐帧多改的只有自由边亮面、暗面两层的 opacity 与两道高光的 opacity、transform（`bodyAt(θ)`），不加模糊、不重排。外屏在翻页途中当右页时比内屏右页高 9 pt：一层盖板（`.u-pagecut`）按外屏的形状裁，在内屏右页的轮廓外画上与机身同色的黑边与屏框，只淡入淡出，所以 120° 换成内屏时右页的下缘不跳，也不改任何裁切。前板收起时不再 `visibility: hidden`，而是透明（不加 `will-change`，合成器不画它，模糊也不算）：它一直画好着，翻开的第一帧不用现画边框与副本；收起时它接不到点按（只有升起、静止的前板接）。整台按 pt 等比缩进视口时，把机身伸出的部分（键、左半、落影，`BODY_PAD`）也算进去，所以 1440 × 900 下屏比 #42 小 3.6%（内屏 1046 → 1009 px 宽）。屏上浮着的详情、操作单与回执过折痕的那层（`.u-clip`）按屏的圆角裁。脚本接口：`foldDuo.state()` 加了 `body`，`shell` 是哪副壳，`light` 是前板升起时自由边的亮面、暗面与两道高光（收起时为 null）；原有字段一个不少。

**讲一遍。** 顶层直接打开、地址里没有 `frame` / `posture` / `hinge`、没有 referrer 时演一遍，约 11 秒：合上 0.9 秒 → 跟手展开 1.5 秒（加整理 0.40 秒；“跟手”用最小加加速度缓动，起落都软、侧立时最快）→ 停 1.6 秒 → 答一件 → 2.0 秒后下一轮落地 → 2.8 秒后合上 1.1 秒。composite 是 f22 答 Smilla“打给诊所”、落到 f23（与 D、A 同一个样本）；story 是 f04 答导出模板“固定模板”、落到 f05。任意键或点按跳到结尾（合上、下一轮、已答）；侧栏“重演”从头演。嵌在合页或体验站的弹框里、从别处链进来、带 `frame` / `posture` / `hinge` 打开都不演；不带帧号时停在 composite f26、story f04（四件等你、其中一件是单行条；f14 只剩一件）。减少动态时不演，折、展、作答都直接到终态。

**性能上的三处改动**：翻页逐帧只改 transform 与 opacity，前板的画在空闲时提前拍好（上文）；每一拍只重画看得见的那一层（书本时不重画外屏，合上时不重画书本，等它下次出现时补上）；一拍里所有的位置先一起量、再一起写（列表的位置、回执的起点和终点、详情的起点），不在写过 DOM 之后再读布局。改之前落地的第一帧在 2 倍像素下要 167 毫秒，之后约 33–50 毫秒（掉一帧）。

**还差什么。**

- 尺寸按 @3x 推算，20° / 120° 是常量，都待真机量；浏览器里的铰链是模拟的，真机上的手感、阻尼和系统转屏的时机都没有验证。
- 帐篷姿态没做（4.4）。
- 外屏页头没有 D 的稍后提醒计数与“我的回应记录”，被稍后的事在 E 里看不到，要切到 D 看。
- 桌面姿态的换轮只用通用的移位与进出场，没有“回执过分界”那一笔；桌面姿态里没有长按色带格。
- 外屏比内屏右页窄 9.5 pt，整理段里右半有 9.5 pt 的横向移动，第 3.3 节说的“x 距右缘不变”只近似成立。
- 视角取发布会的（看着外屏，前板翻开），没有做 Tech Talk 那种从铰链一侧看、两块板对称张开的镜头：浏览器里只有一个正对屏幕的视口，正对时右页不动才读得出“钉住”。
- 糊与暗的曲线、相机位置都是照视频估的：自由边最大模糊按 empirical.health 的 48 px @3x 取 16 pt，暗幕的深浅与时机是目测。透视取 2000 pt 而不是 1200–1600：1500 时 100–110° 的板上下伸出视口太多。
- 前板是两块屏的一张画，不是活的页面：翻页途中点不到左页；数据在翻页途中换轮时当帧重拍。半折静止时左页详情平铺在斜着的前板上，没有跟着倾斜。
- 英雄数字没有做跨页重新取景（上表）。
- 机身只照正面渲染图量：侧面、背面与相机凸台没画，正对屏幕的镜头里也看不到；合上时没有 Tech Talk 那种从侧面看的两块板。金属的光是一盏固定的灯算出来的，不随环境变。
- 内屏圆角取 36，不是量到的 54（3.7）：系统条不动，54 会切掉时间。
- 机身的键、缺口与天线断点是照渲染图的位置画的，没有对过真机；键不能按。
