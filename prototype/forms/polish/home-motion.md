# D 手机首页 · 动画记录

状态：已实现（2026-10-20）。2026-10-19 把第三轮概念动画的六步流程（reference → data → story → motion → direct → ship）推到 [D 手机首页](../../index.html?variant=d&frame=26)，先写前三步：参考、数据、故事；2026-10-20 评审后做完第 4–6 步，实现的取舍、与故事的出入、定格与性能见第 4–6 节。原型探索，不是规范。现状与交互清单见 [home.md](home.md)，范本是份额拨盘（[spec](../motion/dial/spec.md)、[data](../motion/dial/data.json)、[story](../motion/dial/story.md)）与整理脉冲（[spec](../motion/pulse/spec.md)、[data](../motion/pulse/data.json)、[story](../motion/pulse/story.md)），两层法则见 [CONCEPTS.md](../CONCEPTS.md) 第三轮。数字都由 `scenario.mjs` 回放现算，规则见 2.1；推算脚本只留在本机，不入库。

D 与两个概念动画有三处根本不同，故事都要正面回答：它是真正作答的地方（其他形式的“去回答 →”都链到它），动画服务作答而不是展示；手机没有悬停；它是阅读工具，“丝滑”要来自元素在换轮、作答、展开之间位置连续，而不是粒子。

## 1 参考（reference）

### 1.1 D 现在怎么变

读 [d.mjs](../../variants/d.mjs)、[d.css](../../variants/d.css) 与 [respond.mjs](../../respond.mjs) 所见。D 不是硬切：每次重绘按 `data-key` 只换变了的叶子，再用 FLIP 让同一件事从旧位置走到新位置（320 ms，`cubic-bezier(.2,.75,.25,1)`）。断在别处：

| 时刻 | 现在怎么动 | 断在哪 |
| --- | --- | --- |
| 换轮（‹ ›、轨道、空格每 5.6 秒） | 先量位再补丁，然后同时起跑：留下的平移 320 ms；同一件事换脸（行 ↔ 卡、卡 ↔ 回执）时旧面做成幽灵层，旧字 128 ms 淡出、盒子 320 ms 收到新高、新字过了 35% 才出现；新来的用 `clip-path` 揭开 360 ms，从折叠行出来的错开 24 ms；离开的上收淡出或收进折叠行；头部数字滚一格 260 ms，说明行与累计栏从 0.25 淡入 260 ms；状态栏时间、侧栏标题与旁白硬切 | 一切挤在 0–0.36 秒里一起动，没有先后。f25 → f26 首页 8 个元素全部在变、另有 2 个离开（两周最多，见 2.5），眼睛不知道先看哪；数字与卡片同一刻变，看不出“因为什么少了一件” |
| 作答（approve、choose 一键，confirm 两键） | 卡换成回执（同上的幽灵层变形），下一张升首卡（题干 17.5 → 21 px、多两行摘要），折叠里一件补上来，数字滚一格，顶部再弹 2.2 秒 toast“已保存 · …”，焦点到“撤回” | 同一刻四件事：回执收起、首卡变大、补位、数字。toast 把视线拉到屏幕顶，离开手指。下面的卡上移到手指下面，连点会落到下一张卡的按钮上 |
| 下一轮整理之后 | 本页回执按条目 `id` 与 `updated_at` 存（`createResponseStore`），Agent 一改写这件事就取不到 | 你按下的东西在下一个节拍里没有落点：f22 答“打给诊所”，f23 猫看病改写成进行中的一行，回执凭空消失；f26 答主水管，f27 改写重登记，数字从 4 回到 5，像答了白答（见 2.4） |
| 详情 | 从右侧平移 36 px 淡入 280 ms；收回向右 220 ms | 与被点的卡没有几何联系：卡在屏幕中间，详情从右边来，收回也不回到卡上，等于换了一个场景；与拨盘、脉冲“沿自己的几何弹出”不是同一标准 |
| 选项层（schedule、defer、稍后、折叠里的问题） | 从底部上滑 300 ms，背景淡入 240 ms；换轮时立即收起 | 基本成立；有把手却不能下拉关闭 |
| 稍后 | 卡缩到 0.2 倍飞向头部“◷ N 件”，480 ms | 成立：D 里唯一把“从哪到哪”画清楚的退场 |
| 左滑已阅（进行中与结果的行） | 跟手平移淡出，过 80 px 松手即已阅，否则 200 ms 回弹 | 只用指针事件模拟过，没在真机试（home.md 已记） |
| 新登记的问题 | 卡外圈朱红细描一次，1.6 秒、延迟 0.25 秒，每帧每件只一次 | 成立；但它和揭开、平移同时开始，被淹掉 |
| 自动播放（原型的回放） | 每 5.6 秒一轮，作答不暂停 | 刚按下的回执可能下一秒就被换轮冲走 |

### 1.2 拨盘与脉冲：搬什么，不搬什么

| 要素 | 拨盘 / 脉冲 | D |
| --- | --- | --- |
| 离散量一帧硬切，连续量 ease-out | 计数在切点翻牌；扇区、枝条 ease-out | 搬。时间、说明行、累计栏、标签上的“N 份”硬切；位置与大小 ease-out。英雄数字差 1 时滚一格（作答、撤回都差 1，滚动本身就在说“少了一件”），差 2 以上一帧硬翻 |
| 过冲约 3.7% | 扇区落定、游标、弹出 | 只给被按的那张卡外扩 8 px；列表重排一律临界阻尼、不过冲，阅读中的行回弹会像抖 |
| 切点后 0.4 秒才有第一个焦点 | 每轮都一样 | 只搬到“回来”与“下一轮整理”：先 0.4 秒只换字、只确认回执，再动列表。手指触发的动作不等，按下的那一帧就要有反馈 |
| 展开三段 0–0.3 / 0.4–0.6 / 0.6–0.9 秒，收回 0.2 / 0.15 / 0.2 秒 | 弹出 8 px → 引线 → 详情卡 | 搬顺序与“收回逆序、比展开快”。引线换成卡框自己长到全屏，屏幕上没有放引线的地方；时长见 3.7 与待定问题 2 |
| 悬停：其余降到七成，概念层降到四成；0.15 秒宽限、0.12 秒淡出 | 鼠标；触屏上“轻点一下就是悬停” | 搬到长按。D 不能用“轻点即悬停”：它的轻点必须直接起作用（作答或展开） |
| 节拍守恒：卡上的数不提前说后面节拍的事 | 弧没到根之前写“本轮的输入还在路上” | 搬成“保存不等于收到”：下一轮整理落地之前，页面不说份额已经让出，回执写“等 Agent 下一轮整理，状态还没变” |
| 概念层约八成，可以一直动 | 粒子、余辉、字形碎片 | 不搬。D 是阅读工具，静止是默认；概念层只留累计栏左侧那块细纹，约占屏幕 1%，每轮整理只动一次（3.6） |
| 4 秒节拍器、首尾循环 | 官网首屏 | 不搬。D 只在三种时刻动：一轮整理落地；你作答、撤回或稍后；你展开或收起 |
| 一个圆心、一套刻度 | 极坐标、64 条射线 | 搬成“一个盒子”：同一件事的行、卡、回执、详情是同一个盒子变形，不换盒子 |

### 1.3 两个手机端参照

凭使用记忆描述，没有逐帧量过；时长只作量级。

- **iOS「提醒事项」勾掉一条。** 点左边的圆圈，圆圈先填满，这一行原地停一会儿（一两秒；这段时间再点就撤销），然后收起高度、下面的行上移补位；开着“显示已完成”时它不消失，落到已完成的那一段。可取三点：按下的东西先在原地确认，不立刻离场；离场与补位是同一个动作，不先空出一个洞再合上；撤销窗口就是那段停留。D 的回执原地收起已接近第一点，缺的是“落到已完成那一段”，对 D 就是下一轮整理时沉到“进行中与结果”。
- **App Store「Today」卡片。** 轻点一张卡，卡从它在列表里的位置原地长成整屏文章，圆角、配图、标题跟着长大，其余卡片退后变暗；在文章顶部往下拖，文章跟手缩回成卡、落回原位，拖得不够远就弹回全屏。可取的：展开是“卡自己长成详情”，没有第二个元素从屏幕外进来；收回回到原位；手势跟手、可以中途反悔。D 的详情从右边滑进来，缺的正是这一点。

### 1.4 Safari iOS 的约束

- **帧率。** 默认约 60 Hz（ProMotion 机型上网页也不跑 120 Hz，这是 WebKit 默认打开的一个开关，第 4 步在真机上核对），每帧 16.7 ms。只动 `transform` 与 `opacity`；`clip-path`、`height`、`box-shadow` 的动画在 WebKit 里不保证走合成线程，D 现在的揭开与幽灵层变形正用 `clip-path`，第 4 步先用 Web Inspector 的时间线在真机上量，掉帧就改成父层 `overflow: hidden` 加子层平移的揭开。阴影不做动画，预先画在伪元素上只改不透明度；变暗层不用 `backdrop-filter`。
- **没有滚动锚定。** Safari 不支持 `overflow-anchor`：视口以上的元素变高变矮，正在读的内容会跳。真机宽度下 D 是整页滚动，补位时按量到的位移自己补 `scrollTop`。
- **左缘右滑是后退。** 从左边缘起的右滑交给浏览历史；从拨盘或脉冲的“去回答 →”进来时一滑就退回上一页，本页回应只在内存里，全丢。详情打开时 `history.pushState`，让这一滑等于“收回详情”；这一滑 Safari 自己画返回动画，本页直接到终态，免得演两遍。右边缘起的左滑在有前进记录时是前进，行上的左滑要从行内起手；整页不绑任何右滑。
- **下拉刷新。** 页面在顶部继续下拉是 Safari 的回弹，较新的系统里还会刷新页面，同样丢掉本页回应。首页顶部不绑下拉；真机宽度下本页回应用 `createResponseStore` 已有的 `persistKey` 存起来。
- **长按。** 默认会选字、弹放大镜或链接预览；卡与行上设 `-webkit-touch-callout: none` 与 `user-select: none`，自己计时。网页拿不到触感（Safari 不支持 Vibration API），长按成立只能靠画面。
- **工具栏伸缩。** 地址栏随滚动收起会改变视口高度；吸附在底部的累计栏按 `dvh` 定位，否则补位动画中途跳一下。
- **减少动态。** `prefers-reduced-motion` 时一切直接到终态（D 已经这样做）。

## 2 数据（data）

### 2.1 规则

| 量 | 怎么算 | 出处 |
| --- | --- | --- |
| waiting：英雄数字 N | 根层条目里 `currentAsk(s, id)` 不为空的件数，不含本页回应 | `variants/shared.mjs` `currentAsk`；`d.mjs` `compose().waiting` |
| 三张大卡、还有 N 件 | 上面这些问题按 `urgencyKey`（档位 → 24 小时内到期 → 截止 → 份额 → 排名）排序，取前 3 张，其余折成“还有 N 件” | `d.mjs` `urgencyKey`、`compose()` |
| 期限 | `ask.due_at`，没有则取条目 `due_at`（done 除外）；“还有 N 小时”按本帧时刻算 | `d.mjs` `dueOf`、`dueWords` |
| 份额、留白 | `records[i].state.root.items[].share`；留白 = 64 − `root.used` | `engine.mjs` `replayScenario` |
| 说明行 | 比较起点 = 上一帧；收到 = 区间内 `frame.events.length` 之和；新问题 = `ask.registered_at` 晚于起点；变化 = `diffStates(起点, 此刻).changes` 去掉 `annotations_changed`；原处处理 = 本人事件 `feedback[].target` 去重 | `d.mjs` `sinceHTML` |
| 真实作答 | `event.feedback[]` 带 `ask` 指向这个问题；答掉 = 之后某帧这件事的 `currentAsk` 不再是它；关上时没有反馈指向它就是失效 | 同 [拨盘 data.json](../motion/dial/data.json) 的 `rules.openAsks` |
| 让位 | 相邻两帧根层 `share` 之差；回执不记“谁让给谁”，只能并排同一轮的增减 | 同拨盘 `rules.yield` |
| 重排 | 首页带 `data-key` 的叶子（折叠收起时）按 `render()` 的顺序；数“动了的元素”：进、出、换序（留下的相对次序变了）、换脸（首卡 ↔ 大卡 ↔ 回执 ↔ 行，折叠行与表头的计数），一个元素只数一次 | `d.mjs` `render()`、`patch()` |
| 本页回执 | 按条目 `id` 与 `updated_at` 存；下一帧版本变了就取不到 | `respond.mjs` `createResponseStore` |

### 3.6 两层与约束

- **信息层（约 99%）。** 英雄数字、说明行、大卡、折叠行、进行中与结果、次要事项、累计栏的字、回执。墨黑加朱红；朱红只给能作答的（按钮、“新问题”、“还有 N 件”前的圆点、24 小时内的期限），动画里朱红只描一次新问题；回执是墨色，失效是灰色。
- **概念层（约 1%）。** 只有累计栏左侧 54 × 48 px 的细纹。每轮整理落地的 0–0.40 秒向下收拢一次，收拢的纹距随本轮条数按对数取 1–3 个（54 条为 1、234 条为 3）；没有输入的轮（story 的 f17、f27 两次 review）不动。只用灰，不出数字。它说的是“又有这么多被折进来了”，与脉冲的弧、拨盘的车道是同一件事，只占一角。
- **绝不动。** 英雄数字的位置与字号；状态栏；累计栏的位置；卡片排序规则。动画只表现 `urgencyKey` 排出的结果，不发明顺序。
- **每个元素一次只走一段。** 一次节拍里每个元素从旧位置到新位置只有一段运动，不先上后下、不折返；升首卡的放大并在同一次移动里。
- **先后。** 切点换字 → 你做过的先确认（回执）→ 英雄数字 → 离场 → 主角（你答的、失效的）→ 移位 → 进场 → 新问题描边。
- **不提前。** 下一轮整理落地之前，不动份额、回执不变实、答过的卡不离开大卡区。
- **预算。** 一次节拍同时动的元素不超过 10 个（两周的最大值），只动 `transform` 与 `opacity`，幽灵层同时不超过 3 个。

### 3.7 与 ix.mjs 共用什么，手机专属什么

`ix.mjs` 正由另一处从拨盘与脉冲抽出，接口以它为准；D 需要它提供下面这些，并能换掉“弹出方向”和“连接”两块几何。

| 共用 | 内容 |

1. **样张用哪一帧。** 默认链接与拨盘落点都是 f26，但 f26 → f27 主水管被改写重登记，没有让位；f22 → f23 有真实作答、两周最大的让位。建议默认链接仍是 f26，第 6 步的定格对照用 f22 → f23；也可以把 D 的默认帧改成 f22。

## 4 动（motion）

### 4.1 评审定下的

2026-10-20 评审对 3.8 与第 3 节的答复，实现照此：

1. 默认帧仍是 f26；定格对照用 f22 → f23。
2. 手机一组时长：展开 0.48 秒、收回 0.40 秒，三段顺序与桌面同一套。
3. 累计栏加 2 px 高的 64 格细带，整理落地时各段一次缩放；不再加别的份额编码。
4. 回执跟着条目走，不随版本消失。要修的两处：f22 作答 → f23 回执消失；f26 答主水管 → f27 数字 4 → 5 反弹。
5. 换轮重排改成离场 → 移位 → 进场依次走，不再 0.36 秒一齐动；详情改成从点中的卡长出来，不从右边滑入。
6. D 本身就是作答处，不加“去回答”；别的形式用 `?variant=d&frame=` 链进来时落在那一帧，不自动演开场。
7. 能共用的用 `ix.mjs`（概要卡、详情两节、`IX` 时序、键盘）；长按、左滑、跟手收回这些手机专属的写在 D 自己的代码里。钩子 `window.foldHome` 与 `foldDial` 同名同义。
8. Safari iOS 性能：只在合成线程上动 `transform` 与 `opacity`，不来回读写布局，`clip-path` 动画换成等价的 transform。用无头 Chrome 的手机模拟（iPhone 尺寸、触屏事件、CPU 4 倍降速）量 60 fps；真机 Safari 由用户看。
9. 作答只存在内存里。Safari 的左缘后退与下拉刷新会丢掉它们，首页不绑这两种手势即可；不做持久化（契约未接纳），1.4 里“用 `persistKey` 存起来”作废。

### 4.4 取舍

- **只动 transform 与 opacity。** 圆角盒子变高变矮用三块拼：上盖与下盖只平移，中段只缩放，圆角不被拉扁；需要换外观（卡白 → 纸色、圆角 20 → 0）时两套盒子同步变形、交叉淡化。揭开不用 `clip-path`，改成一块纸色盖板向下沿 `scaleY` 收走。部件缩放的 `transform-origin` 写在元素样式上，不写进关键帧（写进关键帧会让这条动画留在主线程）。
- **只在切点读布局。** 一次节拍在重绘前量一次、重绘后量一次（各件与部件的位置、列表、细带宽度、“◷”的位置一起读），之后只写；每个叶子预先定位，z 序不用再读样式。Chrome 时间线里切点之后的整段动画没有一次样式重算或布局。
- **旧脸跟着条目，不放全局幽灵层。** 换脸时旧内容留在它所在列表的末尾、与条目同一层级，越过它的卡在上层时，旧字也被盖住；放在全局层，旧字会浮在一切之上（第一版就是这样：f23 落地时，待审 PR 的旧题干浮在正越过它下沉的母亲那张上面）。代价是 3.6 的“幽灵层同时不超过 3 个”没有守住：f22 → f23 同时有 6 个旧脸节点；它们只动不透明度与平移，4 倍降速下仍是 60 fps（6.1）。
- **主角是“端着走”，不是“扔下去”。** 主角的下沉改用缓入缓出，其余仍是不过冲的缓出：照缓出走，回执 0.1 秒就走完一半，0.48 秒才起步的补位前会空出一大片纸。两个主角同时下沉时先起步的在上层，回执在最上。
- **字号变了、行数也变了的题干不硬缩放。** 升首卡时题干 17.5 → 21 px；行数不变时照 3.2 纯缩放，不重排字；21 px 下多折一行时（f22 作答后母亲那张从两行变三行），缩放后的块与旧块对不上，会压到下一行，于是旧行骑到新位置、前 45 % 淡出，新行从旧尺寸放大、30 % 起淡入，仍在同一次移动里。题干换了字时只平移、交叉淡化，不缩放。
- **回执按问题 id 认。** 同一个问题重登记（f26 → f27 主水管，两轮都是 ask-23）仍是回执，不算“等你回应”，数字停在 4；问题关上后回执留成那一行下面的小字（“✓ 你选了「打给诊所」· 已收到”，措辞按当时的问题）；问题被改写成另一个问题时，卡上写“你答过上一版”。上一轮开着、这一轮关上、没有任何回应指向它的问题，那一行下面写灰字“这个问题随改写失效”（f23 母亲那行）。
- **回执填实**：空心勾上叠一颗实心勾放大淡入（0–0.30），小字在切点就换成“已收到 · Agent 在 12:00 的整理中读到”，之后不再交叉淡化。
- **详情从卡长出。** 卡样与纸样两个盒子始终同一矩形，卡样在上、后半段淡成纸，框在任何时刻都不透明；题干与详情标题同字时才当锚点移到顶部，否则只淡入。收回时卡上原字整段淡回，题干不飞回。非嵌入页打开详情时 `pushState`，Safari 左缘右滑就是收回（本页直接到终态，不再演一遍）；界面上收回时 `history.back()`，并把地址还原成收回后的那一个。嵌入（合页、单文件导出）不动历史。
- **长按。** 移动超过 10 px 或开始滚动即取消；长按大卡等于轻点（大卡就是概要）；长按累计栏出本轮概要（本轮输入的采用、重复、噪音，空余份额）。长按松手后同一次触摸可能补发的点按吞掉（150 ms 内），不会落到概要卡上。
- **左滑。** 行只跟手平移，不再边走边变淡；“✓ 知道了”在行的右沿原地露出，灰色，过 80 px 变墨色。从屏幕右缘 16 px 内起手的不接（那是 Safari 的前进）。
- **手指保护**只拦点按（`click` 的 `detail > 0`），键盘照常；保护区是上一次按下点周围 32 px，自己的回执（撤回）不拦。
- **滚动锚定自己做。** 重绘前记下视口顶端第一件（或刚操作的那件）的位置，重绘后补 `scrollTop`；Chrome 自己的 `overflow-anchor` 关掉，与 Safari 一致。
- **键盘。** Tab 到行出概要（与悬停同义）；Enter 或空格打开详情（卡与行上的空格归它们，不是播放，与 ix 一致）；Esc 依次收回选项层、比较起点菜单、概要、详情。重绘或收回后焦点回到原处时不再弹概要。
- **链入落地即终态**，只有新问题描一次朱红（3.2）。“去回答 →”带条目 id、落地描墨框（3.7 末尾）按评审 6 不做。
- **连播。** 长按、Tab 概要与详情会停住回放，都收起 0.4 秒后接着播（ix 的 `resume`；3.7 表里写的“不用”改为照 ix）；作答会停住回放且不自动接着播，免得刚按的那件被下一轮卷走。
