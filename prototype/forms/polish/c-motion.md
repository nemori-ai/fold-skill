# C 流动形态 · 动画记录

状态：2026-10-20。把第三轮概念动画的六步流程（reference → data → story → motion → direct → ship）推到 [C 流动形态](../../index.html?variant=c&frame=25)：先写参考、数据与故事（第 1–3 节），交互的标准写在第 4 节，故事定下之后才改代码；实现、与故事的出入、定格与验证见第 5–6 节。原型探索，不是规范。C 打磨时的做法与交互清单见 [temporal.md](temporal.md#c--流动形态)，范本是[整理脉冲](../motion/pulse/story.md)（一粒一条）、[份额拨盘](../motion/dial/story.md)（一涨一缩同时落定）与 [D 手机首页](home-motion.md)（答一件少一件、回执跟着条目走），两层法则见 [CONCEPTS.md](../CONCEPTS.md#第三轮概念动画)。数字都由 `scenario.mjs` 回放现算，规则见 2.1；推算脚本只留在本机，不入库。

C 和其他阅读工具的问题是反的：别的形式本来是静图，要想办法让它在节拍上动；C 一直在动（液滴有弹簧、会回弹、会拉长），但动的东西没有节拍，也没和信息层的数量对上。这一轮要做的是让液滴场守信息层的账。

### 1.2 从脉冲、拨盘、D 搬什么，不搬什么

| 要素 | 出处 | 搬过来 | 不搬 |
| --- | --- | --- | --- |
| 一粒一条 | 脉冲：云里一颗亮粒子就是一条输入，去向与面板分类一一对应 | 每轮采用的输入一条一粒从水面上方落下，落进它所属的那一滴或那颗小珠；暂缓的是水底的泥，粒数 = 暂缓条数，不飞；噪音、重复与未判不画（初版每条都画，用户看后嫌多，见第 6 节） | 尘埃、辉光、余辉、收拢弧；脉冲那样每条都画 |
| 节拍 | 脉冲：涌入 → 折叠 → 一问，拍外静止 | 涌入 → 长缩 → 沉浮 → 数字落定，四段依次走，每段只做一类事 | 4.25 秒的固定节拍器与首尾循环：C 是阅读工具，不自己连播 |
| 一涨一缩 | 拨盘：同一轮里一涨一缩同时落定，不画成谁推谁 | 长缩拍里所有份额走同一条缓动、同起同落，任何时刻各滴份额加留白都是 64；只有明确的 `merged_into` 画成一滴流进另一滴 | 拨盘扇区的 3.7% 过冲：体积过冲就是多出来的份额 |
| 数字只在节拍上翻 | 拨盘：计数在切点翻牌；脉冲：卡上不提前说后面节拍的事 | 滴里的份数、标签、朱红环、64 格带、标题行与阅读区都在“数字落定”那一刻一帧硬切；悬停停在轮中途时，卡上写“本轮的份额还没落定” | — |
| 答一件，少一件 | D：卡原地收成回执，数字减一；下一轮整理先确认回执，再带着让出的份额沉下去 | 回应控件原地收成回执，“N 件等你回应”当场减一；液滴不动，等下一轮整理读到了才沉进托盘（推后），回执在那一轮的切点填实 | D 的列表编排（离场 → 移位 → 进场） |
| 回执跟着条目走 | D：回执按问题 id 认，条目改写后仍在 | 本页记录本来就按条目 id 取（`latestRecord`），条目改写后液滴旁仍写“✓ 你推到 8/16 09:00 · 已收到” | — |
| 交互 | 拨盘、脉冲、回应时序：悬停概要卡、点击弹出 8 px + 引线 + 详情卡，共用 `motion/ix.mjs` | 同一个模块；弹出沿“容器中心 → 液滴中心”这条线向外推 8 px，体积不变；引线沿同一条线出去再连到卡 | 详情里的“去回答 →”：C 自己能作答，换成“在右栏作答” |
| 讲一遍 | 回应时序、让位图、腕上一瞥：只在顶层直接打开时演一次，任意键跳过，有“重演” | 同一条规则 | — |

### 1.3 概念层占比：三到四成，静止时为零

拨盘与脉冲的概念层约占八成，因为官网首屏要先让人感到量；让位图、回应时序是复盘工具，概念层不到一成。C 在两者之间：它本来就是用液体讲份额的形式，液滴的凝胶质感、落下的粒子、水底的泥就是它的画法，所以概念层可以占三到四成。但它仍是阅读工具，会被停在任何一轮仔细看，所以两条规矩比拨盘严：

- 概念层的每一样东西都是信息层某个数的样子：粒子数 = 本轮采用的条数，泥的粒数 = 本轮暂缓条数，液滴面积 = 份额，过水面 = 3 份阈值或推后。没有纯装饰的粒子。
- 落定之后零运动：不呼吸、不漂、不闪。泥停在水底，液滴停在原处，直到下一次换轮、作答或交互。

## 3 故事（story）

**论点。** 能等的事沉下去，不是丢掉：它在水底留着一份，到该看它的那一轮整理，带着新消息浮上来。64 份是同一池水：它沉下去时让出的，同一轮别处接住；它浮上来要的，同一轮别处让出。

**英雄数字：9（轮）。** 英雄事项在水下待了几轮整理。规则：根层沉下又浮起的事项里，浮起时份额涨得最多的；一样多取沉得最久的。composite 选出猫看病（+5，9 轮；主水管、master CI、FTPS 计时同为 +5，沉得更短），story 选出费用（+11，13 轮）。帧号由规则现算，不写成常量。

- 它是一只按轮数的钟，单位用“轮”：一轮就是一次整理，Agent 每一轮都重新看了它一眼、让它继续留在水底。composite 每轮正好 12 小时，9 轮就是 108 小时；story 不定时，只写轮。
- 第 1 拍它沉到水底的那一刻出现在它的小珠旁，写“在水下 1 轮”，字高约为水底那一条的三分之一，全场只有它这么大。
- 每一轮的切点硬切加一，不滚动：数字只在节拍上动。
- 第 3 拍它浮起时数字停在 9，标签换成“沉了 9 轮 · 1 → 6 份”，随它浮出水面后淡去。
- 讲完之后的日常阅读里，它变成卡与面板上的一行：悬停一颗小珠写“在水下第 N 轮”，浮起过的液滴写“沉过 9 轮，f15 浮起”。

### 3.3 两层

- **信息层（约六成，少、准、有出处）：** 液滴的大小与位置（份额）、滴里的份数、问题的标签与朱红环、小珠、托盘与“◷ 09:00”、64 格带、水底与托盘的说明、标题行、信号行、阅读区。墨黑、各类别的颜色与一个朱红；只在“数字落定”与作答时变。
- **概念层（三到四成，只用灰）：** 液滴的凝胶质感（透光、焦散、接触阴影、移动时沿速度方向微微拉长）、落下的粒子、水底的泥。粒子与泥是墨色的低透明度圆点，不出文字、数字，不用朱红；粒子比泥还轻（半径约 1 px、不透明度约三成）。
- **共用几何与数量：** 两层用同一个容器：同一条水面、同一个水底、同一套面积比例（水面以上 1，水面以下九分之一）。粒子落进的就是信息层上那一滴；粒子数 = 本轮采用的条数（落进这一层的；详情卡“本轮进了它 N 条”就是落进它的粒数），泥的粒数 = 概览里的“暂缓 N”；液滴面积 = 64 格带里它的格数。
- **不打架：** 粒子画在液滴下面，落进液滴就被它挡住；泥在小珠与托盘下面；悬停与展开时概念层降到四成，其余液滴降到七成（压暗在着色器与 Canvas 退路里用同一个公式）。

### 3.4 动起来之前的约束

- **绝不动：** 水面的位置、64 格带的位置与格数、颜色的含义（颜色 = 根层事项的类别；朱红只给登记的问题与它的期限）。
- **体积守恒：** 长缩拍里不过冲；同一份额在任何一轮都一样大（整层的比例按这一层两周里最挤的一轮定，不再逐帧换档）。
- **每个元素一轮只走一段：** 一滴在长缩拍只长或缩一次，在沉浮拍只过一次水面。
- **不提前：** 下一轮整理读到之前，推后的不沉；“数字落定”之前，份数、标签、朱红环与格带不变。
- **泥不浮起：** 1117 条暂缓没有一条后来被引用，所以泥只表示这一轮的暂缓条数，下一轮在长缩段里原地换成那一轮的条数，不积累，不飞，也不画成会回来。
- **静止时零运动。**
- **只读同一份回放：** frames、批次、asks、feedback，不加只为动画服务的字段，也不改契约；本页作答只在浏览器内存里，不改写回放。

## 4 交互

与份额拨盘、整理脉冲、回应时序同一套标准，时序取 `motion/ix.mjs` 的 `IX`，卡片是同一套概要卡与详情卡（换成 C 的纸色与字体）。这里只写 C 的几何。

- **悬停**
  - 触发：鼠标移到液滴（命中区放宽到液滴外 12 px）、它的标签、水底的小珠（外 8 px）、托盘里的事或 64 格带里它的格子；Tab 到它（每件一个隐藏按钮，顺序按 rank）；触屏轻点一下。
  - 动什么：液滴场的钟停在当前时刻（轮中途也停），播放停住；这一滴保持原样并微微从里面亮起，其余液滴与小珠降到七成，粒子与泥降到四成；概要卡贴在液滴朝外的一侧，一根细引线从液滴边上连到卡。卡上写来自哪条流、几份、本轮怎么变、本轮进了几条输入、开着的问题与期限，C 另加一行位置：“在水面上”“在水下第 4 轮”“推到 8/16 09:00 · 已收到”。
  - 节拍：停在轮中途时，粒子没落完写“本轮的输入还在路上”，数字落定前写“本轮的份额还没落定”，本轮新登记的问题落定前不列。
  - 收回：离开 0.15 秒后卡 0.12 秒淡出，再过 0.4 秒钟与播放接着走。
- **展开**
  - 触发：点液滴、标签、小珠、托盘里的事、格子或概要卡；Tab 后按 Enter 或空格。
  - 0 秒切点：旁白改写为“这一件 · 8/15 12:00 · 条目标题”，右栏切到“这一件”（摘要、回应、份额理由、依据、来源处的回应、两周版本）。
  - 0–0.3 秒：液滴沿“容器中心 → 液滴中心”这条线向外推 8 px（缓出，过冲 3.7%），大小不变；水底的小珠与托盘里的事向上推 8 px。
  - 0.4–0.6 秒：引线从液滴边上沿同一条线出去，过了它的标签再连到卡。
  - 0.6–0.9 秒：详情卡从引线末端展开，先沿接上的那条边、再向外；卡贴在容器离它远的一侧，避开它自己与标签。
  - 卡上是 ix 的详情（摘要、子层、份额逐轮、本轮进了它的输入、开着的问题与期限、你的回应），问题旁不是“去回答 →”，是“在右栏作答”：C 自己能作答，点它把焦点移到右栏的回应控件。
  - 收回：Esc、点空白、再点同一件：卡 0.2 秒收起、引线 0.15 秒缩回、液滴 0.2 秒落回，然后一帧切回旁白与右栏，0.4 秒后接着走。点另一件先收回再展开。←/→、拖时间轴、▶ 与合页顶栏选帧会立即收起并照常执行。`prefers-reduced-motion` 时直接到终态。
- **作答**（右栏）：按下回应控件，控件原地收成回执（0.2 秒），“N 件等你回应”减一；液滴旁的问题标签原地换成回执一行，朱红环换成墨色虚线环。下一轮整理的切点回执填实、虚线变实线；推后的在那一轮的沉浮拍里沉进托盘。撤回逆着走；已经沉下的撤回后马上浮回（0.6 秒）。
- **脚本：** `window.foldC` 有与 `foldDial` 同名同义的 `hover / unhover / open / close / ixAt / ix / paused / pointOf / ixState`，名字可用条目 id 或短名（猫看病、待审 PR）；另有 `beatAt(t)` 把换轮停在切点后 t 秒（定格用）、`tell()` 与 `skip()`、`answer(id, action)`。

## 5 实现（motion、direct）

改的文件：`prototype/variants/c.mjs`（重写）、`c-field.mjs`、`c.css`；`scripts/check-ix.mjs` 的 PAGES 末尾加了 `c`。`temporal.mjs`、`ix.mjs`、`explore.mjs`、`shared.mjs`、`respond.mjs` 没有改。

- **一个钟，按段取值。** 每件事是一个“体”，位置、份额、深度（0 水面上，1 水面下）、透明度、颜色、环各有一段 `[起, 止, t0, t1, 缓动]`，每帧在同一个换轮钟上取值。换轮时先把所有体冻结在屏幕上的当前值，再按四段的时刻表排新的段，所以任何时刻打断都从眼前起算，不跳。种类：`turn`（一轮往后，四段全走）、`fast`（讲一遍第二拍，四段按比例压缩到一轮约 0.9 秒，story 约 0.6 秒）、`jump`（往回、拖轴、跨几轮：长缩与沉浮并成 0.42 秒）、`layer`（进出子层 0.5 秒）、`local`（作答撤回引起的沉浮 0.6 秒）、`instant`（首屏、减少动态、后台标签页）。
- **守恒是构造出来的。** 长缩段里所有份额（新增的从 0、撤下与并入的到 0）用同一条缓入缓出、同一对 t0 / t1，所以各体份额之和 = 前后两轮已分配的同一插值，留白 = 64 减它。f25 → f26 定在 1.35 秒时量得体的份额和 57.5、留白 6.5（52 → 63 的正中）。
- **信息层只在落定时换。** 页面留着一份 `shown` 快照：份数、标签、环的墨色与虚实、64 格带、水底与托盘的说明、标题行、阅读区都读它，只在落定那一帧换成新的；信号行“本轮输入 N 条”是唯一在落定之前动的数：切点写“…”，涌入段末（1.0 秒，讲一遍第二拍按比例压缩）一帧翻成 N。
- **粒子与泥** 画在液滴下面的一张 2D 画布上，墨色低透明度；WebGL 与 Canvas 2D 退路共用这一张，两条路一起改到。只画采用、并且落进当前层某一滴或某颗小珠的输入，一条一粒，半径 1.05 px、不透明度 0.29（初版 1.5 px、0.42 的七成）。粒子按 `event.at` 在 0–0.4 秒放出；落进的体用 `batch.declarations[].sources` 里的 `event:` 引用，否则 `relatedIds[0]`，沿合并与父级上到当前层（与整理脉冲同一规则，详情卡的“本轮进了它 N 条”用的也是这个规则）。泥不由粒子落成：容器最下 27 px 里按编号排着一串固定点位（半径 1.3 px、不透明度 0.26），第 j 个在 j 小于本轮暂缓条数时显示；换轮时每个点位从眼前的不透明度沿长缩段（1.0–1.7 秒）的缓动走到新目标，多的淡入、少的淡出，打断时从眼前接着走；往回走、跳帧在那 0.42 秒里换，首屏直接铺好。
- **排布。** 每次换轮只解一次布局（`solveLayout`），以各滴上一轮的位置为初值；要沉下去的滴作为固定节点占着原位，别的滴绕开它；每滴的“家”按层记住，所以沉下又浮起的事回到原处。整层的比例按这层两周里最挤的三轮定一次（约 0.7–1），不再逐帧换档。
- **压暗** 在着色器与 Canvas 退路里用同一个式子：其余体向纸色混 30%（`DIM_TO_PAPER`），阴影与环乘同一个系数；粒子与泥降到四成。液滴、小珠、托盘里的事都画在 WebGL 里（最多 32 个体），这样压暗、弹出与命中对每一种都一样。`c-field.mjs` 加了每体的压暗与环墨色，把分组参数并成一个 `vec4` 数组，片元着色器的 uniform 向量用量低于 WebGL2 保证的 224。
- **交互** 接 `motion/ix.mjs`：命中按到圆心的距离（液滴边缘外 12 px，小珠与托盘外 8 px），标签与 64 格带的格子也算；弹出方向是“容器中心 → 液滴中心”，小珠与托盘向上；详情卡站在弹出的那一侧，放不下时换到另一侧，引线从液滴朝卡的那一点直连到卡边。▶ 是 C 自己的播放器：每 5.6 秒一轮，悬停或展开时连同剩余时间一起停住，移开后从剩下的时间接着走；底栏的空格也转到它。
- **作答。** 右栏控件原地收成回执（盒子高度 0.2 秒缓到回执的高度，回执在 45% 之后淡入）；同一刻标题“N 件”减一，液滴旁的标签换成回执一行，朱红环换成墨色虚线环，液滴不动。下一轮切点虚线变实线，落定时回执写“已收到”；推后的在那一轮的沉浮段沉进右侧托盘，下面挂“◷ 09:00”，64 格带里它的格子换成斜纹；到点那一轮的沉浮段浮回原处，信号行写“◷ 1 件到点浮起”，右栏顶上列出。已经沉下的撤回后马上浮回（这一段不受悬停停表的约束）。
- **讲一遍。** 只在顶层、加载地址不带 `frame=`（读 `performance` 的导航记录，地址栏已被改写过）、没有 referrer、不在 `prefers-reduced-motion` 下时开始。步骤等前一轮落定再走；第二拍每轮固定间隔。英雄数字是小珠下方的一枚小签：“N 轮在水下 · 标题”，每个切点后落定时加一；浮起后写“9 轮之后浮起 · 1 → 6 份”，详情卡出来时让开。任意键或按下一次跳到浮起那一帧；顶栏“▶ 讲一遍 / 跳过 ▸▸”。嵌入（`is-embedded`）时按钮不显示。

## 6 与故事的出入、定格与验证（ship）

**与第 3、4 节的出入**

- 讲一遍实测：composite 21.0 秒（f07 在 6.0 秒，f15 在 13.5 秒，详情卡 16.9 秒出现），story 20.8 秒（f22 在 13.3 秒）。第二拍每轮 composite 约 0.9–1.0 秒（压缩后的四段比 0.875 秒的间隔略长，以落定为准）、story 0.6 秒。
- 英雄签不是“字高为水底那一条的三分之一”的大字，是小珠正下方一枚 22 px 数字的小签（放在水底说明那一行下面，不压字）；浮起后写“9 轮之后浮起 · 1 → 6 份”，不是“沉了 9 轮”，并且在详情卡出来时让开，而不是浮出后 1.2 秒淡去（卡上同一行“沉过 9 轮，第 16 次整理浮起”接着讲）。
