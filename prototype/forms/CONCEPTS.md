## 第一轮结论

2026-10-15，用户看过十个形式后的原话：

> 那个两周小倍数，虽然我不知道有啥用，但是还有点意思，其他的感觉略普通，不如我之前创意的那几个（指 A/B/C/D）。。。btw 你那个水晶球也太丑了。

诊断：

- A/B/C/D 每个都是围绕状态本身发明的一种结构：空间、时间、流体、首页。第一轮多数形式是把状态搬进一个现成载体：手表、广播、小票、报纸、时刻表、聊天窗。载体眼熟，所以第一眼成立，但结构没有新东西。
- 小倍数被认可，是因为它是唯一回答“注意力在两周里怎样移动”的形式，一眼扫完两周；其他所有视图只给“此刻”。
- 环境球的问题在渲染：高光 3D 球加暗房，像老式拟物屏保。“环境信号”这个想法本身没有被否定。

处理：只保留 08 两周小倍数，页面仍在画廊。撤下九个：01 腕上一瞥、02 晨间朗读、03 进程条架、04 头版、05 小票、06 环境球、07 到期时刻表、09 出处栏、10 对话线程。它们的代码已删除，概念卡留在下文供回看，标题标注“已撤下”；“发现：状态缺少的信息”一节仍然有效。

之后用户决定保留 01 腕上一瞥：2026-10-15 从第一轮分支恢复了它的页面，与两周小倍数一起留在画廊。其余八个仍撤下；同日晚为了把所有原型合在[一页](../all.html)里看，它们也从第一轮分支恢复为可运行页面，只做了能在两个数据集下运行的最小适配，没有打磨，仍算撤下，放在合页末尾与画廊页尾。

第二轮由诊断得出三条规则：不把状态塞进现成设备或媒介；每个形式先写清它让人看见了哪一种其他形式都看不见的关系；平面、克制，让数据本身构成画面。五张草图与概念卡见文末[第二轮概念卡](#第二轮概念卡)。

## 第一轮的出发点

A/B/C/D 都把整份状态铺在一块屏幕上，区别在怎样编码份额：面积、时间带、液滴体量、先后与字号。用户认为方向对，想看到更多、更不一样的形式。这一轮不再只换编码，而是同时换载体、场景与用法：表盘、耳机、纸卷、台灯、车站大屏、聊天窗口；一瞥、通勤、值守、复盘、核对、被打断；被动接收、按时间收听、手写回应、对话回应。

## 概念卡怎样读

| 栏目 | 回答什么 |
| --- | --- |
| 载体 / 场景 / 用法 | 在什么东西上、什么时候、怎么用 |
| 读者此刻的问题 | 拿起它时想知道的那一件事 |
| 预注意通道 | 面积、位置、颜色、字号、声音、触觉、时间顺序中，哪一个给了哪一个维度 |
| 视觉骨架 | 第一眼的画面构成，用一两句话或 ASCII 草图 |
| 故意舍弃 | 为了这一个问题，主动不表达什么 |
| 与 A/B/C/D 的结构差异 | 不只是“另一种排卡片”的理由 |
| 配色 | 只在偏离原型纸白墨绿体系时说明理由 |

所有形式遵守 [EXPLORATIONS.md](../EXPLORATIONS.md#共同边界) 的共同边界：读同一份回放、份额不重算、关系只来自数据、不制造“已读”、保留未分配份额、标题与原数据一致。页面上的概念卡由 `catalog.mjs` 提供：`forms` 是留下的腕上一瞥与两周小倍数，`withdrawn`（`round: 1, withdrawn: true`）是撤下后恢复的八个，与本文第一轮的十张卡保持一致；画廊里第二轮草图的简介在同一文件的 `sketches` 中，与文末第二轮概念卡保持一致。

## 第一轮做的十个形式

### 1. 腕上一瞥 · `watch` · 用户决定保留

- 载体 / 场景 / 用法：手表表盘、卡片堆与回应屏 / 会议间隙、走路时抬腕两秒 / 被动一瞥，必要时点按回应；悬停刻度或表盘下的事项名看概要，点击展开详情。
- 读者此刻的问题：有没有等我回应的事？最大的是哪件？
- 预注意通道：角度给份额（表圈 64 个刻度，一格一份，按排名顺时针点亮）；颜色只给“登记了回应路径”（朱红刻度）；字号只给一个数：等你回应的件数。
- 视觉骨架：

  ```text
  ┌───────────┐  ┌───────────┐  ┌───────────┐
  │ ·:::::::· │  │ 10:00     │  │ 这次开放  │
  │:  10:00  :│  │┌─────────┐│  │ 给谁？    │
  │:    2    :│  ││暂存口径 ││  │[只开两店] │
  │: 件等你  :│  ││未知…    ││  │[10%老用户]│
  │ ·:::::::· │  │└─────────┘│  │ 稍后提醒  │
  └───────────┘  └─露边 +2──┘  └───────────┘
   表盘：刻度=份额    卡片堆        回应屏
  ```

- 故意舍弃：摘要、来源、子层结构、没有回应路径的事项文字（只剩灰色刻度）。
- 与 A/B/C/D 的结构差异：不铺开任何事项，整份状态压缩成一圈刻度和一个数；D 的卡片在这里只剩“最前一张 + 露边”。
- 配色：表盘是黑底 OLED 惯例，白字，朱红只给回应路径。
- 灵感：#7 Farsight、#8 Smart Stack、#9 灵动岛、#11 Pebble、#41 触觉。
- 2026-10-19 按第三轮的标准重做（[watch-motion.md](polish/watch-motion.md)）：它是读数的工具，不是官网动画，概念层只占两成，只在换轮时动 1.5 秒：本轮输入化成灰点落向表圈、64 格从 0 点顺时针换主人，新变得要紧的那几件闪一下、外沿轻敲，中间的数最后落定；英雄数字仍是等你回的件数。悬停与展开共用 [motion/ix.mjs](motion/ix.mjs)，卡挂在表壳外。

### 2. 晨间朗读 · `radio` · 已撤下

- 载体 / 场景 / 用法：耳机或音箱，配一份朗读稿 / 通勤、做早饭时 / 线性收听，可说“下一件”“展开”“稍后”。
- 读者此刻的问题：不看屏幕，我能在一分多钟里听到该知道的吗？
- 预注意通道：时间长度给份额（每份约 1.5 秒播报预算，64 份上限 96 秒；份额决定这件事被读几句）；时间顺序给排名；未分配份额就是简报提前结束的时间。
- 视觉骨架：

  ```text
  ┃▇▇▇▇▇▇▇▇▇▇▇▇┃▇▇▇▇▇▇┃▇▇▇▇▇▇┃▇▇▇┃▇┃░░░░░┃  ← 播报时间轴：段长=份额，灰=未分配
  ▶ 01:12 / 01:31
  ──────────────────────────────────────────
  24份 │ 远川演示仍缺暂存字段解释。                ← 正在读的句子高亮
       │ 11点演示只看分店数据……需要你决定：……
  12份 │ 导出发布是否仅开放远川两店……
  ```

- 故意舍弃：空间总览与并排比较；子层只在“展开”时读；来源只给最大份额的一条。
- 与 A/B/C/D 的结构差异：唯一不依赖视觉的形式；份额第一次变成“占用你多少秒”。
- 配色：朗读稿用纸白墨绿；当前句用浅黄底，像荧光笔，只表示“正在读”。
- 灵感：#27 Flash Briefing、#28 标题导航、#29 驾驶场景、#21 Espresso。

### 3. 进程条架 · `strips` · 已撤下

- 载体 / 场景 / 用法：桌面工作站或平板的“条架” / 白天持续值守、多 Agent 并行时 / 主动巡视，拿起一条看子项。
- 读者此刻的问题：每件事处在哪个阶段？这一轮改了哪一格？
- 预注意通道：位置给阶段（四个槽：等你回应、进行中、已有结果、知会）；字号给份额（条左的大数字与刻度条）；蓝色手写笔迹只给“本轮改动”，旧值划掉留在条上。
- 视觉骨架：

  ```text
  等你回应 ┃ 24 ▮▮▮▮▮▮ │ 远川演示仍缺暂存字段解释   │ 期限 16日11:00 │ 3h │ 邮件·群 │ ↳2 ┃
           ┃ 12 ▮▮▮    │ 导出发布是否仅开放远川两店 │ ~~旧标题~~ 新  │    │         │ ↳2 ┃
  进行中   ┃  6 ▮▮     │ 厨房维修已约周五14点       │ …                                 ┃
  ```

- 故意舍弃：面积与液体那样的“分量感”；所有条等高，只有大数字与刻度条说份额。
- 与 A/B/C/D 的结构差异：固定字段的密表格，按阶段分槽而不是按份额铺版；改动就地手写，不切换到对比视图。
- 配色：深灰条架、米黄纸条、黑色印字；蓝墨水只用于本轮改动。
- 灵感：#13 飞行进程单、#12 Bloomberg、#16 分诊牌、#15 安灯。

### 4. 头版 · `frontpage` · 已撤下

- 载体 / 场景 / 用法：一张报纸版面，可打印 / 周末早餐、离开半天后的深读 / 主动阅读，边读边用笔批注。
- 读者此刻的问题：这一轮最大的新闻是什么？其余事各占多大版面？
- 预注意通道：面积与字号给份额：版面是 8 栏 × 8 行 = 64 格，每件事占的格数等于份额，标题字号按格数分档；位置给排名（左上起）；报耳放等你回应的件数与本轮输入统计。
- 视觉骨架：

  ```text
  ┌ 等你 3 件 ┐   F O L D   晨  报        ┌ 输入 3 条 ┐
  └──────────┘ 第 r23 版 · 10月16日 周五   └──────────┘
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  ██ 远川演示仍缺暂存字段解释 ██████ │ 导出发布是否仅 │
  导语……  正文 正文 正文 正文 正文    │ 开放远川两店   │
  ──────────────────────────────────┼───────────────┤
  周六11点见妈妈 │ 厨房维修 │ 筛选  │ 本版留白 3 份  │
  ```

- 故意舍弃：时间演变与动效；版面一期一印，变化只在报耳和“本期新”标记里说。
- 与 A/B/C/D 的结构差异：编辑排版的语法，面积之外还有标题字号、导语、正文与栏线；可直接打印。A 是散落纸片，这里是有栏网格的整版。
- 配色：新闻纸米白与黑色衬线；唯一的红色用于“需要你”的栏目标签，延续报纸红字栏头的习惯。
- 灵感：#20 报纸头版、#21 Espresso、#22 Morning Brew、#26 TRMNL。

### 5. 小票 · `receipt` · 已撤下

- 载体 / 场景 / 用法：58 毫米热敏纸卷 / 早上桌上自动打出一张，回家后看一眼 / 被动接收，撕下带走，在方框里打勾回应。
- 读者此刻的问题：这一期有什么？和上一张比，哪件变长了、哪件没了？
- 预注意通道：纸的长度给份额（每份 14 像素，约 1.5 毫米），左侧一格一份的刻度尺；未分配份额是走纸留白；两张并排给比较。
- 视觉骨架：

  ```text
   上一张(f11)      这一张(f12)
  ╭──────────╮    ╭──────────╮
  │ FOLD r22 │    │ FOLD r23 │
  │┊ 家人 12 │    │┊ 远川 24 │  ← 长度 = 份额
  │┊ ……      │    │┊ □ 演示留空
  │┊ 发布 12 │    │┊ □ 按现有口径
  │┊ ……      │    │┊ 发布 12 │
  │ 留白 3份 │    │ 留白 3份 │
  ╰╌╌✂╌╌╌╌╌╯    ╰╌╌✂╌╌╌╌╌╯
  ```

- 故意舍弃：颜色、交互、子层（只印子项数）；纸面上的勾选不回传状态。
- 与 A/B/C/D 的结构差异：一维的“长度”编码，物理可带走；比较靠两张纸并排而不是动画。
- 配色：热敏纸只有黑色，阴影与纸色只为看出是一张纸。
- 灵感：#25 Little Printer、#21 Espresso、#24 小倍数的同尺度原则。

### 6. 环境球 · `orb` · 已撤下

- 载体 / 场景 / 用法：桌上一颗会发光的球与一圈底座灯 / 人在场工作，余光里 / 完全被动；按一下才说出最大的那件。
- 读者此刻的问题：现在要不要分心看一下？
- 预注意通道：色相只给“有没有登记了回应路径的事”（暖橙 / 冷白绿）；亮度给等你回应的事合计占多少份；呼吸只给“本轮新增了等你回应的事”；底座 64 颗灯一灯一份。
- 视觉骨架：

  ```text
          .-""-.            解码
         /  ◉   \           等你回应 3 件 · 合计 48/64 份 → 亮度 75%
         \      /           本轮新增 2 件 → 呼吸
          '-..-'            按一下 → “远川演示仍缺暂存字段解释”
     ○○○○●●●●●●●●○○○○       底座：一灯一份，暖色=等你
  ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
  37 帧的球色：▮▮▯▮▮▮▯▯▮▮……
  ```

- 故意舍弃：几乎全部文字；没有回应路径的事只体现在底座白灯里。
- 与 A/B/C/D 的结构差异：唯一不需要阅读的形式；它决定“要不要去看”，而不是“看什么”。
- 配色：深色房间才能看出光，因此页面用暗色；暖橙只表示等你回应。
- 灵感：#1 Ambient Orb、#2 Nabaztag、#3 Dangling String、#4 Calm Technology、#15 安灯。

### 7. 到期时刻表 · `departures` · 已撤下

- 载体 / 场景 / 用法：走廊或车站式翻牌大屏 / 规划今天，看接下来会发生什么 / 路过时扫一眼，变化时翻牌。
- 读者此刻的问题：接下来几点会有什么到期？哪些已经过点？
- 预注意通道：纵向位置给到期时间（由近到远）；琥珀色翻牌只给“等你回应”；翻牌动作只给本轮变化的行；份额是一列数字与刻度。
- 视觉骨架：

  ```text
  ┌─ 前 方 ──────────────────────── 10月16日 10:00 ─┐
  │ 11:00 16日 │ 远川演示仍缺暂存字段解释 │ 等你决定 │ 24 │ 还有 1 小时 │
  ```

## 发现：状态缺少的信息

这些是做形式时碰到的缺口，只记录，不改契约：

- **受众与可见范围。** 团队墙、共享大屏、家人一起看的冰箱屏，都需要知道哪些事项能给谁看。现在工作与家事在同一份状态里，任何共享形式都会泄露私事。
- **事项归属。** 多个 Agent 共享预算时，任务墙要按负责的 Agent 分列；状态与回执里只有批次的 `actor`，条目上没有。
- **日程或会议关联。** 会前一页需要“这件事与哪场会有关”；`due_at` 只是时间点，不说明场合。
- **批次级说明。** 对话线程与晨间朗读最自然的开场是“这一轮做了什么”。回放数据里的 `frame.title` 与 `frame.narrative` 是故事作者写的旁白，契约中的批次只有声明、`reason` 与确认，没有面向用户的批次说明。原型照读这两段，并在页面上注明它们来自演示数据。
- **上次接触的锚点。** 小票的“上一张”、对话线程的“上次读到这里”、出处栏的“自你上次看后”都需要一个起点；首切片 `last_seen_at` 恒为 null。原型用上一帧或手选起点代替，和 D 的做法一致。
- **回应本身的期限。** 手表与时刻表想显示“这个问题几点前要答”，但期限属于事项（`due_at`），登记的问题没有自己的截止时间。
- **可朗读的写法。** 标题里有“INP 486ms”“p75”这样的写法，读出来不自然。原型照原文朗读，没有另起名字；是否需要为语音单独提供读法，留待以后判断。

## 原型边界

- 每个形式只做到能表达核心假设：第一眼画面要成立，不做复杂动效和响应式适配。
- 回应按钮、勾选框、对话快捷回复只在本页演示，不写回状态，也不产生“已阅”。
- 每页右侧写着自己的概念卡；顶部“状态”打开完整 state JSON、原始输入、声明与回执、本轮变化。
- 页面用 `?frame=` 选择帧，←/→ 逐帧。截图只在本地 `.local/forms/` 保存，不提交。
- 第二轮草图不受上面三条约束：每张只画一个选定帧，没有帧导航、交互、概念卡面板与状态检查器，截图在 `.local/forms-r2/`。

### 下一轮怎样分工

- **首页类（D、腕上一瞥）只承载最急的少数问题。** 真实数据里同时开着 9 个问题，其中只有猫的药量与车道下的主水管是当天要决定的（新数据 f26：开着 5 个问题，只有主水管要在一两天内决定，期限 8/17 10:00）；建议由 `due_at` 与档位选出至多 3 个，其余折成计数。
- **空间类（原版、A）承载工作评审的 approve。** 它们本来就在电脑前看，适合把 PR 链接、批准与要求修改放在格子里。
- **时间类（B、回应时序）承载 schedule 与 defer。** 航班改签、周末排气、冻结后再审都依赖“期限在此刻之后的哪里”（新数据里航班改签不带期限，母亲九月住哪、主水管与开学同意书带期限）。
- **复盘类（小倍数、身份线、来源矩阵、批次记谱、让位图）不承载作答**，只标出问题的开闭与作答后的份额去向。
- **所有形式都要先解决两件通用的事**：来源处的回应怎样写（`via: source`，不贴原文、不冒充回答了别的问题），以及根层长尾怎样折叠（1 份事项与身份色不够用）。

## 第三轮：概念动画

2026-10-19。前两轮问的是“一帧该怎样画”；这一轮做给第一次看 Fold 的人：官网首屏的概念动画。它不是新的视图，而是把**一轮整理本身**演出来。入口在[画廊](index.html)的“第三轮：动画”，页面放在 `motion/`，参考视频见 [INSPIRATION.md](INSPIRATION.md) 第三轮。

show 不是这个项目的目的，但想 show 就能 show、完全不用调整底层逻辑，是这套设计的优势。动画页和前两轮的形式一样只读同一份 `scenario.mjs` 回放（同一组 frames、批次、问题与反馈），用 `engine.mjs` 重放、按已有页面的算法现算，不另造数据管道、不改契约、不在数据里加任何只为动画服务的字段；炫的部分全在渲染层完成。同一份状态，既能压成手表上的一圈刻度，也能铺成官网的一整屏动画。

**两层怎样叠。** 每一页分概念层与信息层，各页的具体叠法写在各自一节：

- 概念层约占八成画面，可以炫、可以密、可以一直动（整理脉冲是粒子、笔触、辉光与余辉，份额拨盘是字形碎片、记号簇与灰仪表）。疏密比例来自真实数据，整理脉冲更进一步，一颗亮粒子就是一条输入（见下），份额拨盘里绝对个数仍是装饰；它只用灰，不出可读的文字与数字，也不用朱红，也不暗示信息层没有的事实（空轮不下雨，没有新问题时不闪任何像朱红线的东西）。
- 信息层约占两成，少、准、有出处，只在节拍上动：大数字、份额、问题、流水线。每个数都能在该页的 `data.json` 里找到来源，页面用同一推导现算。

**交互同一套。** 两页（以及按同一标准重做的 01 腕上一瞥、改过的 [05 批次记谱](polish/notation-motion.md)、加了放映的 [08 两周小倍数](polish/multiples-motion.md)、[02 回应时序](polish/timing-motion.md)与做了动画的 [04 让位图](polish/yield-motion.md)）的悬停看概要、点击展开详情走同一个模块 [motion/ix.mjs](motion/ix.mjs)（样式 [motion/ix.css](motion/ix.css)，纸色与黑底两套只差变量）：状态机与时序、概要卡与详情卡、摆位与引线、键盘与触屏、`window.foldX` 的同名钩子都在里面，页面只说哪里是哪件事、卡挂在哪里、怎样停表与压暗。接入要提供什么写在文件头的宿主契约里，之后的形式照它接；`scripts/check-ix.mjs` 用真的鼠标、键盘与触屏事件逐页跑同一套 16 项检查。D 手机首页也用它的概要卡、详情两节与时序，但手机没有悬停：长按代替悬停、轻点展开，`check-ix` 给它另跑一套 23 项触屏流程（[home-motion.md](polish/home-motion.md)）。

### 01 整理脉冲 · `motion/pulse.html`

**主关系**：一轮整理本身。前两轮把一轮记成一帧（原版、A/B/C/D）或一行（批次记谱）；这里把一轮演成 4.25 秒的一次脉冲：上百条落下成云，一道弧从外向根收拢，只有几颗被带到根上、再化成光顺着枝流上去，要你开口的那一件从枝梢打一道朱红线到根。

**一个圆心**：两层共用以根为圆心的极坐标。根是一段弧，扇形是正圆扇（张角 160°），64 条份额线是从根出发的射线，扇形外沿是一道细弧；每根枝就是其中一条射线从根到梢被点亮（偶数格的楔形取靠自己一侧的那条），光沿同一条直线上行；云在外沿之外的环带里，事件沿射线朝根落下；收拢弧与根同心、张角等于扇形；暂缓的余烬是外沿外侧一圈同心环带。上一版的扇形外沿是椭圆、弧是正圆、云是顶部矩形雨，两层对不齐，用户说“前后景对不上，有点假”；统一圆心之后，枝仍是先抬升再外倾的曲线，大枝弯出射线网格、梢不在任何一条射线上，用户又说“弧度还是不一样”，于是枝改成直的射线。

**一颗一条**：云里一颗亮粒子就是一条输入，另带三颗更小更暗的尘埃做质感（固定三倍，弧经过就散）。亮粒子的去向与面板分类一一对应，f20 的 234 颗里 66 颗进根、111 颗成余烬、57 颗熄灭，即“采用 66”“没采用 168 = 暂缓 111 + 噪音 57”；页面的 `foldPulse.census(i)` 能逐轮核对。

**三个节拍**：涌入 1.0 秒（落下先快后慢、砸到位）、折叠 2.1 秒（弧 0.45 秒扫过云，噪音熄灭、暂缓被推到外沿成余烬；再 0.7 秒穿过扇形合到根，采用的落在所属条目在根上的格子，停 0.12 秒，化成一束光顺枝流到梢，光到哪里枝亮到哪里，到梢时枝梢闪一下、枝按新份额变粗）、一问 1.15 秒（整屏先压暗 0.3 秒，朱红线成为唯一的亮点；没有新问题的轮次只剩余辉）。自动播放从 f00 起，f28 之后是片尾“两周 3196 条 → 新登记 26 个问题”，树收回根后接回 f00，全程约 124 秒。`?frame=` 演一遍那一轮再停住，`?from=` 从那一轮起连播。

**用法**：自动连播两周，←/→ 逐轮重放一次脉冲；悬停枝条看概要，点击展开详情，两者都让本轮的时钟停在当前时刻，详情里的问题链到同一帧的 D 去回答。标准与份额拨盘相同，落在本页的几何上：枝是线，命中区放宽到线两侧 10 px，名字、枝梢与根上的格子都算；展开时枝与格子沿自己的射线外推 8 px，引线从枝梢沿同一条射线出到外沿再连到卡；卡上的数守本轮节拍（触发、动作与收回见 [story.md](motion/pulse/story.md) 末节“交互”）。

**叠法**：概念层画在下面的 WebGL 画布里，色调映射封顶 0.62，最亮处也低于信息层的字与线（约 0.88）；吸收是两层交接的地方：粒子在概念层被带到根，枝上流动的光画在信息层；信息层每行字的框内概念层为 0，向外 40 px 线性回到原亮度，面板保留框形遮罩，粒子不进面板；信息层每次动作时概念层压暗约三成，要让人只看一处时整屏先压暗。

| 颜色 | 含义 |
| --- | --- |
| 灰白 | 概念层的一切；信息层的枝、64 格、64 条份额线与文字 |
| 朱红 | 只给回应路径：新登记的问题、你的回应沿线返回、答掉后根上的记号、“新问”的数 |

参考拆解、数字与出处、故事见 [spec.md](motion/pulse/spec.md)、[data.json](motion/pulse/data.json)、[story.md](motion/pulse/story.md)；灵感 #73、#74。

**还差什么**：页面只有横屏布局，900 px 以下收起流水线面板，竖屏（手机）没有单独排版；详情卡贴在画面边上，会盖住同侧几根已压暗的枝；Canvas 2D 退路没有余辉，看起来比 WebGL 版素；概念层的亮度按 Apple M1 Pro 调过，别的显卡没有看过。采用的输入若所指条目当轮不在树上（composite 的 f21 两条、f26 一条），进根后直接散掉，没有光可走。

### 02 份额拨盘 · `motion/dial.html`

**主关系**：64 份是一条硬约束。成百条输入进来，环上只留十几件；一件变大，同一轮里别的就得缩；游标只停在等你回、而且要紧的那一件上。

**三拍**（20 秒循环；空格连播 28 轮、每轮 4 秒；←/→ 逐帧并停住）：

1. 刻度（0–5.5 秒，f00→f01）：首次打开先静 0.4 秒，刻度顺时针数出，64 落进环心；76 条从五条车道进来、38 条被采用，母亲换水管、猫看病各长到 12 份，留白 7；游标落到“Smilla 约上兽医了吗？”。
2. 涌入（5.5–14.5 秒，f02→f25 每轮 0.375 秒）：累计输入从 207 滚到 2893，环一格没多；扇区每轮跳一次；f23–f25 没有要紧的问题，游标空心退回硬止刻。
3. 让位（14.5–20 秒，f26）：158 条进来，主水管 12→24，同一轮留白 12→1、猫看病 12→6；游标甩到主水管，落定 0.3 秒后 16 条相关输入收成线束：“主水管：挖开换还是免挖？8/17 10:00 前”。

**用法**：默认循环 20 秒三拍，空格连播，←/→ 逐帧；悬停看概要，点击展开详情，两者都让播放停在当前轮（触发、动作与收回见 [story.md](motion/dial/story.md) 末节“交互”）。

**两层怎样叠**：

| 层 | 占画面 | 画什么 | 规矩 |
| --- | --- | --- | --- |
| 概念层 | 约八成 | 外圈三层沿切线正向排的字形与字段碎片、车道上远浅近深三档灰度的记号簇、左侧细线、三块灰仪表（输入片段、处置格、信号窗口） | 只用灰；字不大于 9px 且截断，不出现可读的整句消息；首次打开静 0.4 秒后一直动，跨切点不断；信息层动的那 0.6 秒降到四成不透明；不进环心、游标、计数、标题 |
| 信息层 | 约两成 | 64 刻度与硬止刻、扇区与留白、游标与注释、五个计数、旁白 `frame.title`、车道上墨色的真实输入、逐轮已分配折线 | 墨黑加一个朱红；只在节拍上动，切点一帧硬切；每个数字都能在 [data.json](motion/dial/data.json) 里对上 |

| 颜色 | 含义 |
| --- | --- |
| 墨黑 | 游标所指的扇区、游标与它的名牌、计数与文字 |
| 灰阶 | 其余扇区（两档交替）与整个概念层 |
| 朱红 | 只给等你回的问题：注释里的小方块；环外沿其余开着的问题用暗朱红小刻 |

画法：canvas 画车道、记号与线束，SVG 只画环与文字；64 刻度、硬止刻与环心的 64 建好后不再重画。拆解见 [spec.md](motion/dial/spec.md)，画面数字见 [data.json](motion/dial/data.json)，三拍与约束见 [story.md](motion/dial/story.md)。

灵感：视频 B（@francescoinweb3 的工作室仪表）：0.4 秒的第一个动作、一帧硬切、亮的极少。

**还差什么**：

- 不承载作答；只有详情里问题旁的“去回答 →”链到同一帧的 D 手机首页，官网上怎样从动画过渡到首页类形式仍没有设计。
- “谁让给谁”的配对回执里没有，只能画成同一轮里一涨一缩同时落定。
- story 数据集没有 `stream`，车道按 channel 在渲染层归组（规则在 `motion/dial-model.mjs`），只是近似。
