## 第一轮结论

2026-10-15，用户看过十个形式后的原话：

> 那个两周小倍数，虽然我不知道有啥用，但是还有点意思，其他的感觉略普通，不如我之前创意的那几个（指 A/B/C/D）。。。btw 你那个水晶球也太丑了。

诊断：

- A/B/C/D 每个都是围绕状态本身发明的一种结构：空间、时间、流体、首页。第一轮多数形式是把状态搬进一个现成载体：手表、广播、小票、报纸、时刻表、聊天窗。载体眼熟，所以第一眼成立，但结构没有新东西。
- 小倍数被认可，是因为它是唯一回答“注意力在两周里怎样移动”的形式，一眼扫完两周；其他所有视图只给“此刻”。
- 环境球的问题在渲染：高光 3D 球加暗房，像老式拟物屏保。“环境信号”这个想法本身没有被否定。

处理：只保留 08 两周小倍数，页面仍在画廊。撤下九个：01 腕上一瞥、02 晨间朗读、03 进程条架、04 头版、05 小票、06 环境球、07 到期时刻表、09 出处栏、10 对话线程。它们的代码已删除，概念卡留在下文供回看，标题标注“已撤下”；“发现：状态缺少的信息”一节仍然有效。

之后用户决定保留 01 腕上一瞥：2026-10-15 从第一轮分支恢复了它的页面，与两周小倍数一起留在画廊。其余八个仍撤下；同日晚为了把所有原型合在[一页](../all.html)里看，它们也从第一轮分支恢复为可运行页面，只做了能在两个数据集下运行的最小适配，没有打磨，仍算撤下，放在合页末尾与画廊页尾。

第二轮由诊断得出三条规则：不把状态塞进现成设备或媒介；每个形式先写清它让人看见了哪一种其他形式都看不见的关系；平面、克制，让数据本身构成画面。五张草图与概念卡见文末[第二轮概念卡](#第二轮概念卡)。

## 第一轮的出发点

A/B/C/D 都把整份状态铺在一块屏幕上，区别在怎样编码份额：面积、时间带、液滴体量、先后与字号。用户认为方向对，想看到更多、更不一样的形式。这一轮不再只换编码，而是同时换载体、场景与用法：表盘、耳机、纸卷、台灯、车站大屏、聊天窗口；一瞥、通勤、值守、复盘、核对、被打断；被动接收、按时间收听、手写回应、对话回应。

## 概念卡怎样读

| 栏目 | 回答什么 |
| --- | --- |
| 载体 / 场景 / 用法 | 在什么东西上、什么时候、怎么用 |
| 读者此刻的问题 | 拿起它时想知道的那一件事 |
| 预注意通道 | 面积、位置、颜色、字号、声音、触觉、时间顺序中，哪一个给了哪一个维度 |
| 视觉骨架 | 第一眼的画面构成，用一两句话或 ASCII 草图 |
| 故意舍弃 | 为了这一个问题，主动不表达什么 |
| 与 A/B/C/D 的结构差异 | 不只是“另一种排卡片”的理由 |
| 配色 | 只在偏离原型纸白墨绿体系时说明理由 |

所有形式遵守 [EXPLORATIONS.md](../EXPLORATIONS.md#共同边界) 的共同边界：读同一份回放、份额不重算、关系只来自数据、不制造“已读”、保留未分配份额、标题与原数据一致。页面上的概念卡由 `catalog.mjs` 提供：`forms` 是留下的腕上一瞥与两周小倍数，`withdrawn`（`round: 1, withdrawn: true`）是撤下后恢复的八个，与本文第一轮的十张卡保持一致；画廊里第二轮草图的简介在同一文件的 `sketches` 中，与文末第二轮概念卡保持一致。

## 第一轮做的十个形式

### 1. 腕上一瞥 · `watch` · 用户决定保留

- 载体 / 场景 / 用法：手表表盘、卡片堆与回应屏 / 会议间隙、走路时抬腕两秒 / 被动一瞥，必要时点按回应；悬停刻度或表盘下的事项名看概要，点击展开详情。
- 读者此刻的问题：有没有等我回应的事？最大的是哪件？
- 预注意通道：角度给份额（表圈 64 个刻度，一格一份，按排名顺时针点亮）；颜色只给“登记了回应路径”（朱红刻度）；字号只给一个数：等你回应的件数。
- 视觉骨架：

  ```text
  ┌───────────┐  ┌───────────┐  ┌───────────┐
  │ ·:::::::· │  │ 10:00     │  │ 这次开放  │
  │:  10:00  :│  │┌─────────┐│  │ 给谁？    │
  │:    2    :│  ││暂存口径 ││  │[只开两店] │
  │: 件等你  :│  ││未知…    ││  │[10%老用户]│
  │ ·:::::::· │  │└─────────┘│  │ 稍后提醒  │
  └───────────┘  └─露边 +2──┘  └───────────┘
   表盘：刻度=份额    卡片堆        回应屏
  ```

- 故意舍弃：摘要、来源、子层结构、没有回应路径的事项文字（只剩灰色刻度）。
- 与 A/B/C/D 的结构差异：不铺开任何事项，整份状态压缩成一圈刻度和一个数；D 的卡片在这里只剩“最前一张 + 露边”。
- 配色：表盘是黑底 OLED 惯例，白字，朱红只给回应路径。
- 灵感：#7 Farsight、#8 Smart Stack、#9 灵动岛、#11 Pebble、#41 触觉。
- 2026-10-19 按第三轮的标准重做（[watch-motion.md](polish/watch-motion.md)）：它是读数的工具，不是官网动画，概念层只占两成，只在换轮时动 1.5 秒：本轮输入化成灰点落向表圈、64 格从 0 点顺时针换主人，新变得要紧的那几件闪一下、外沿轻敲，中间的数最后落定；英雄数字仍是等你回的件数。悬停与展开共用 [motion/ix.mjs](motion/ix.mjs)，卡挂在表壳外。

### 2. 晨间朗读 · `radio` · 已撤下

- 载体 / 场景 / 用法：耳机或音箱，配一份朗读稿 / 通勤、做早饭时 / 线性收听，可说“下一件”“展开”“稍后”。
- 读者此刻的问题：不看屏幕，我能在一分多钟里听到该知道的吗？
- 预注意通道：时间长度给份额（每份约 1.5 秒播报预算，64 份上限 96 秒；份额决定这件事被读几句）；时间顺序给排名；未分配份额就是简报提前结束的时间。
- 视觉骨架：

  ```text
  ┃▇▇▇▇▇▇▇▇▇▇▇▇┃▇▇▇▇▇▇┃▇▇▇▇▇▇┃▇▇▇┃▇┃░░░░░┃  ← 播报时间轴：段长=份额，灰=未分配
  ▶ 01:12 / 01:31
  ──────────────────────────────────────────
  24份 │ 远川演示仍缺暂存字段解释。                ← 正在读的句子高亮
       │ 11点演示只看分店数据……需要你决定：……
  12份 │ 导出发布是否仅开放远川两店……
  ```

- 故意舍弃：空间总览与并排比较；子层只在“展开”时读；来源只给最大份额的一条。
- 与 A/B/C/D 的结构差异：唯一不依赖视觉的形式；份额第一次变成“占用你多少秒”。
- 配色：朗读稿用纸白墨绿；当前句用浅黄底，像荧光笔，只表示“正在读”。
- 灵感：#27 Flash Briefing、#28 标题导航、#29 驾驶场景、#21 Espresso。

### 3. 进程条架 · `strips` · 已撤下

- 载体 / 场景 / 用法：桌面工作站或平板的“条架” / 白天持续值守、多 Agent 并行时 / 主动巡视，拿起一条看子项。
- 读者此刻的问题：每件事处在哪个阶段？这一轮改了哪一格？
- 预注意通道：位置给阶段（四个槽：等你回应、进行中、已有结果、知会）；字号给份额（条左的大数字与刻度条）；蓝色手写笔迹只给“本轮改动”，旧值划掉留在条上。
- 视觉骨架：

  ```text
  等你回应 ┃ 24 ▮▮▮▮▮▮ │ 远川演示仍缺暂存字段解释   │ 期限 16日11:00 │ 3h │ 邮件·群 │ ↳2 ┃
           ┃ 12 ▮▮▮    │ 导出发布是否仅开放远川两店 │ ~~旧标题~~ 新  │    │         │ ↳2 ┃
  进行中   ┃  6 ▮▮     │ 厨房维修已约周五14点       │ …                                 ┃
  ```

- 故意舍弃：面积与液体那样的“分量感”；所有条等高，只有大数字与刻度条说份额。
- 与 A/B/C/D 的结构差异：固定字段的密表格，按阶段分槽而不是按份额铺版；改动就地手写，不切换到对比视图。
- 配色：深灰条架、米黄纸条、黑色印字；蓝墨水只用于本轮改动。
- 灵感：#13 飞行进程单、#12 Bloomberg、#16 分诊牌、#15 安灯。

### 4. 头版 · `frontpage` · 已撤下

- 载体 / 场景 / 用法：一张报纸版面，可打印 / 周末早餐、离开半天后的深读 / 主动阅读，边读边用笔批注。
- 读者此刻的问题：这一轮最大的新闻是什么？其余事各占多大版面？
- 预注意通道：面积与字号给份额：版面是 8 栏 × 8 行 = 64 格，每件事占的格数等于份额，标题字号按格数分档；位置给排名（左上起）；报耳放等你回应的件数与本轮输入统计。
- 视觉骨架：

  ```text
  ┌ 等你 3 件 ┐   F O L D   晨  报        ┌ 输入 3 条 ┐
  └──────────┘ 第 r23 版 · 10月16日 周五   └──────────┘
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  ██ 远川演示仍缺暂存字段解释 ██████ │ 导出发布是否仅 │
  导语……  正文 正文 正文 正文 正文    │ 开放远川两店   │
  ──────────────────────────────────┼───────────────┤
  周六11点见妈妈 │ 厨房维修 │ 筛选  │ 本版留白 3 份  │
  ```

- 故意舍弃：时间演变与动效；版面一期一印，变化只在报耳和“本期新”标记里说。
- 与 A/B/C/D 的结构差异：编辑排版的语法，面积之外还有标题字号、导语、正文与栏线；可直接打印。A 是散落纸片，这里是有栏网格的整版。
- 配色：新闻纸米白与黑色衬线；唯一的红色用于“需要你”的栏目标签，延续报纸红字栏头的习惯。
- 灵感：#20 报纸头版、#21 Espresso、#22 Morning Brew、#26 TRMNL。

### 5. 小票 · `receipt` · 已撤下

- 载体 / 场景 / 用法：58 毫米热敏纸卷 / 早上桌上自动打出一张，回家后看一眼 / 被动接收，撕下带走，在方框里打勾回应。
- 读者此刻的问题：这一期有什么？和上一张比，哪件变长了、哪件没了？
- 预注意通道：纸的长度给份额（每份 14 像素，约 1.5 毫米），左侧一格一份的刻度尺；未分配份额是走纸留白；两张并排给比较。
- 视觉骨架：

  ```text
   上一张(f11)      这一张(f12)
  ╭──────────╮    ╭──────────╮
  │ FOLD r22 │    │ FOLD r23 │
  │┊ 家人 12 │    │┊ 远川 24 │  ← 长度 = 份额
  │┊ ……      │    │┊ □ 演示留空
  │┊ 发布 12 │    │┊ □ 按现有口径
  │┊ ……      │    │┊ 发布 12 │
  │ 留白 3份 │    │ 留白 3份 │
  ╰╌╌✂╌╌╌╌╌╯    ╰╌╌✂╌╌╌╌╌╯
  ```

- 故意舍弃：颜色、交互、子层（只印子项数）；纸面上的勾选不回传状态。
- 与 A/B/C/D 的结构差异：一维的“长度”编码，物理可带走；比较靠两张纸并排而不是动画。
- 配色：热敏纸只有黑色，阴影与纸色只为看出是一张纸。
- 灵感：#25 Little Printer、#21 Espresso、#24 小倍数的同尺度原则。

### 6. 环境球 · `orb` · 已撤下

- 载体 / 场景 / 用法：桌上一颗会发光的球与一圈底座灯 / 人在场工作，余光里 / 完全被动；按一下才说出最大的那件。
- 读者此刻的问题：现在要不要分心看一下？

## 发现：状态缺少的信息

这些是做形式时碰到的缺口，只记录，不改契约：

- **受众与可见范围。** 团队墙、共享大屏、家人一起看的冰箱屏，都需要知道哪些事项能给谁看。现在工作与家事在同一份状态里，任何共享形式都会泄露私事。
- **事项归属。** 多个 Agent 共享预算时，任务墙要按负责的 Agent 分列；状态与回执里只有批次的 `actor`，条目上没有。
- **日程或会议关联。** 会前一页需要“这件事与哪场会有关”；`due_at` 只是时间点，不说明场合。
- **批次级说明。** 对话线程与晨间朗读最自然的开场是“这一轮做了什么”。回放数据里的 `frame.title` 与 `frame.narrative` 是故事作者写的旁白，契约中的批次只有声明、`reason` 与确认，没有面向用户的批次说明。原型照读这两段，并在页面上注明它们来自演示数据。
- **上次接触的锚点。** 小票的“上一张”、对话线程的“上次读到这里”、出处栏的“自你上次看后”都需要一个起点；首切片 `last_seen_at` 恒为 null。原型用上一帧或手选起点代替，和 D 的做法一致。第四轮的峰值保持把它当成主关系，起点改成页面侧的推定：你最近一次在 Fold 里回应时屏上的那一帧，没有就往前 6 轮，可手选，按“已阅”移到此刻（只在本页内存）；composite 的 160 条反馈全在来源处，两周里一次也没有在 Fold 里回应，推定只能退到往前 6 轮（[peak-motion.md](polish/peak-motion.md) 第 2 节）。
- **回应本身的期限。** 手表与时刻表想显示“这个问题几点前要答”，但期限属于事项（`due_at`），登记的问题没有自己的截止时间。
- **可朗读的写法。** 标题里有“INP 486ms”“p75”这样的写法，读出来不自然。原型照原文朗读，没有另起名字；是否需要为语音单独提供读法，留待以后判断。
- **谁在等、答了之后谁能动。** 等待链要画“这个问题后面站着谁、答了之后哪一环能动”。状态里没有等待方：页面只能从问题所在条目这一版依据（`sources`）的作者里按规则推（去掉本人、机器、公开资料与陌生人，见 [chain-motion.md](polish/chain-motion.md) 第 2 节），推不出转述的等待（“妈妈问我去不去”只有你自己的一句）、机构的群发期限（学校的同意书），也会把旁证里的人算进来；“答了之后”只能读 `ask.actions`、approve 的 `subject` 与期限，真实动了什么写在 `reason` 与 `summary` 的自然语言里。要画准，问题上可以带可选的 `waiting_on`（人或渠道，指向依据里的输入）与 `unblocks`（答了之后谁或哪件事能动）。

## 原型边界

- 每个形式只做到能表达核心假设：第一眼画面要成立，不做复杂动效和响应式适配。
- 回应按钮、勾选框、对话快捷回复只在本页演示，不写回状态，也不产生“已阅”。
- 每页右侧写着自己的概念卡；顶部“状态”打开完整 state JSON、原始输入、声明与回执、本轮变化。
- 页面用 `?frame=` 选择帧，←/→ 逐帧。截图只在本地 `.local/forms/` 保存，不提交。
- 第二轮草图不受上面三条约束：每张只画一个选定帧，没有帧导航、交互、概念卡面板与状态检查器，截图在 `.local/forms-r2/`。

## 第二轮概念卡

2026-10-15。按[第一轮结论](#第一轮结论)的三条规则做了五张草图，每张是一页 1440×900 的完整画面，读同一份回放，只画一个选定帧，入口在[画廊](index.html)的“第二轮草图”。

### 02 回应时序 · `sketches/timing.html`

### 下一轮怎样分工

- **首页类（D、腕上一瞥）只承载最急的少数问题。** 真实数据里同时开着 9 个问题，其中只有猫的药量与车道下的主水管是当天要决定的（新数据 f26：开着 5 个问题，只有主水管要在一两天内决定，期限 8/17 10:00）；建议由 `due_at` 与档位选出至多 3 个，其余折成计数。
- **空间类（原版、A）承载工作评审的 approve。** 它们本来就在电脑前看，适合把 PR 链接、批准与要求修改放在格子里。
- **时间类（B、回应时序）承载 schedule 与 defer。** 航班改签、周末排气、冻结后再审都依赖“期限在此刻之后的哪里”（新数据里航班改签不带期限，母亲九月住哪、主水管与开学同意书带期限）。
- **复盘类（小倍数、身份线、来源矩阵、批次记谱、让位图）不承载作答**，只标出问题的开闭与作答后的份额去向。
- **所有形式都要先解决两件通用的事**：来源处的回应怎样写（`via: source`，不贴原文、不冒充回答了别的问题），以及根层长尾怎样折叠（1 份事项与身份色不够用）。

## 第三轮：概念动画

2026-10-19。前两轮问的是“一帧该怎样画”；这一轮做给第一次看 Fold 的人：官网首屏的概念动画。它不是新的视图，而是把**一轮整理本身**演出来。入口在[画廊](index.html)的“第三轮：动画”，页面放在 `motion/`，参考视频见 [INSPIRATION.md](INSPIRATION.md) 第三轮。

show 不是这个项目的目的，但想 show 就能 show、完全不用调整底层逻辑，是这套设计的优势。动画页和前两轮的形式一样只读同一份 `scenario.mjs` 回放（同一组 frames、批次、问题与反馈），用 `engine.mjs` 重放、按已有页面的算法现算，不另造数据管道、不改契约、不在数据里加任何只为动画服务的字段；炫的部分全在渲染层完成。同一份状态，既能压成手表上的一圈刻度，也能铺成官网的一整屏动画。

**两层怎样叠。** 每一页分概念层与信息层，各页的具体叠法写在各自一节：

- 概念层约占八成画面，可以炫、可以密、可以一直动（整理脉冲是粒子、笔触、辉光与余辉，份额拨盘是字形碎片、记号簇与灰仪表）。疏密比例来自真实数据，整理脉冲更进一步，一颗亮粒子就是一条输入（见下），份额拨盘里绝对个数仍是装饰；它只用灰，不出可读的文字与数字，也不用朱红，也不暗示信息层没有的事实（空轮不下雨，没有新问题时不闪任何像朱红线的东西）。
- 信息层约占两成，少、准、有出处，只在节拍上动：大数字、份额、问题、流水线。每个数都能在该页的 `data.json` 里找到来源，页面用同一推导现算。

**交互同一套。** 两页（以及按同一标准重做的 01 腕上一瞥、改过的 [05 批次记谱](polish/notation-motion.md)、加了放映的 [08 两周小倍数](polish/multiples-motion.md)、[02 回应时序](polish/timing-motion.md)与做了动画的 [04 让位图](polish/yield-motion.md)，以及按同一标准重做的 [B 时间展开](polish/b-motion.md)、[C 流动形态](polish/c-motion.md)、[原版树图](polish/tree-motion.md)与 [A 空间排布](polish/a-motion.md)，以及第四轮的 [04 变形](polish/morph-motion.md)、[07 峰值保持](polish/peak-motion.md)、[03 驻龄](polish/age-motion.md)、[05 等待链](polish/chain-motion.md)、[01 拔河](polish/tug-motion.md)、[06 结绳](polish/khipu-motion.md)、[08 回应托盘](polish/trays-motion.md)，和桌面壳层的 [E 折叠屏](polish/duo-motion.md)）的悬停看概要、点击展开详情走同一个模块 [motion/ix.mjs](motion/ix.mjs)（样式 [motion/ix.css](motion/ix.css)，纸色与黑底两套只差变量）：状态机与时序、概要卡与详情卡、摆位与引线、键盘与触屏、`window.foldX` 的同名钩子都在里面，页面只说哪里是哪件事、卡挂在哪里、怎样停表与压暗。接入要提供什么写在文件头的宿主契约里，之后的形式照它接；`scripts/check-ix.mjs` 用真的鼠标、键盘与触屏事件逐页跑同一套 16 项检查。D 手机首页也用它的概要卡、详情两节与时序，但手机没有悬停：长按代替悬停、轻点展开，`check-ix` 给它另跑一套 23 项触屏流程（[home-motion.md](polish/home-motion.md)）；E 折叠屏同 D 一样长按代替悬停，另跑 29 项，多出铰链与翻页、左页详情、色带格联动与讲一遍（[duo-motion.md](polish/duo-motion.md)）。回应托盘也在手机上，照 D 的触屏规则接，`check-ix` 另跑一套 29 项（[trays-motion.md](polish/trays-motion.md)）。

### 01 整理脉冲 · `motion/pulse.html`

**主关系**：一轮整理本身。前两轮把一轮记成一帧（原版、A/B/C/D）或一行（批次记谱）；这里把一轮演成 4.25 秒的一次脉冲：上百条落下成云，一道弧从外向根收拢，只有几颗被带到根上、再化成光顺着枝流上去，要你开口的那一件从枝梢打一道朱红线到根。

**一个圆心**：两层共用以根为圆心的极坐标。根是一段弧，扇形是正圆扇（张角 160°），64 条份额线是从根出发的射线，扇形外沿是一道细弧；每根枝就是其中一条射线从根到梢被点亮（偶数格的楔形取靠自己一侧的那条），光沿同一条直线上行；云在外沿之外的环带里，事件沿射线朝根落下；收拢弧与根同心、张角等于扇形；暂缓的余烬是外沿外侧一圈同心环带。上一版的扇形外沿是椭圆、弧是正圆、云是顶部矩形雨，两层对不齐，用户说“前后景对不上，有点假”；统一圆心之后，枝仍是先抬升再外倾的曲线，大枝弯出射线网格、梢不在任何一条射线上，用户又说“弧度还是不一样”，于是枝改成直的射线。

**一颗一条**：云里一颗亮粒子就是一条输入，另带三颗更小更暗的尘埃做质感（固定三倍，弧经过就散）。亮粒子的去向与面板分类一一对应，f20 的 234 颗里 66 颗进根、111 颗成余烬、57 颗熄灭，即“采用 66”“没采用 168 = 暂缓 111 + 噪音 57”；页面的 `foldPulse.census(i)` 能逐轮核对。

**三个节拍**：涌入 1.0 秒（落下先快后慢、砸到位）、折叠 2.1 秒（弧 0.45 秒扫过云，噪音熄灭、暂缓被推到外沿成余烬；再 0.7 秒穿过扇形合到根，采用的落在所属条目在根上的格子，停 0.12 秒，化成一束光顺枝流到梢，光到哪里枝亮到哪里，到梢时枝梢闪一下、枝按新份额变粗）、一问 1.15 秒（整屏先压暗 0.3 秒，朱红线成为唯一的亮点；没有新问题的轮次只剩余辉）。自动播放从 f00 起，f28 之后是片尾“两周 3196 条 → 新登记 26 个问题”，树收回根后接回 f00，全程约 124 秒。`?frame=` 演一遍那一轮再停住，`?from=` 从那一轮起连播。

**用法**：自动连播两周，←/→ 逐轮重放一次脉冲；悬停枝条看概要，点击展开详情，两者都让本轮的时钟停在当前时刻，详情里的问题链到同一帧的 D 去回答。标准与份额拨盘相同，落在本页的几何上：枝是线，命中区放宽到线两侧 10 px，名字、枝梢与根上的格子都算；展开时枝与格子沿自己的射线外推 8 px，引线从枝梢沿同一条射线出到外沿再连到卡；卡上的数守本轮节拍（触发、动作与收回见 [story.md](motion/pulse/story.md) 末节“交互”）。

**叠法**：概念层画在下面的 WebGL 画布里，色调映射封顶 0.62，最亮处也低于信息层的字与线（约 0.88）；吸收是两层交接的地方：粒子在概念层被带到根，枝上流动的光画在信息层；信息层每行字的框内概念层为 0，向外 40 px 线性回到原亮度，面板保留框形遮罩，粒子不进面板；信息层每次动作时概念层压暗约三成，要让人只看一处时整屏先压暗。

| --- | --- |
| 灰白 | 概念层的一切；信息层的枝、64 格、64 条份额线与文字 |
| 朱红 | 只给回应路径：新登记的问题、你的回应沿线返回、答掉后根上的记号、“新问”的数 |

参考拆解、数字与出处、故事见 [spec.md](motion/pulse/spec.md)、[data.json](motion/pulse/data.json)、[story.md](motion/pulse/story.md)；灵感 #73、#74。

**还差什么**：页面只有横屏布局，900 px 以下收起流水线面板，竖屏（手机）没有单独排版；详情卡贴在画面边上，会盖住同侧几根已压暗的枝；Canvas 2D 退路没有余辉，看起来比 WebGL 版素；概念层的亮度按 Apple M1 Pro 调过，别的显卡没有看过。采用的输入若所指条目当轮不在树上（composite 的 f21 两条、f26 一条），进根后直接散掉，没有光可走。

### 02 份额拨盘 · `motion/dial.html`

**主关系**：64 份是一条硬约束。成百条输入进来，环上只留十几件；一件变大，同一轮里别的就得缩；游标只停在等你回、而且要紧的那一件上。

**三拍**（20 秒循环；空格连播 28 轮、每轮 4 秒；←/→ 逐帧并停住）：

1. 刻度（0–5.5 秒，f00→f01）：首次打开先静 0.4 秒，刻度顺时针数出，64 落进环心；76 条从五条车道进来、38 条被采用，母亲换水管、猫看病各长到 12 份，留白 7；游标落到“Smilla 约上兽医了吗？”。
2. 涌入（5.5–14.5 秒，f02→f25 每轮 0.375 秒）：累计输入从 207 滚到 2893，环一格没多；扇区每轮跳一次；f23–f25 没有要紧的问题，游标空心退回硬止刻。
3. 让位（14.5–20 秒，f26）：158 条进来，主水管 12→24，同一轮留白 12→1、猫看病 12→6；游标甩到主水管，落定 0.3 秒后 16 条相关输入收成线束：“主水管：挖开换还是免挖？8/17 10:00 前”。

**用法**：默认循环 20 秒三拍，空格连播，←/→ 逐帧；悬停看概要，点击展开详情，两者都让播放停在当前轮（触发、动作与收回见 [story.md](motion/dial/story.md) 末节“交互”）。

**两层怎样叠**：

| --- | --- | --- | --- |

**还差什么**：

- 不承载作答；只有详情里问题旁的“去回答 →”链到同一帧的 D 手机首页，官网上怎样从动画过渡到首页类形式仍没有设计。

### E 折叠屏 · `index.html?variant=duo`

**主关系**：轮到谁。合上是 D；展开时每件等你的事沿折痕拆成两半，左半写 Agent 为它做了什么（来源、本轮进了几条、两周份额、为什么升档），右半写要你答什么，两半同一行、同一高。铰链就是 Agent 与你的分界：64 格份额带一页宽，分界线压在折痕上，你的格子在右、Agent 的与空余在左。右页就是外屏，合上时留在手里的正是右半。

**三拍**：

1. 展开：照 iPhone Duo 的开合做成真的翻页，跟着铰链走。承载外屏的那块板绕折痕向左、朝你翻开（透视，转到一半自由边迎面变高），右页一像素不动，就是外屏；板的正面越翻越像磨砂玻璃、越透明，露出底下一模一样的右页；背面就是跨页的左页，钉在终点，靠折痕先清，越往自由边越糊越暗，落平时全清。内屏报告跨页（120°）时右页整理一次 0.40 秒：右半压紧，折起的几件展开成单行条，英雄数字在 0.22 秒那一帧从“5 件”翻成“38 份”；板继续翻到 180°，份额带在 120°–170° 随铰链从折痕向两侧长出来。合上是整理倒放并加快（0.28 秒），然后板跟手合回，暗与糊从自由边扫向折痕。
2. 答一件：右半原地收成回执，条高不变，下面什么都不动；墨格就地变空心，数字少这一件的份额。
3. 整理落地（1.0 秒）：回执先填实，再斜穿折痕落到“Agent 在办”那一行（目标在屏外时从左页下缘离开），左半同时下移成那一行；空心格过分界变灰，其余的条上移一次，新问题描一圈。

**用法**：拖折痕上的把手折、展，松手落到最近的姿态；[ ] 每次 15°，F 一键折 / 展，`?hinge=0..1` 定格在 180° × hinge 那个角度；侧栏三个按钮切合上、书本、桌面。手势与 D 同一套：长按看概要、轻点左半详情长满左页（右半仍可作答）、长按色带格把那一件的两半描出来，Esc 或点空白收回。直接打开讲一遍约 11 秒：合上 → 展开 → 答一件 → 下一轮落地 → 合上，任意键跳到结尾。故事、时间表与交互表见 [duo-motion.md](polish/duo-motion.md)。

**两层**：概念层只有份额带和左页页头那块累计细纹，只用墨与灰；其余都是信息层，数字只在节拍上变。翻页只换表现、不动信息层：板上画的就是两块屏本来的样子，糊与暗是隔着毛玻璃看它；板只有一圈发丝边，不画金属机身、高光与戏剧化的阴影。平放时折痕处只有 24 pt 纸色留白，半折时按 `ReservedRegion(.division)` 加宽到 48 pt。

**还差什么**：

- 尺寸按 @3x 推算，铰链阈值（20° 接管、120° 报告跨页）是常量，都待真机量；浏览器里的铰链是模拟的。
- 帐篷姿态没做，等真机确认帐篷时外屏能不能作答。
- 桌面姿态的作答与书本同一张时间表；换轮只用通用的移位与进出场，没有回执过分界那一笔。

## 第四轮：关系的画法

2026-10-28。第四轮灵感（[INSPIRATION.md](INSPIRATION.md#第四轮没碰过的方向)）只找前三轮没碰过的方向，由它长出 8 个[候选](INSPIRATION.md#第四轮候选)；每个都先回答“它让人看见哪一种别的形式看不见的关系”，再按六步流程（参考、数据、故事、动起来、自审、交付）做成完整形式。它们和第二轮一样是复盘工具：只读同一份回放现算，概念层不到一成、静止时为零，悬停与展开走 [motion/ix.mjs](motion/ix.mjs)。

### 01 拔河 · `sketches/tug.html`

**主关系**：家里与工作在 64 份里此消彼长：谁领先、领先多少、哪一轮被哪件事拉过中线；以及你在来源处实际在哪一边动手。小倍数按身份着色，看不出领域之间的拉锯；没有一个形式把“Agent 给的份额”和“你做的”并排。

**英雄数字**：此刻的“家里 : 工作”，composite f26 是 40 : 23；标题给两周的极值，8/13 00:00 家里 59 份、工作 5 份。

**三拍**（直接打开时讲一遍，composite 约 23 秒，停在 f26；任意键跳过，顶栏「▶ 讲一遍」重演）：

1. 手在工作上（f01–f08）：第一轮家里就领先；到 f08 份额家里 39 : 工作 25，你却在工作上动手 13 次、家里 1 次。
2. 坠下（f09–f20）：f18 向家里 28（母亲换水管 +12、猫看病 +9），f20 家里 59 : 工作 5。
3. 弹回（f21–f26）：f23 向工作 35（母亲换水管 −18、猫看病 −12），留白一下空出 25 份；f26 落在 40 : 23。

story 照实是另一个故事（约 17 秒，停在 f19）：工作一直占大头，家里只在林苒开口的那个周末翻过中线（f15 30 : 16），周一退回（f19 18 : 37）。

**两层怎样叠**：信息层是条、曲线、朱红柱与注，数字只在一轮落定时一帧硬切；概念层不到一成，只有一样：一格换了边（工作 → 留白 → 家里），条上的分界扫过它时先灰 0.28 秒，落定后为零。动得顺靠同一样东西连续地动：条上每一段从上一轮的位置滑到这一轮，曲线的头同时走到这一轮的点，朱红柱从基线长出。

| 颜色 | 含义 |
| --- | --- |
| 墨黑 | 家里（家庭与生活）：条的下半、曲线在中线下的墨面 |
| 纸白与浅灰 | 工作：条的上半、曲线在中线上的浅面 |
| 斜线 | 留白 |
| 朱红 | 只给你：在来源处的回应（向上工作、向下家里）、你的批注 ✎ |
| 灰 | 换了边的格子，拉的时候先灰一下 |

口径：每件根层事项按它引用过的来源投票，得票最多的是工作流就算工作，其余都算家里，两周不变；回应一条反馈链接算一次，归到它指向的那件事所在的一边。数字、三拍与时间表见 [tug-motion.md](polish/tug-motion.md)。

灵感：#89 棋局复盘的评估条与评估曲线、#88 纽约时报 2016 年选举指针（只取“此刻一个数、背后一条走过来的曲线”，不取指针的抖动）、#54 Playfair 差额面积。

**还差什么**：

- 领域是推断的：composite 用事件的 `stream`，story 没有，按 channel 头归组；生活问答并入家里。状态里没有“这件事属于哪个领域”。
- 次数不等于用力：一条评论是一次，一通电话也是一次。回应的分量回放里没有。
- 只画根层；子层的拉锯与“领先”的好坏都不画，份额没有对错。

### 03 驻龄 · `sketches/age.html`

**主关系**：此刻的 64 份里，每一份已经在当前这件事上连续待了几轮：多少是沉淀的，多少是刚换手的。

让位图画每一轮份额从谁来、到谁去，小倍数画每件事的大小怎样变，都看不出此刻的预算有多“新”：主水管的 24 份里 12 份是这一轮才给的，母亲换水管剩下的 3 份从第一轮起就没挪过。

**选用帧**：f26（8/16 00:00，r26）。车道下的铜管裂了，主水管 12→24，FTPS 计时 1→6、后刹 1→3，同一轮猫看病 12→6、Ture 发烧 3→1；63 份里 19 份是这一轮才给的，从第一轮起没挪过的只剩 6 份（母亲换水管 3 份，master CI、猫看病、Kerberos 各 1 份）。story 停在 f19：55 份里 21 份是这一轮才给的，发布的 3 份从第一轮起没挪过。

```text
f26 · 一格一份；数字 = 待了几轮，+ = 10 轮以上，■ = 从第一轮起一直在，· = 留白
 ■ ■ 1 1 4 4 5 ■
 ■ 3 1 1 4 4 3 7
 3 3 ■ 1 1 4 2 5
 1 9 + 9 + 2 3 3
 1 1 9 1 1 3 3 2
 1 1 1 1 + 3 3 2
 1 8 ■ 1 + 2 2 5
 1 9 5 1 · 5 5 5
```

驻龄的算法：第 i 轮一件事的第 k 份已经待了几轮 = 往回数，这件事的份额一直不少于 k 的轮数。它等价于一个栈：变小时先交回最年轻的几份，变大时新的从 1 数起。只算根层；并入算新的一件，从 1 数起；撤下再恢复也从 1 数起；留白不计驻龄。

| 记号 | 含义 |
| --- | --- |
| 同心方框的圈数 | 这一份在这件事上连续待了几轮，画到 12 圈 |
| 实心黑 | 从第一轮起一直在，又已超过 12 圈 |
| 浅底连成一块，格缝中线一道细线 | 同一件事的地盘 |
| 虚线格 | 留白 |

只用墨黑，圈数是唯一的变量。

灵感：#90 Vera Molnár《(Des)Ordres》（同心方框）、#91《Interruptions à recouvrements》（格子不动，只在局部被打断）、#93 Jared Tarbell《Substrate》（一道一道长出来）。

**动起来**（[age-motion.md](polish/age-motion.md)）：格子两周不挪，只在份额易手时换主人。一轮三个动作：清出（变小的事交回最年轻的格，圈向中心收拢、淡出，原位留一道灰框 0.5 秒散去）、加圈（留下的每一格最里面多一圈）、新框（认领空格的事画出最外一道框），平账一帧落定。英雄数字是这一轮新给的份数 / 此刻在用的份数，旁边是守恒：让出 + 留白减 = 新给。直接打开时讲一遍约 23 秒（story 约 21 秒）：快放到 f21，f23 母亲换水管一次清出 18 格（其中 6 格从第一轮起就在）全速放，停在 f26；静止时概念层为零。悬停与展开共用 [motion/ix.mjs](motion/ix.mjs)：一件事的地盘描边、其余降到七成，点击沿“方阵中心 → 地盘重心”弹出 8 px，引线沿格缝出到详情卡，侧栏切到“这一件”。

**还差什么**：

- 格在哪里是画法：回执只记每件事增减多少，不记谁让给谁；新给的格落在空着、又离自己地盘近的地方，卡与侧栏一律写“同一轮清出 / 新给”。
- 驻龄只算根层，子层没有画。
- 撤下又恢复、并入的事都从 1 数起，看不出它是“回来的”；并入的只是落在来源让出的格里。

### 04 变形 · `sketches/morph.html`

**主关系**：Agent 的判断本身。同一批事项留在原位，面积从“收到多少条输入”变成“占多少份”；收到最多的那件不一定给得最多。来源矩阵数来源，整理脉冲把输入汇到根上，没有一种让同一件事的两种量在原地互换。

**选用帧**：f26（8/16 00:00「车道下的铜管裂了」）。关联到此刻 14 件的输入 464 条，已分配 63 份、留白 1：收到最多的 master CI 141 条只给 6 份，车道下的主水管 29 条给了 24 份；条数里家里 45%，份额里家里 63%。composite 的 28 轮里，收到最多的那件从来不是份额最多的那件；手写情境不是每轮都这样，所以论点只写这一轮。

```text
收到（面积 = 条数占比 × 已分配份额）        给出（面积 = 份额）
   ○ master CI 141                           ○ master CI 6      ← 同一个位置，只改面积
         ● 主水管 29        ── 1.4 秒 ──▶          ● 主水管 24
   ○ 待审 PR 52   ● 猫看病 60                ○ 待审 PR 6   ● 猫看病 6
                ┊留白 1┊                                ┊留白 1┊   ← 两态一样大
```

| 颜色 | 含义 |
| --- | --- |
| 黑 / 白 | 家里 / 工作（两周落到它身上的输入按流计，工作过半为白），与拔河一致，只此一义 |
| 细灰圈 | 这件事在另一态的大小 |
| 灰虚线圈 | 留白，两态不变 |
| 朱红小方块 | 此刻有开着的问题，只此一义 |

**口径**：一条输入指向批次声明里引用它的那件事，没有引用就取 `relatedIds[0]`，再沿合并与父级上溯到正在看的这一帧的根层事项（与整理脉冲同一规则）；暂缓与重复照算，噪音不指向任何事项。所以 master CI 是 141 而不是草图的 149（草图把 `relatedIds` 里的每个 id 各算一次），待审 PR 沿合并接上旧的两版是 52。

**三拍**（约 7 秒，停在 f26；story 停在 f15：发布 11 条 → 3 份，妈妈 10 条 → 24 份）：

1. 收到（0.4–2.4 秒）：从只有留白的空图起，14 个圆同一条缓出、同起同落长到收到态，条数在落定那一帧写出；master CI 一个白圆最大。
2. 变形（2.4–4.4 秒）：所有圆原地胀缩成给出态，同一条缓入缓出、不过冲，面积线性插值，任何一帧圆面积之和加留白都是 64 份；落定那一帧数字从“条”换成“份”，英雄数字补齐“141 → 6”。
3. 放大与压小（4.4–7.0 秒）：master CI 的细圈与主水管的黑圆描墨边，各挂一条注：“141 条 → 6 份 · 收到的 30% → 份额的 9%”“29 条 → 24 份 · 6% → 38%”。

**用法**：只在顶层直接打开、不带 `frame=`、不是从别处链来时讲一遍，任意键跳过，“▶ 讲一遍”重讲；其余情况静止，默认最后一帧。“收到 / 给出”或 M 原地变形 1 秒；←/→ 换轮 0.7 秒，位置从上一轮出发只做最小的挪动，并入的一边缩一边挪进它并入的那一件。悬停看概要，点击弹出 8 px、引线出到详情卡，侧栏切到“这一件”，开着的问题旁“去回答 →”链到同一帧的 D；画法与自审见 [morph-motion.md](polish/morph-motion.md)。

灵感：#96 Douïeb “Land doesn't vote, people do” 的原地变形、#92 Hobbs 的最小间距、#75 Liquid Glass 的总量守恒；同起同落取自 [C 流动形态](polish/c-motion.md)。

**还差什么**：

- 回放里没有 Agent 为什么给这件事这么多份；`reason` 是一句话，不是对条数的解释。“按条数分”从来不是系统的一个状态，收到态只是一种读数。
- 一件事撤下、同一轮另起新 id 而没有记合并时，旧 id 的输入接不过去；状态里没有“它们是同一件”的记录。
- 手写情境没有 `stream`，家里与工作按 channel 在渲染层归组（`motion/dial-model.mjs` 的车道规则），只是近似。

### 05 等待链 · `sketches/chain.html`

**主关系**：谁在等谁、你挡住了谁。每个开着的问题后面站着哪些人、各等了多久，答了之后哪一环才能动；答掉一件，放走的是一串人。

已有形式都不画“这个问题后面站着谁”：回应时序画问题开了多久，B 画期限在此刻之后的哪里，D 只取最急的 3 张，来源矩阵数谁喂了哪件事。

**谁在等由规则现算，不手工标注**：开着的问题所在那件事这一版的依据里，去掉你自己、机器（`author_kind` 为 bot 或 automation）、公开资料（`publicSourceId`）、群里通讯录外的人与公开站点上的陌生人，剩下的作者一人算一个，等了多久从他在依据里最早的那条算起。composite 171 个问题·帧里 80% 找得到有名字的人，story 131 个里 86%；规则、两套数据的结果与推不出来的四种情形见 [chain-motion.md](polish/chain-motion.md) 第 2 节。

### 08 回应托盘 · `trays.html`

和本轮其余几张不同，回应托盘不是复盘工具，是手机上真正作答的地方（390 × 844）：页面放在 `forms/`，与腕上一瞥用同一个页框（帧导航、概念卡、核对数据），交互照 D 手机首页的触屏规则。先写动画记录的参考、数据、故事与手势再动（[trays-motion.md](polish/trays-motion.md)）。

**主关系**：每个问题要你付出多少。D 把问题排成一样的卡片、按多急排；托盘也按多急排（同 D 的档位、期限、份额），但让托盘的**高度**说要你点几下：一下就完的（确认、批准、选择、带建议句或预填金额的回复、拍照）只有一排按钮，最矮；推后、定时刻要先点开再挑，没有建议句的回复要先点开再写，高一排。托盘仍是真正作答的地方，不加“去回答 →”。

**英雄数字**：“6 下答完 5 个问题”（composite f26）：4 个点一下就完，“三个旧 PR 推到哪天？”要先点“推到…”再挑一天。两周里 4–9 下，有两下托盘的轮次 18 轮。story 两周 36 轮没有一个两下的问题（作者给每个要一句话、一个数的问题都配了建议句或预填），托盘一样高，页面照实画。几下的口径写在页脚与详情里（[trays-motion.md](polish/trays-motion.md) 2.1）。

**三拍**：

1. 叠起（换轮，约 1.0 秒，D 的换轮节拍）：切点换字；回执先填实；0.40 秒数字翻；离开的托盘上收、留下的一次移位、新问题的托盘从上沿揭开，高度已经是几下；0.96 秒新问题外框描一次朱红。
2. 按下（每一下即刻）：一下就完的托盘原地收成一行回执（上沿不动），右栏刻度跟着收掉，数字减一，下面的一次补位；两下的第一下让第一排并进标题成一枚“推到… ×”小签，第二排由虚变实升上来，托盘矮一排；撤回逆序。
