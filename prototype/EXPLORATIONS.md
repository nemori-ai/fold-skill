# 同一份状态，四种视觉表达

这轮要回答的问题：Agent 已经作出同样的整理判断，怎样的视觉编码能让人更快、更准确地还原当前局面？用户评价原版约为60分，具体反馈是：整齐本身没有增加理解；留白可以散在事项周围；动画要给人时间看清来源、移动和结果。用户也提出 Three.js 液体形态，尝试用流动表达注意力。

## 三个不同的假设

| 版本 | 尝试改善什么 | 主表达 | 需要观察的代价 |
| --- | --- | --- | --- |
| A · 空间排布 | 第一眼辨认现在值得关注的内容 | 中央松散纸片，份额决定面积，真实空白分散在周围与间隙 | 少量小事项是否难读，位置是否仍过度变动 |
| B · 时间展开 | 理解当前局面怎样形成 | 事项保持身份，沿真实整理节点看份额、摘要与明确合并关系 | 历史会不会抢走当前内容，轨迹是否增加理解负担 |
| C · 流动形态 | 用连续形变感知注意力变化 | Three.js 液滴与可读中文，真实合并才相连，预算带给精确份额 | 流动是否只是在吸引眼球，体量会不会被当成精确测量 |
| D · 手机首页 | 打开手机第一眼知道哪些需要你，并就地回应 | 卡片高度表达份额，登记的反馈按钮表达期待，只需知道的事项错开成叠，底部折叠带交代被整理的输入 | 最小行高是否扭曲小份额，按钮会不会让“需要你填一个数”压过更重要但只需知道的事 |

原版继续保留作对照。四个视图使用同一个回放模型，37帧、输入、声明、份额、批注与状态完全相同。表达可以不同，事实与不确定性不变。查看和展开不会写回状态，也不制造“用户已读”的记录。

## 不是争论哪版更漂亮

人离开一段时间再回来，尝试回答：

1. 此刻哪些内容会改变我的理解或行动？结果与放心等待也算，不只看待办。
2. 相比上一轮，真正变了什么？哪些只是位置变化或时间经过？
3. 为什么这件事变得更值得关注？有疑问时，能否沿原消息、理由或批注核对？

可用同一时刻切换四个方案，观察漏读、误读、反复查找和阅读负担。不用动效数量、信息密度或排列整齐程度代替传递效果；视觉吸引力只有在帮助辨认与记忆时才有价值。

## 共同边界

- 每个子层独立使用64份预算，不乘父事项的份额。
- A的事项面积、B的同宽状态截面面积表达最终份额；空白不需要连成一整块，也不必起名。
- C的体量随份额变化，但液体光照和轮廓不用于精确计量；准确数值看独立预算带和完整 JSON。
- 状态不变时不制造进展。跨事项连线或吸合必须有明确合并关系，不从相邻、同色或份额此消彼长推断因果。
- 数据检查入口保留完整 state、原始输入、Batch 和 Diff。故事中的私人消息与 Agent 判断为演示创作。

## 待用户体验后决定

当前没有选定方案，也不声称某版已经提高传递效率。可以保留某版的空间布局、另一版的变化解释，再重新组合；尚未把实验代码吸收为产品实现。

## 标题与措辞

2026-10-10，用户指出标题像小说章节，浪费了最重要的信息空间。已逐帧重写事项及子项标题、37个时间节点和6个阶段名称，让标题直接说明对象、当前结果或待决定的边界。预算标题区分费用预测与已批准上限；故障、样表和家庭行程随事实更新名称。三种视图和原版读取同一份标题，不另外创作展示名称；保留原消息、份额、状态和时间。

## 第一轮体验后的反馈

2026-10-10，用户认为方向可继续，但整体质感仍不足。C 的光线与材质显得生硬，流动不明显，选中后的矩形底色破坏了液体形态。B 的历史主体缺少可辨认的演变动画，悬停没有联动整条事项；上下堆叠的布局让看图与读详情需要反复滚动，历史区域也占用了过多横向空间。

第二轮据此调整：B 将历史与此刻并排放进左侧画布，右侧固定阅读区；按同一事项联动历史、当前截面和标签，并让历史与当前几何连续过渡。C 将材质改为连续液面，采用柔和环境反射、低幅表面流动和运动时的滞后形变，选中效果沿液体轮廓呈现。表面运动不改动状态、份额或文字锚点，业务合并仍只来自明确记录。效果是否改善理解，继续由实际体验判断。

随后用户指出 C 的灰色选中描边仍然生硬。选中表达改为斜光照透液滴：本色在内部聚集，两段不闭合的折射光带随液面弯曲，文字中心避开增强高光。最终按用户反馈移除点击和指针引起的水波纹，将持续的表面蠕动放缓至原速的 40%，帧间与层级切换的过渡速度不变。颜色与透光差异持续标记选中，减少动态效果时保留静态材质。选中不改变液滴半径、位置、轮廓计算或份额；无法使用 WebGL 时，列表明确标出当前查看的事项。

材质与动效参考来自创作者的一手说明：[SDF 液体与光照](https://tympanus.net/codrops/2024/07/15/how-to-create-a-liquid-raymarching-scene-using-three-js-shading-language/)、[延迟形变与折射](https://tympanus.net/codrops/2025/10/25/dissecting-a-wavy-shader-sine-refraction-and-serendipity/)、[厚度、法线与环境反射](https://tympanus.net/codrops/2026/09/08/building-an-infinite-liquid-glass-grid-with-three-js-webgpu-and-tsl/)。实现继续使用随原型保存的 Three.js，本地运行。

## D · 手机首页与反馈回路

2026-10-10，用户提出移动端的第一屏问题：助理有几百个任务、上千个信息源，打开时要先给出最需要知道的内容，不是输入框加会话列表，也不是通知列表。随后用户在[领域模型](../docs/domain-model.md)中把“需要你”与“让你知道”分开：前者以注册了反馈路径为前提，已阅等反馈的后果由业务用途决定。D 据此把这些关系直接变成视觉语法：

| 状态或记录 | 手机上的表达 |
| --- | --- |
| share | 卡片高度，一份约一行；24 份是首屏大卡，6 份是一行。份额不足一行且只需知道的事项进入错开的一叠。 |
| 登记的反馈动作 | 按钮形态：两个选项是决定，预填输入框是提供，单个动作是去做，相机是提供照片，没有按钮是只需知道。朱红只用于可以回应的控件。 |
| 子层 | 卡片下方贴合的薄纸边，详情中展开为独立 64 份。 |
| 被整理的输入 | 底部折叠带给出累计输入、当前件数、本轮噪音与重复，点开看原文与撤下或合并的事项。 |
| 变化 | 相对你指定的比较起点标出“新”“变”“子项有变”；首切片不记录查看，这个起点需要人工选择。 |
| 时间信号 | 零事件的每日整理显示窗口、渠道覆盖与这次整理的结果。 |

点击卡片进入详情：依据原文、份额理由、来龙去脉、反馈回路和子项，底部固定与首页相同的回应按钮。稍后提醒会把卡片收进顶部时钟；往后切到提醒时间后，它回到首页并注明期间是否有更新。

为此升级了共用的演示数据（四个视图读取同一份）：

- 每个“需要你”的输出版本都登记了期待与可用的反馈动作（`frame.asks`）；Agent 改写该事项而没有重新登记时，视为没有可用回传路径。
- 故事中林苒回应先前问题的消息，标注了所回应的对象与动作（`event.feedback`）；另增加两次按钮反馈和一次完整的稍后提醒回路（f14、f24、f30），后者在到点后由 Agent 重新判断并更新招聘事项。
- 每一帧记录调用原因与窗口（`frame.signal`）。f17 的零事件每日整理不再只是检查：东馆资料已过复核时间，改为“最后核对于13日，出发前再确认”；f27 仍是有效的无变化检查。

这些记录在宿主一侧，不进入 Fold 状态，也不改变其他声明。哪些按钮出现、按下后如何处理，仍属于业务策略；原型中的两种用途只用于比较，不是内置规则。
